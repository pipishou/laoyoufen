B1 · 只搬四件机制

上一轮结论的延续 · 技法：反向假设
  • 做什么：眼睛绿截图、规则直译 4 条、L0 加 ran 第三态、rigor 先验。
  • 优点：1.5 人时内见效；每件独立可回滚；不动任何现有结构。
  • 缺点（硬）：证据只有截图、没有过期检测（无 CHANGED / GONE / RECEIPT: NONE）；判据仍两态，出不了「未评估」；design/registry 那层单一事实来源照旧缺位，数值与文案会双写。
  • 触发信号：三周后 evidence/ 里出现「改了代码但图没换」的旧证据，却没人报。
结论：不成立（作为完整方案） —— 是地板不是方案，其四项并入 B2 的 P0/P1。

B2 · 三层改造（机制 / 目录协议 / 最小角色集）推荐

置信 HIGH · 双向门 · 技法：类比迁移（当五金店，不买整套柜子）
  • L1 机制层（改写进脚本）：四态 verdict（NOT ASSESSED 优先于通过并须点名什么能 settle）、观察三证据（looking / asked / seen on screen，a described check is an assertion）、证据过期三态、qa.level × Type 豁免矩阵（the look is never waived）、scope 对照 git status --porcelain。
  • L2 目录协议层（近零成本）：game/data/registry.yaml 单一数值来源、game/data/evidence/<slug>/NN-*.png 命名即规范、.junshi/session-state.md 含 Run result: 行、docs/tech-debt.md。
  • L3 角色层（只留 3 个）：economy-designer（汇/漏建模、曲线必须给区间两端算例、sink 悬空即未平衡）／qa-lead（证据裁量）／performance-analyst（帧预算）。其余 46 个丢弃。
  • 三批：P0 1.5h（机制 + 第三态）→ P1 5h（Playwright 四视口 + sha256 stamp + 负测试）→ P2 2h（角色 brief + 实跑汇/漏）。任一批可停。
  • 失败边界：三个月内 evidence/ 零新增、或 review_stats 仍报不出「未执行」→ 说明买的是流程不是游戏，退回 B1 并停。
结论：成立 —— 机制层是 CCGS 全库最贵也最可移植的部分；自证「standard 档 30 篇文档 / 58 分钟，盲评排最后」正是我们不该学的那一半。

B3 · 全量移植为 dsh skill pack

技法：10 倍放大，看断在哪
  • 做什么：74 skill 逐条改 frontmatter、内联 bash 改 Python；49 agent 改 subagent brief；128 docs 整包进项目。
  • 优点：从立项到发布的链条不缺环（epics → stories → dev → done → sprint → gate → release）。
  • 断点（实测）：68/74 顶部内联 yaml-helper.sh resolve_config、25/74 直接调 .claude/scripts/*、32/74 含 Godot/Unity/Unreal 指令 → 74 × 1 人时 = 74 人时纯改造，且期间 0 游戏产出。
  • 次生伤害：39/74 的 blocked 靠 18 个 bash hook 落地，dsh 无 hook 入口 → 门退化为口号；三引擎指令在 Phaser 项目里产出错指令。
结论：不成立，封存 —— 保留为只读参考库（已就位），需要哪节当场进去读。
