## 4 依据（实测，2026-11-08）

- `[过闸]` 仓库现状：root `D:/项目/REA`，remote `github.com/pipishou/rea-procurement-agent`，branch 仅 `main`；`.git` 仅 **0.6 MB**；`git ls-remote` + `git fetch` 均成功 ⇒ **凭据可用**（credential.helper=manager）。
- `[过闸]` 仓库是**私有**：未认证 GitHub API `GET /repos/pipishou/rea-procurement-agent` 返回 **404**。
- `[过闸]` 本地落后远端：本地 HEAD `00a0a13`，远端 main `b4bcb8a` ⇒ 动手前必须先同步，否则 push 会被拒或误覆盖。
- `[过闸]` 体积红线：`REA/` **3,405 MB / 17,537 files**（逆向 3,064 MB、重构 336 MB）；`REA/重构/老友粉店` 216 MB 中 **node_modules 211.5 MB**，源码仅 ≈**4.7 MB**。⇒ 只能白名单纳入，绝不能整体 `git add REA/`。
- `[过闸]` 未配置 git 身份：`git config --global user.name/email` 均为空 ⇒ 直接 commit 会失败。
- `[未过闸]` 仓库是否设了分支保护、是否有 Actions 配额未查（私有仓 Actions 分钟数受限）。

## 5 不做什么

- 不整体解除 `/REA/` 忽略：会一次把 3.4 GB（含逆向解包资源与 211 MB node_modules）塞进历史，不可逆。Git 删不掉已进历史的 blob，只能 rewrite。
- 不新建第二个 GitHub 仓库（除非你要「一仓一产品」的洁癖）：远端与凭据都现成，新建只换来语义干净。
