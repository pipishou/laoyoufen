# B1 · 只搬四件机制（上一轮 B 方案的延续）

- 一句话：维持上一轮结论，只把 D1 眼睛绿、D2 规则直译 4 条、D3 L0 第三态、D4 rigor 先验搬进项目，不动目录、不加角色。
- 技法：反向假设（技法 5）——把「上一轮的 B 已经够了」当成真命题，去找它撑不住的边界。
- 核心假设：CCGS 对我们的增量集中在 4 个可独立落地的机制，其余 70 个 skill / 49 个 agent 与 128 份 docs 都是「编制冗余」。
- 支撑证据：
  - 首评已实测：`test-run.sh` 里 grep `node|npm|vitest|jest|playwright|python|pytest` 零命中 → 其自动化层对我们无一条可用分支。
  - 74 skill 中 32 个正文带 Godot/Unity/Unreal 假设，25 个直接调 `.claude/scripts/*`，8 个才真提「证据」——**证据机制只在 8 个 skill 里，抽出来即可**。
  - 我们的审核管线（`tools/reviewer/` 6 个脚本 + 89 用例）已经是比 CCGS 的 bash 脚本更贴合本项目的门，不需要被替换。
- 反证信号：四件做完之后，「第四绿」仍然只有截图、没有**过期检测**与**四态 verdict**——那时会重新需要 `story-done` 的判据（`review-receipts.sh check` 的 `CHANGED/GONE/RECEIPT: NONE` 三态）；或目录里仍然没有 `design/registry/entities.yaml` 这类跨系统事实单一来源，导致数值/文案双写。
- 成本：1.5–2 人时（D1 半天、D2 半时、D3 半时、D4 一句话）。
- 可逆性：双向。四项各自独立，回滚＝删脚本/回退一段提示词，无悔成本。
- 结论：**不成立（作为完整方案）**。它是地板而非天花板：能立即少踩坑，但不解决「我们缺一套跨系统事实与证据生命周期的规矩」这个真问题——这层规矩恰好是 CCGS 全库里最贵也最可移植的部分。保留其四项作为 B2 的第一批交付。
