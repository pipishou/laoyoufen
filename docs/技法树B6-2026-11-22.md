# 批次 6 · 手上的功夫（技法树 12 支 × 3 级）

## 一、这一批解决什么

《下一轮开发方案》最后一批，替掉方案里原写的「改良扩五级」。

开罗 `ramen_skill.txt` 45 行 + `finishskill.txt` 11 行，做的是「经营中一点点练出来的手艺」：
每一支都挂在具体动作上（煮、切、汆、摆、招呼），练满了给一个固定加成。
我们此前有两层相近的东西，但都不是这一层：

| 已有的层 | 管谁 | 形态 |
|---|---|---|
| A6 老师傅的方子 | **某一款的一口锅** | 四条一次性决断，钉死一个出口 |
| A9 店员专精 | **店里的人** | 每岗位一门，人走了只算一份 |
| **批次 6 手上的功夫** | **老板自己的手** | 十二支各三级，永久在身上 |

所以这一层不是「再加一堆数字」，是把**「你自己也在长本事」**这件事做出来。

## 二、十二支与三十六节点

四个门派（`FAMILY_NAMES`）各三支：

| 门派 | 支 | 练的是什么 | 三级效果（1 / 2 / 3） |
|---|---|---|---|
| 火候 | 看火 | 锅一直是热的，下粉不用等 | 出碗 3% / 4% / 5% |
| 火候 | 爆香 | 酸笋豆豉下锅那一下 | 满意 +1 / +1 / +2 |
| 火候 | 撇沫 | 汤清不浑，料不白费 | 料钱 2% / 3% / 3% |
| 刀工 | 切片 | 肉切得薄，熟得快也省料 | 料钱 2% / 3% / 3% |
| 刀工 | 笋丝 | 酸笋切得匀，酸味不忽轻忽重 | 满意 +1 / +1 / +1 |
| 刀工 | 洗杂 | 猪杂洗得干净，客人等得安心 | 耐心 3% / 3% / 4% |
| 待客 | 招呼 | 人还在门口，话就先到 | 进店 3% / 4% / 4% |
| 待客 | 记脸 | 谁要什么口味不用问第二遍 | 耐心 3% / 4% / 4% |
| 待客 | 递茶 | 等位的人有杯茶，火气就下去 | 满意 +1 / +1 / +1 |
| 生意 | 记账 | 每天收多少花多少心里有本账 | 料钱 2% / 2% / 3% |

每一级都有一句老师傅的土话（「火苗别让它趴下，锅边一直有响。」「肉冻半小时再切，片就齐了。」「队尾挂块牌，让人知道还要几个。」）。
**三十六句全都不同**，测试锁了「不许重复、长度 > 6、门槛逐级不降」。

## 三、三条纪律

写在 `game/src/data/skill.ts` 文件头：

1. 一支只落**已有出口**（出碗 / 料钱 / 耐心 / 满意 / 抢客），不新开机制；
2. **必须一级一级练**，不能跳级 —— 火候这回事就是如此；
3. 十二支加起来由 `SKILL_CAP` 统一夹住，不然三十六节点能把乘数拉到失真。

`SKILL_CAP = { servePct 0.15, costPct 0.12, patiencePct 0.15, satBonus 4, attractPct 0.12 }`。
测试里有一条专门断言「全练满时 `costPct` 与 `satBonus` 真的撞到上限」——
不然封顶形同虚设，数值会悄悄漂。

**为什么不做成「改良扩五级」**：开罗的改良是「同一件事加五档数字」，玩家只看到价格涨；
技法树是「十二件不同的事各自三级」，玩家能挑自己缺的那一手 —— 缺客人就练招呼，缺速度就练看火。

钱与门的门槛：人情 8/10/14 点、¥200/400/700，三级合计一支约 32 点人情 + ¥1,300。

## 四、接在哪

- `game/src/data/skill.ts`：`SkillFamily` / `SkillEffect` / `SkillLevel` / `SkillBranch` / `SKILL_BRANCHES`（12 支）/ `SKILL_TOTAL = 36` / `SKILL_BY_ID` / `skillById` / `branchesOfFamily`；
- `game/src/sim/skill.ts`：
  - 读：`skillLevelOf` / `skillCount` / `skillSummary` / `branchMastered`；
  - 算：`skillBonus`（逐项夹 `SKILL_CAP`）→ `skillServeFactor` / `skillCostFactor` / `skillPatienceMult` / `skillSatBonus` / `skillAttractMult`；
  - 练：`learnSkill(state, id)` —— 查表、查上一级、查人情、查钱，扣完写 `state.skills`；
  - 视图：`skillViews`（`affordable` + 缺什么的人话）/ `skillLine` / `skillEffectWords`；
- `game/src/sim/state.ts`：`SAVE_VERSION 32 → 33`、`GameState.skills: Record<string, number>`（初始化 `{}`）；
- `game/src/sim/save.ts`：判废白名单加 `32`，迁移 v32→v33（只留表内支、只留 1–3 的整数）；
- `game/src/sim/customer.ts` 五处出口接线：
  - `spawnChance` 乘 `skillAttractMult(state)`（招呼、摆摊）
  - `patienceScale` 乘 `skillPatienceMult(state)`（洗杂、记脸、排队）
  - 满意链加 `skillSatBonus(state)`（爆香、笋丝、递茶）
  - 料钱链乘 `skillCostFactor(state)`（切片、撇沫、记账）
  - `serveCooldown` 乘 `skillServeFactor(state)`（看火）
- `game/src/ui/panels.ts`：店铺页「家当 / 搭配 / 店的样子 / 碗 / 袋装 / 摆件」之后的 `${skillSec}`
  （抬头「手上的功夫 · N / 36 节点」，四门派分节，十二行各带三个 `.skpips i` 小方块与「练」按钮）；
  `PanelActions.learnSkill` + `case "skill"`；
- `game/src/main.ts`：`learnSkill` action（失败 toast 理由，成功 toast 那句土话 + `playSfx("upgrade")`）；
- `game/src/ui/hud.css`：`.skpips / .skpips i / .skpips i.on`（像素小方块，用已有 token）。

## 七、与开罗逐项

| 开罗 | 本作 |
|---|---|
| `ramen_skill.txt` 45 行（多为一支多级） | 12 支 × 3 级 = 36 节点 |
| `finishskill.txt` 11 行（最后一手） | 并入「生意」与「待客」两支的第三级 |
| 练法靠经营累积 | 人情 + 钱，一级一级往上点（更直白，玩家能规划） |
| 效果多为直接数值 | 全部落在已有五条出口，且有统一上限 |
| 店员技能（`clerk_skill` 21）另算 | 我们已有 A9 店员专精，两层分开互不加成 |

## 八、新缺口

- **P185** 三十六节点没有「练的时间」：点一下就会，真实里看火要练几个月。
- **P186** 技法不随段位解锁，新局第一天就能点满（只要有人情）。
- **P187** 十二支之间没有依赖关系（真实里刀工不到家，切不出薄片，爆香也没那么快）。
- **P188** 练满之后没有任何外部反馈 —— 打烊单、街坊报、客人都不知道老板长了本事。
- **P189** `SKILL_CAP` 是拍的，没验过「三十六节点全满」与「一个不练」之间的实际差距有多大。
