# 钩子先添凳（批 AM′ · 2026-11-25）

一句话：**门口站满的时候，钩子以前会叫人去买灶，而实测买灶一天一碗都不多、买凳一天多卖十八碗。**
这一批只改「它说什么」，不改任何一件东西的价钱、产量与客流。

---

## 一、这一批要解的是 P70

`docs/ACCEPTANCE.md` 第五节从 1619 试玩报告里记下过一条 (P70)：

> 钩子先点产能还是先点座位。第 4 天纯灶对照：小陆只加猛火灶（座位 2）流失 50.0%，
> 阿兰、老韦只加塑料矮凳（座位 3）流失 36.8% / 33.7%。玩家跟着红按钮走，就被带去加灶。

批 AK′ 把「一天只有一处红」做出来了，但那一处红**指的方向**还是老样子。这一批负责方向。

## 二、先把差距量出来（四天对照实验）

临时脚本（`game/src/sim/tmp_p70.test.ts`，跑完已删）按试玩的场景压了一遍：
`FLOW.spawnScale = 6`、`serveMinutes = 1`、`eatScale = 1`、`patienceScale = 1.5`、`queueMax = 12`，
**第 2 天开头只置办一件**，五个种子（1 / 2 / 3 / 5 / 8）取均值，看第 4 天：

| 策略 | 第 4 天流失率 | 第 4 天卖出 | 与「什么都不买」比 |
| --- | --- | --- | --- |
| 什么都不买 | 54.0% | 75.2 碗 | —— |
| 只买塑料矮凳（¥150，座位 4 → 5） | 53.7% | **93.6 碗** | **+18.4 碗 / 天（+24%）** |
| 只买猛火灶（第 1 档，炒锅 1 → 2 口） | 54.0% | 75.2 碗 | **±0 碗** |

两笔购买都返回成功（`炒锅第 1 档：开到 2 口` / `塑料矮凳搬进来了：红色塑料凳…`），所以不是「没买上」。

## 三、为什么模型会说「买灶」，而实测是「买凳」

`game/src/sim/bottleneck.ts` 里当天的日碗量是三项取小：

```
stove = DAY_MINUTES / serveNow            // 120 / 2  = 60
seats = seats × DAY_MINUTES / (serveNow + EAT_MINUTES)   // 4 × 120 / (2 + 6) = 60
cap   = 扩建 / 门路 / 杂货叠出来的日上限
```

4 座时 **`stove` 与 `seats` 正好都是 60**，`pack()` 的平局判定是
`total === stove ? "stove" : …` —— 平局判给灶，于是 `tight = "stove"`、
`capacityGain().seat(1) = 0`（再添一个座位，取小之后总量不动）。

钩子第 ⓪ 步（流失率 ≥ 45%）按「每一块钱能把当天上限抬高多少碗」排候选，
座位件那一格是 0，自然排到设备后面 → 54% 流失时说「先把「猛火灶」加上（¥1,500）」。

而实测里买灶**一点用都没有**：4 座时总量被座位那一闸卡在 60 碗附近，
灶再快也只是让菜等着凳子 —— 这正是试玩报告里「出碗从 1.6 降到 0.8 也抬不高那个顶」的同一个病灶。

**结论：这不是「提示顺序」问题，是模型给座位项的估值错了。**
但改 `capacityOf` 的座位公式会直接改经济（替身按 `capacityGain` 的量尺买东西），
所以这一批只做**建议侧**的修正，模型那一侧记为 P443 另开一批。

## 四、改了什么（只有一处判定 + 一处候选池）

`game/src/sim/hook.ts`：

1. **候选池不再把「增益 0 的座位件」筛掉**。原来 `preferSeat` 分支是从
   `pool`（已被 `gain > 0.05` 过滤）里挑座位，4 座时池子里根本没有凳；
   现在从 `picks` 里挑，`byCost.find(亲钱够的) ?? byCost[0]` —— 买不起也照样提，只是话换成「卖了钱先添」。
2. **「座位这一环没富余」也算门口站满**。调用点从
   `capacityPick(state, split.dominant === "queue")` 改成：

   ```ts
   const cap = capacityOf(state);
   const seatTight = cap.seats <= cap.stove;
   const pick = capacityPick(state, split.dominant === "queue" || seatTight);
   ```

   `cap.seats <= cap.stove` 的意思是「坐着能吃下的人，不比灶一天能出的碗多」——
   这时候先添凳，比再开一口灶更贴近实测（4 座 → 5 座：+18.4 碗/天）。

判据写在 `game/src/sim/hook-seat.test.ts`（5 例）：4 座 + 排队走掉一大半 → 说凳子；
4 座 + 等人等走 → 说凳子；6 座（`cap.seats > cap.stove`）→ 走回「谁最划算」那条路、指设备；
凳子买不起 → 仍提凳子、话里是「卖了钱先添」；两件座位家当都买过之后不再硬推凳子。
