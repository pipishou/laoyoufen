# 今天只亮一处（批 AK′，解 P430）

> 一句话：**同一天只允许一处喊「现在做这个」**，其余三处退成灰字。四处各算各的，是把玩家从红按钮带走的根因。

## 一、试玩报告里那三处对不上

1619 包三局两周（`docs/试玩-1619包三局两周-2026-11-25.md`）逐条摘出来：

| 哪天 | 店铺页说的 | 打烊单说的 |
| --- | --- | --- |
| 老韦第 10 天（买完隔墙） | 汤锅 | 壁扇 |
| 老韦第 13 天（买完壁扇） | 排风扇 | 汤锅 |
| 阿兰 / 老韦第 15 天 | 「巷口老铺」按钮已亮 | 还在攒 ¥35,000 后厨扩容 |
| 小陆第 2–4 天（加过灶） | 凳 | 凳（而实测加凳才是对的） |

同一天四个地方会各自亮起来，而它们**从来不是同一套算法**：

| 谁 | 原来的依据 |
| --- | --- |
| 打烊单那一行 | `sim/hook.ts` 的 `nextHook` → `sim/today.ts` 的 `todayLine` |
| 店面 / 设备 / 家当段头红标 | 面板里再问一次 `nextHook`，还各自加条件（`hotPlan.kind === "capacity" && …`） |
| 设备段「最慢：炒锅 2.2 分」 | `slowestStation`，与钩子毫无关系 |
| 「交费评定」按钮 + HUD「可评定」小牌 | `checkGrade().ready`，与钩子毫无关系 |

开罗的做法是**同一时刻只指一件事**（`sim/today.ts` 文件头引的 `help.txt` / `Shop Stats` 三段）。我们这一批把它落成代码。

## 二、一个裁定：`game/src/sim/align.ts`

新文件 189 行，只读既有事实，**不产生任何数值**。

```ts
export type FocusSec = "seat" | "equip" | "expand" | "gear" | "grade" | "price" | "street" | "arena" | "none";

todayFocus(state): Focus        // 今天那一件：kind / sec / gearId / equipId / station / main / detail
alignMarks(state): AlignMarks   // 其余三处怎么降级
focusWords(focus): string       // 抬头用词
demotedWords(marks): string     // 灰字一行
```

`alignMarks` 交出来的东西：

| 字段 | 含义 |
| --- | --- |
| `seatHot` / `equipHot` / `expandHot` / `gearHot` / `gradeHot` | 五处里**至多一个** true |
| `slowHot` | 设备段那行「最慢」是不是今天这一件（`focus.equipId === STATION_EQUIP[slow.station]`） |
| `hudGradeChip` | 顶上那枚「可评定」要不要出现（`=== gradeHot`） |
| `demoted` | 今天不主张但确实做得到的事，一句一条，界面拼成灰字 |

`demoted` 目前会生成四类句子：评定够格了但今天不是它 / 最慢的是哪一环但今天不动设备 / 家当里还有买得起的小件 / 扩建钱够了但不急。

## 三、界面怎么变

1. **`game/src/ui/panels.ts`**
   - `const marks = alignMarks(s);` 之后，`hotSeat` / `hotEquip` / `gearHot` 全部改成读 `marks`，删掉面板里对 `nextHook` 的第二次询问（连带删掉 `gearEfficiencyLeft` 这个只为旧红标存在的 import）。
   - `todayBox` 底部多一行 `<div class="tdemoted" data-demoted>今天先不动：…</div>`（只在该有灰字时出现）。
   - 设备段那句拆成两支：今天就是这一段时 `最慢：炒锅 2.2 分`（红），否则 `参考：炒锅 2.2 分最慢`（灰，带 `data-slow-soft`）。
   - 「交费评定」按钮在不是今天那一件时加 `class="soft"`（虚线描边），**仍可点**，`title` 写「够格了，但今天这一件不是评定 —— 想先评也行」。
   - 扩建阶梯里「下一步」那一行在 `expandHot` 时加 `hotrow`。
2. **`game/src/ui/hud.ts`** —— HUD 那枚小牌只在 `marks.hudGradeChip` 时喊「可评定」，否则退回比赛日历（第 15 天那条就是这么来的）。
3. **`game/src/ui/hud.css`** —— `.todaybox .tdemoted`（虚线隔开、木色小字）、`.sechd .tag2.soft`（木色、75%）、`.lbtns button.soft`（虚线边、纸底色）。

### 顺手修掉的一个真 bug（第十四次「键漏字段」）

店铺页的渲染缓存键里没有「今天这一件」。裁定变了、DOM 不重画 —— 探针首跑 `grade_hot_when_focus` 红就是这个：状态改了、HUD 换了、面板还是上一份。键里补了
`alignMarks` 的签名（`kind:sec:gearId:equipId:gradeHot:slowHot:demoted.length`）。

新增单测（`align.test.ts`）判六件事：开局只亮家当一处、队列主因只亮产能一处且家当段不跟着亮、段位够格但今天该接客时评定降级且 HUD 不喊、没人走时评定就是今天那一件、`slowHot` 只在指到那一段时为真、任何状态至多一处红。

探针（`align_probe.py`）造三个状态量 DOM：

1. 昨天走 30 位全是排不下队 → 设备段是今天那一件：`最慢` 是红字、`参考` 那支不存在、灰字里没有「最慢」那条；
2. 段位够格 + 昨天同样走 30 位 → 评定按钮 `soft`、HUD 小牌不热、灰字里有「够格了」；
3. 段位够格 + 没人走 → 评定按钮回主推、HUD 小牌热、设备段退回「参考」；
4. 三态各自「段头红标 ≤ 1」；存档 37；控制台干净。

> 关于「红只有一处」的口径：钩子点到某件设备时，**段头红 + 那一行 `hotrow` 会占两个计数** —— 它们指同一件，所以探针断言的是「段头红标 ≤ 1」而不是「全页红元素 == 1」。

## 五、这一批没动什么

- 没有改 `nextHook` 的优先顺序。**P70（先点产能还是先点座位）仍是账**：开局 `venue.seats = 4` 时 `capacityGain().seat(1)` 算出来是 0，钩子于是永远先点设备，而试玩第 4 天的纯灶对照（50% vs 加凳 33.7–36.8%）说明先点凳才对。这条要动的是「替身会买什么」，四种子必然变，得单开一批。
- 没有改任何数值、任何乘数、任何概率。四种子逐位不变就是这一批的判据。

## 六、新记的缺口

- **P431** 灰字只是灰字，点不动：想做那件事还得自己翻到对应的段。
- **P432** 一份裁定算两遍：`shopHtml` 调 `alignMarks`，面板缓存键又调一次（含 `checkGrade` / `gearViews` / `nextHook`），价格随店变大线性涨。
- **P433** 评定降级时 HUD 那枚小牌退回比赛日历，玩家看不到「其实够格了」——信息只在面板灰字里。
- **P434** `focusWords` 只有单测与探针在用、界面没接（与 P414 同型）。
- **P435** 三处「今天该动什么」的口径里，只有钩子有优先级规则；`slowHot` 与 `gradeHot` 现在是被动跟随，没有自己的「为什么不是现在」。
