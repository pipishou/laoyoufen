## 二、改了什么

### 1. 门路当天给了多少（解 P347）

`game/src/sim/invest.ts`

```ts
export function investGainOf(def: InvestDef): string {
  if (def.capacity) return `多做 ${def.capacity} 碗`;
  if (def.slowestMinutes) return `出碗快 ${def.slowestMinutes} 分`;
  if (def.attractPct) return `进店多 ${Math.round(def.attractPct * 100)}%`;
  return "";
}

export function investEndingToday(state: GameState): InvestEnd[] {
  const last = dayIndexOf(state) + 1;
  return INVESTS.filter((def) => state.investments?.[def.id] === last)
    .map((def) => ({ def, gain: investGainOf(def) }));
}
```

`investDoneToday` 保留，改成 `investEndingToday(state).map((e) => e.def)` —— 老调用点不用动。

`game/src/sim/state.ts`

- `DayRecord.investGain?: string[]`，与 `investDone` **一一对应**（同一次 filter、同一个顺序，不会错位）。
- `recordDay` 里两条一起写：

```ts
const doneInvest = investEndingToday(state);
if (doneInvest.length > 0) {
  rec.investDone = doneInvest.map((e) => e.def.name);
  rec.investGain = doneInvest.map((e) => e.gain);
}
```

`game/src/ui/hud.ts`

- 打烊单那一行：`到点：跟料商多留一筐 走完了（多做 20 碗）`；两条同天到点用「；」隔开。

### 2. 推荐不抢红（解 P349）

`game/src/ui/hud.css`

```css
.pane .pc.rec{outline:2px dashed var(--wood);outline-offset:1px}
```

原来的 `var(--red)` 换成 `var(--wood)`。理由：红在这个界面里是**「现在就卡住了」**（`.lrow.hotrow`、「现在最缺」、压迫型事件标题的 ⚠），推荐只是**「先点这个也不亏」**。两件事挤在一种颜色里，玩家就分不出哪件是今天必须做的。

新增三项探针的做法：

- `invest_line_says_gain`：往 `dayReport` 塞 `investDone: ['跟料商多留一筐']` + `investGain: ['多做 20 碗']`，要求打烊单那行同时出现「走完了」与「多做 20 碗」。
- `rec_outline_dashed`：读 `[data-rec="1"]` 的 `outlineStyle`，必须是 `dashed`。
- `rec_not_red`：临时插两个 span 分别取 `var(--wood)` 与 `var(--red)` 的计算色，要求 `outlineColor === wood` 且 `wood !== red` —— 这样即使将来换色板也能跟上。

## 六、新缺口

- **P350** 效果量是「理论上限」不是「当天实际」。产能 +20 碗，但门口没人时这 20 碗白给；打烊单说的是承诺，不是结果。要真说结果，得在 `recordDay` 里对比「去掉这条门路会卖多少」——那要跑一次影子模拟，贵。
- **P351** `investGain` 只在**最后一天**记一笔。中间那几天它在工作，界面上只有店铺页的「今天：…」，打烊单不说话。
- **P352** 木色虚线在小屏（375 宽）上只有 2px，和默认边框差别不大；`eye_gate` 截图能过，人眼未必分得出。
- **P353** 三种单位（碗 / 分 / %）没有统一口径说明。玩家得自己明白「出碗快 0.5 分」值多少碗。
