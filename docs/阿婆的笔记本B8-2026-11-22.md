# 阿婆的笔记本（批次八）· 2026-11-22

## 一、这一批要解决什么

开罗 `topics` 表只有 9 行，但打开游戏看过就知道它不是九条 tooltip：**那是一个有排版的册子** —— 组 0 四条讲面，组 1 五条讲汤，配着图，一次只讲一件事，讲完就合上。它解决的是「玩家知道自己在忙什么，但不知道自己懂了什么」这件事。

本作前七批已经把玩法铺到 8 个系统（设备/工序、碗、配料、味道、行情、段位、零售、技法），玩家的操作面越来越宽，但没有一处告诉他「你刚才学到的东西有名字」。这一批补这处。

**判据**：玩到三十天的人，能在图鉴最末翻到至少五条写着自己做过的事的话，而且那五条话里没有一个游戏术语。

## 二、为什么不做成任务清单

最省事的做法是「达成条件 → 解锁 → 弹条」。但那样册子就变成了成就表，阿婆就成了提示系统。

这一批定了三条规矩：

1. **线索写「等你遇上」，不写条件**。`cue` 一律是「等你换过一回粉」「等哪天出锅特别慢」这种口气，不写「换 1 种粉」。玩家看不见分母，就不会去刷。
2. **正文是阿婆的手写稿，不是玩家手册**。60–120 字，一句人话开头，通篇没有阿拉伯数字，也不许出现「分数 / 契合 / 加成 / 百分比 / 属性」（这两条都有测试锁）。
3. **阿婆的原话单独放在 `title` 里**。正文是她写下来的，`elder` 是她嘴里说的（「粉要摊开晾，唔好焗住。」）。同一条知识，两种介质。

## 五、AI 落点 17：`notebook_voice`

模型**不写册子上的字**，只写阿婆说完这句话之后嘴里那一句。

- `key`：条目的 id
- `context`：`{事, 类, 话}` —— 事是这条讲什么，类是哪一组，话是阿婆的原话
- 服务端场景原文：「阿婆在册子上写完一条，抬头跟老板说了一句：说的就是这一条里的事，口气像自家长辈，短、实在、有点土；不要念正文、不要报数字、不要讲道理，也不要劝他该怎么做。」

本地的四句兜底已经把口气定了：「嗱，粉厚了就要多烫一阵，唔好急。」「钱要省在客人看不见的地方，唔好省在碗里。」

## 九、新缺口

- **P210 十二条不影响任何数值** —— 册子纯叙事，玩家不看也照样通关，缺少「懂了就有用」的那一层（比如看懂「座位与灶」之后钩子更准）。
- **P211 没有插画** —— 开罗每条配图，我们只有字；图鉴页翻到最末一段是纯文本墙。
- **P212 触发不看顺序** —— `p_price` 出现在第一次调价，`p_cost` 出现在第一次亏损，谁先来谁先翻；晚期玩家可能一条都没触发（一直没亏损、没掉口碑）。
- **P213 `n_soak` 用 3.5 分作门槛** —— 这个数是照当时替身的出碗时间拍的，三段设备改过之后没重标。
- **P214 图鉴页的渲染缓存键又漏过一次**（第七次同类）—— 这次把 `notes`·`news`·`rivals`·`flavors`·`bowls`·`bowl` 一次性都补进了 key；**规矩再加一条：图鉴页新加一段，必须同时改缓存键。**
- **P215 阿婆原话与正文有重复语义** —— 十二组「原话 / 正文」里有三组说的是同一件事（如 `n_thick`），只是口气不同；这不是错，但读起来像重写了一遍。
