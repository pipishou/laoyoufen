# 门先修好，再谈口径（批 BB1′）

体检那天先跑的不是游戏，是门。跑完发现：**扫过的四十九条线索里有二十条在说假话** —— 不是游戏坏了，是探针自己烂了，红的说绿、绿的挡路。这一批先把门修到可信，再修它挡住的那处口径（同一个「灶」两个数）。

## 一、这一批要解决什么

体检（`docs/` 之外的一次临时扫描，脚本已删）给出三条：

1. **十四个探针整条失效**。它们全都断言 `saveVersion == 36`，而 `game/src/sim/state.ts:33` 从批 K′ 起就是 `export const SAVE_VERSION = 37;`。这不是「有一处过时」，是**十四条线索集体报废**：`advice / calib / dayreport / invest / map / notebook / pricewar / quality / retail / seat / settings / skill / today / why`。它们每天都出现在交付清单上，每天都红，每天都被当成「已知」跳过。
2. **另外六个探针被 `/laoyou-api/` 的 404 打红**。预览与服务端的接口本来就不在 vite preview 上，但判据写成 `len(console_errors) == 0`，于是九条探针永远红。
3. **还有一批把「数据表长什么样」抄进了探针**：手册「12 页 4 组」（实际 16 页 5 组）、加料台「12 行」（实际 15 行）、粉型「6 张卡」（`.ncard` 后来被汤底卡与款卡共用，数到 19 张）。**探针替数据记账，改代码的人反而被探针挡住。**

这一批同时修它挡住的那处口径：`game/src/sim/slots.ts` 的灶格上限写死 4，而批 AZ′ 的黄金灶能把炒锅开到第六口 —— 面板抬头写「灶 6/4」，图上只画四个灶位。

## 二、六类故障，逐条定性

| 类 | 表现 | 根因 | 修法 |
| --- | --- | --- | --- |
| A 版本号写死 | 14 个探针整条红 | 断言 `saveVersion == 36` | `from probe_version import SAVE_VERSION` |
| B 404 当噪声 | 9 个探针 `console` 判据恒红 | `len(console_errors) == 0` | `probe_console.noisy()`：看**来源 URL** |
| C 端口写死 | 9 个探针只打 `127.0.0.1:4173` | 常量 URL，不认环境变量 | `os.environ.get("PW_URL", …)` |
| D 出处看不见 | `branch` / `unlock` 的 `hasKairo` 恒 false | 出处只在 `?dev=1` 渲染（`game/src/ui/dev.ts:14`） | 探针改打 `DEV_URL` |
| E 期望值抄代码 | 手册 / 加料 / 粉型三条过期 | 探针里写死 12 / 12 / 6 | `probe_source.py` 从数据表读 |
| F 判据取错节点 | `set_probe` 找不到「另买凳子」 | 取 `.sechint[1]`，那句在另一条 | 全部 `.sechint` 拼起来判 |

F 类这条值得单说：`game/src/ui/panels.ts:1300` 原话是「多坐一个人还是得另买凳子」，探针取的是第二个 `.sechint`，第一个才是。**判据本身没错，取的位置错了** —— 和批 AT′ 那次「短句不是长句前缀」同型的错误。

## 三、两个新共用模块

### `tools/gate/probe_version.py`

```python
def _read() -> int:
    path = os.path.join(_ROOT, "game", "src", "sim", "state.ts")
    src = io.open(path, encoding="utf-8").read()
    m = re.search(r"export const SAVE_VERSION\s*=\s*(\d+)", src)
    if not m:
        raise RuntimeError("state.ts 里找不到 SAVE_VERSION")
    return int(m.group(1))

SAVE_VERSION = _read()
```

纪律：**探针不写版本号**。`SAVE_VERSION` 涨一档，四十四个探针一处都不用改。找不到就抛，不静默退回 0 —— 静默退回正是这一批要消灭的东西。

### `tools/gate/probe_console.py`

```python
def on_console(sink):
    def handle(m):
        if m.type != "error":
            return
        loc = getattr(m, "location", None) or {}
        url = loc.get("url", "") if isinstance(loc, dict) else ""
        sink.append({"text": m.text, "url": url})
    return handle

def is_noise(entry):   # "laoyou-api" in entry["url"]
def noisy(entries)     # 只留不是噪声的
def texts(entries)     # 打印用
```

为什么不用「文本里含 404 就算噪声」：那样会把「少了 js」「图裂了」一起吞掉。**看来源 URL** 才是准的 —— 预览没有服务端，`/laoyou-api/*` 的 404 是设计如此；而 `assets/*.js` 的 404 是真事故。

旧式字符串条目一律**不算**噪声（`is_noise` 对 `str` 返回 False）：改漏一个调用点也不会因此放行。

### `tools/gate/probe_source.py` 扩展

```python
def side_ids(kind=None)   # 剥 "export const SIDES" 到 "\n];"，正则 id + kind
def noodle_ids()          # 剥 "export const NOODLES"
SIDE_TOP_IDS / SIDE_DRINK_IDS / SIDE_TOTAL / NOODLE_IDS / NOODLE_TOTAL
```

实测：加料 9 样（`suansun / douchi / lazhi / ludan / shengdan / zhuzai / youtiao / fuzhu / qingcai`）、饮料 4 样（`doujiang / huaifen / lvdou / ningmeng`）、`SIDE_TOTAL 13`、`NOODLE_TOTAL 6`、`MANUAL_TOTAL 16`、`MANUAL_SECTIONS` 五章。

文件顶必须 `from __future__ import annotations`：`str | None` 在 py<3.10 会在**导入期**抛 `TypeError: unsupported operand type(s) for |`，而且这行必须排在 `import` 之前（放后面是 `SyntaxError`）。

## 四、判据从「数出来」改成「对得上」

三条过期断言换法，都不再写数字：

```python
# 手册
checks["all_pages"] = base["pageCount"] == MANUAL_TOTAL
checks["all_groups"] = base["groups"] == MANUAL_SECTIONS
checks["details_closed"] = base["closed"] == MANUAL_TOTAL

# 加料台：表里每一条都得渲染出来
const ids = [...sec.querySelectorAll('[data-id]')].map((e) => e.dataset.id);
missing = all.filter((id) => !ids.includes(id))     # 判 not missing

# 粉型：只数粉型卡，条数取数据表
const cards = [...document.querySelectorAll('.ncard:not(.bcard):not(.mcard)')];
count == total 且 total == NOODLE_TOTAL
```

「每一条都渲染出来」比「行数等于 12」强：多一行少一行都不管，**少一条数据才红**。

## 五、九个写死端口

`dish / equip / expand / noodle / dayflow / sides / branch / unlock / setup` 原来都写死 `http://127.0.0.1:4173/`，且没有 `os.environ`。现在统一 `URL = os.environ.get("PW_URL", "http://127.0.0.1:4173/")`。

顺带一个坑：`vite preview` 只绑 `localhost`（IPv6），所以 `PW_URL=http://127.0.0.1:4246/` 会 `ERR_CONNECTION_REFUSED`。**要么 `localhost`，要么换端口。**

## 六、`?dev=1`：出处只在调试模式渲染

`game/src/ui/dev.ts:14` 的 `devMode` 只在 `?dev=1` 时让 `devNote()` 渲染。`sides` / `branch` / `unlock` 三个探针一直在**生产构建**上找「开罗：」，所以 `hasKairo` 恒 false。

```python
DEV_URL = URL + ("&" if "?" in URL else "?") + "dev=1"
```

三个探针改成打 `DEV_URL`。修好后 `sides` 的 `hasKairo` 立刻 true —— 出处一直都在，只是探针没去看。

## 七、同一个「灶」，两个数

3. `game/src/data/slots.ts` 只有四个灶坐标（x=2/4/6/8），批 BB1′ 补到六个（x=0/2/4/6/8/10，沿后墙 y=0）。
4. `game/src/sim/slots.ts:96` 的 `cap` 原来写死 `{ stove: 4, … }`，现在 `const cap = { ...SLOT_COUNT }` —— **表改长了这里不用改第二处**。
5. `layoutSummary` 第一格从「灶 N/4」改成「炒锅 N/C」：九十六格图数的是**炒锅口数**（设备档位），面板抬头那个数的是**灶位**（扩建档位）。两个数从此各有各的名字。

| 场景 | 改前（图 / 抬头） | 改后 |
| --- | --- | --- |
| 开局 | 灶 1/4 · 灶 1 | 炒锅 1/6 · 灶位 1 |
| 设备第 4 档 | 灶 4/4 · 灶 3 | 炒锅 5/6 · 灶位 3 |
| 设备第 5 档（黄金灶） | 灶 4/4（少画两个） | 炒锅 6/6 · 灶位 3 |

界面三处「灶」改成「灶位」：扩建档的 gain、顶档那句、店面抬头。扩建第 4 档的解锁词（`game/src/data/unlocks.ts:79`）也从「灶 +1」改成「灶位 +1」。

## 九、没动什么

- 不动任何经济数值：段位费、设备价、灶位档、来客上限、售价、料钱，全部原样。
- 不动 `MAX_EQUIP_LEVEL = 4` 的含义（不用段位就能买到的那四档）；第五档仍要评到第 8 段。
- 不删 `UnlockDef.pending` 字段（批 AZ′ 之后这一格是空的，但留着以便将来真要挂预告时不用改类型）。
- 不动探针的**判据强度**：只把「抄来的常数」换成「从表里读」，该红的还会红。

## 十、新缺口

- **P494**：`probe_source.py` 用正则剥 TS 源，`SIDES` 里若出现嵌套对象或注释掉的行会读错 —— 没有守卫。
- **P495**：`probe_console.is_noise` 只认 `/laoyou-api/`，将来加第二类良性接口（如埋点）每个探针都得改这一处才能过。
- **P496**：九个探针的默认端口仍是 4173，`PW_URL` 不传就跑错端口 —— 默认值该不该统一到 4246，没定。
- **P497**：「灶位」与「炒锅」改名后，`docs/` 里旧文档（批 AZ′ 与更早）仍在写「灶 N/4」，没有回头改。
- **P498**：`layout_probe` 的 `stove_five` / `stove_six` 断言「图上有 N 个灶格」，但没有断言这 N 格**位置对不对**（六个格挤在一处也过）。
