# 一步换掉（批 BE′ · 2026-11-27）

> 一句话：门路位满了以后，想从 A 换成 B 不必先撤再买 —— 那一行多一个「换掉「A」」按钮，
> 一次点击同时撤旧买新，**位子从头到尾不空**，钱只付新那一趟。顺带把「还剩几位」
> 写到打烊单脚注与账本页，不用每次都翻回店铺页去看。

这一批解两条缺口：**P505**（没有「换一条」的一步操作）与 **P506**（位子数只在门路抬头写一次）。

---

## 一、这一批要解决什么

### 1. P505：换一条要付两趟钱

批 BC′ 把门路的约束从「同类只能走一条」换成了**门路位**（开局 2 位、第 5 段 3 位、第 8 段 4 位），
于是多了一件以前不会发生的事：**位子满了想换一条**。

当时的做法只有两个动作 —— `cancelInvest` 与 `buyInvest`。于是换一条门路是：

1. 撤掉 A（`cancelInvest`）→ 位子空出来，**A 的钱不退**；
2. 买 B（`buyInvest`）→ **再付一趟钱**。

代价是「付两趟钱」，而且中间那一瞬位子是空的（如果这时正好手滑没买上 B，那天就白挂着少一条）。
玩家不会用「撤销 + 新建」来描述这件事，他会说「我想换一条」。

### 2. P506：位子数只在门路抬头写一次

`investSlotsWords(state)` 报的是「挂了几条 / 一共几位」（`0 / 2 位`）。它只出现在店铺页门路段的
抬头里。于是：

- 打烊单（一天结束时最该决定「明天要不要再买一条」的那一刻）看不到；
- 账本页（翻历史的时候）看不到；
- 玩家一关面板就忘了自己还剩几位。

### 3. 开罗是怎么做的（这一批的对照）

开罗 `rank.txt` 第 16 行只有一条相关能力：

```
16  More Investments  12  Invest in more things at once.  0 0 1 3 2 1 2
```

「同时能投几条」是**随段位涨的一个数**，开罗那边**没有**「换一条」这个专属动作 ——
因为它的门路本身就是「同时能挂几条位子」，换一条不需要额外的东西。
所以这一批对齐的不是某个开罗界面，而是「换一条本来就不该是一个要付两趟钱的操作」这条常识。

> 纪律一（只买量不买乘数）在这一批**没有被动过**：`swapInvest` 唯一的钱的变化就是
> `-to.costYuan`，一个倍率都不新增。

## 二、改法与代码

### 1. `InvestView` 多一个 `swapFrom`

```ts
export interface InvestView {
  def: InvestDef;
  active: boolean;
  leftDays: number;
  affordable: boolean;
  reason: string;
  /**
   * 位子满了又不差钱时，这一行可以**一步换掉**哪一条（批 BE′，解 P505）。
   * 挑的是「最快自己就结束的那条」—— 替它损失的剩余天数最少，玩家不用算。
   */
  swapFrom?: InvestDef;
}
```

`investViews` 里挑牺牲者用的是与 `leftDays` 同一把尺子：

```ts
const daysLeftOf = (d: InvestDef): number =>
  Math.max(0, investUntil(state, d.id) - dayIndexOf(state)) + 1;
let victim: InvestDef | null = null;
for (const d of live) {
  if (!victim || daysLeftOf(d) < daysLeftOf(victim)) victim = d;
}
```

并列时取 `INVESTS` 里靠前的那条 —— 顺序稳定，测试与探针才钉得住。

### 2. 位子满时，「两条路都说出来」

```ts
const hold = victim ? `现在「${victim.name}」占着` : "位子满了";
reason = canSwap ? `先撤一条，或者直接换（${hold}）` : `先撤一条（${hold}）`;
```

**旧口径「先撤一条」一个字都没删**：批 BC′ 的判据与 `bc_probe.py` 就钉在这几个字上
（`third_says_cancel_first` / `third_names_holder`），而且「先撤」确实仍然是可选的做法。
只是不再假装它是唯一办法。

### 3. `swapInvest(state, from, to)`

七条拒绝路径，**全部一分不扣**（顺序仍然是先判位子、再判钱）：

| 情形 | 说法 |
| --- | --- |
| `from` 不在表里 | 没有这条门路 |
| `to` 不在表里 | 没有要换的那条门路 |
| `from === to` | 换的还是同一条 |
| `from` 本来没在走 | 「A」本来就没在走 |
| `to` 已经在走 | 「B」已经在走了 |
| 位子没满 | 还有空位，直接买就行 |
| 钱不够 | 还差 ¥N |

成功时：

```ts
state.cash = Math.round((state.cash - newDef.costYuan) * 100) / 100;
const next = { ...(state.investments ?? {}) };
delete next[oldDef.id];
next[newDef.id] = dayIndexOf(state) + newDef.days;
state.investments = next;
```

`delete` 与写入在**同一次赋值**里完成，所以不存在「两条都不在」的中间态 —— 这就是
「位子没空过」在代码里的意思，探针 `slots_never_empty` 钉的是它。

**为什么 `from` 不退钱**：与 `cancelInvest` 同一个理由（`game/src/sim/invest.ts:208-212`）——
买的是「这几天它会做的那件事」，撤掉只是提前收手，钱已经花出去了；退款会立刻变成
刷钱漏洞（买 → 换 → 白拿几天效果还回血）。

### 4. 界面：按钮排在「先撤一条」前面

```ts
v.swapFrom
  ? `<button type="button" class="pickbtn" data-act="swapinvest"
       data-id="${v.swapFrom.id}|${v.def.id}"
       title="一步换：撤掉「${v.swapFrom.name}」同时买下这条，位子不空；前面那条的钱不退"
     >换掉「${v.swapFrom.name}」· ${money(v.def.costYuan)}</button><span class="tag2">${v.reason}</span>`
  : `<span class="tag2">${v.reason}</span>`
```

`data-id` 是 `旧|新` 拼起来的（`|` 不会出现在任何 id 里），`case "swapinvest"` 那边一眼能拆开。
按钮**同时**带着那句「先撤一条，或者直接换（现在「X」占着）」—— 探针 `third_says_cancel_first`
与 `third_says_swap_too` 各钉一半。

### 5. 打烊单脚注：`门路 N / M 位`

```ts
investSlotsFoot.textContent = `门路 ${investSlotsWords(s)}`;
```

放在 `.dayfoot`（与「今天到手 ¥X」「明天…」同一排），理由三条：

1. 打烊这一刻正是「明天要不要再买一条」的决策点，这时候该看得见；
2. 脚注不占 `foldWhyLines` 那七行的额度（P406 的坑：折行只收七条）；
3. 「0 / 2 位」也是信息 —— 空着两位本身就是该买点什么的意思。

### 6. 账本页多一格「门路 · N / M 位」

```
门路 · 2 / 2 位
跟料商多留一筐   多做 20 碗 · 还剩 2 天
请老师傅来看一天  出碗快 0.5 分 · 还剩 1 天
```

没挂的时候写「今天没挂门路。」，不是空白。

### 7. 顺手修掉的两处缓存键（第二十次、第二十一次）

- **第二十次**：`renderPane` 的 `ledger` 键原来只有
  `${months.length}|${years.length}|${pendingReport?.year}|${finished}|${cash/100}` ——
  账本页要多一格门路，就必须把 `investments` / `gradeLevel` / `days.length` 补进键里，
  否则换一条门路之后翻到账本页还是旧的。
- **第二十一次**：HUD 行情格（右下角那行）的键原来只有 `${mk.id}:${month}:${day}`。
  可这一格里还有「明天：X」半句，读的是**对冲 / 趁势**（`hedgedMarketIds` / `leanedMarketIds`）——
  买下「跟监管所报个备」之后今天那条行情往往没变，键也就没变，整格不重画，
  右下角还挂着买之前那句「明天：创城检查」。
  **`bb_probe.py` 的 `same_day_no_inspection` / `fifteen_days_clear` 两条红就是它**
  （不是对冲没生效：把对冲撤掉再读，那天真的又变回检查）。补上 `hedgeKey` / `leanKey` 之后
  `bb_probe` 从 22/24 变回 **24/24**。

## 四、三个坑（都踩过）

### 1. 「换下来的那条还能不能买」不能按「有没有买按钮」判

首版断言 `old_one_buyable_again`：换完之后旧那行应该重新出现 `buyinvest` 按钮。
**红**。因为位子仍然是满的（2 / 2），旧那行给的是「换掉「X」」按钮而不是买按钮 ——
这是对的（位子没空，凭什么能直接买）。改成 `old_one_back_on_menu`：那行有 `swap` 按钮、
并且点名**老师傅**（此刻挂着老师傅 1 天与夜市 2 天，最短的是老师傅，探针钉的就是「挑最短」）。

### 2. 面板开着时 `.modal` 盖住底栏，`page.click` 会卡到超时

切到账本页签必须走

```python
page.evaluate("() => document.querySelector('[data-tab=\"ledger\"]')?.click()")
```

否则 Playwright 的 `page.click` 报 `intercepts pointer events`，30 秒后超时。
（`bc_probe.py` 里切图鉴页签踩过同一次，这是第二次。）

### 3. 手册不许写阿拉伯数字

`game/src/data/manual.test.ts:30` 断言 `/[0-9]/.test(p.body) === false`。这批在手册里写
「门路位满了可以换一条」，一写「2 位」「3 条」就当场红 —— 一律写中文数字。
（批 BC′ 已经踩过一次，这次写之前就想起来了。）

## 六、新缺口

- **P513** `swapInvest` 的牺牲者是**唯一**的（剩余天数最少那条）。想让玩家自己选换掉谁
  （比如「换掉夜市而不是料商」），得给每一行都画一个按钮 —— 现在面板上是「被迫换最短的」，
  玩家想换另一条只能先撤再买。解法定：`swapFrom` 从单个变数组，或点按钮后弹一个小选单。
- **P514** 打烊单脚注与账本格读的都是 `investSlotsWords(state)`，也就是**当前**状态；
  翻历史月份（`s.months`）时看到的门路格仍是今天的，没有「上个月挂了几条」的记录。
  解法定：`DayRecord` 加 `investSlots: number` 与 `investRunning: string[]`。
- **P515** `swapInvest` 拒绝「还有空位，直接买就行」—— 这条对玩家是好话，但**没有「换到更便宜那条」的路径**：
  位子没满时想省几天、把贵的换成便宜的不行（只能撤）。要不要允许，取决于「撤掉不退钱」这条要不要松动（与 P505 同族）。
- **P516** `be_probe.py` 的 `swap_points_at_shortest` 认的是「点名老师傅」——
  这条依赖当天买的是哪两条门路。将来门路价钱一变，探针里那两句买法（`supplier` + `press`）也许要跟着改，
  但探针不会自己报错（只会变成「点名的是别人」）。
- **P517** `investViews` 现在每条都算一遍 `daysLeftOf`（12 条 × 每次渲染），
  位子一多就是 O(n²) 的 `Math.max`。12 条无所谓，门路加到 40 条就该先排一次序。
