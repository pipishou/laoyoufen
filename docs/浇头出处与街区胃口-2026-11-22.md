# 浇头出处与街区胃口（批 A′）· 2026-11-22

这一批做两件事，都是照开罗《The Ramen Sensei》的骨架补齐、再用南宁本地的材料重新落一遍：

1. **浇头出处审计**：老友粉的浇头一条一条找出处，查不到的不许进表（37 条 → 20 条）。
2. **街区胃口（appetite）**：补上开罗 `Sales Areas 2` 里「energy and appetite」那半句的另一半。

---

## 一、为什么要先做出处审计

上一轮数值校准把浇头价格压回半碗以内，但当时表里有 37 条 —— 里面有一批是我凭「粉店应该有什么」想出来的，
不是南宁老友粉真有的东西。用户指出「老友粉浇头很少有牛腩」，这句话背后是一条更硬的要求：
**一条浇头进表，必须能指着一份材料说「这是它」。**

于是逐条取证，落到代码里：`game/src/data/ingredients.ts` 的 `Ingredient` 多两个字段 ——

```ts
export interface IngredientSource { label: string; url: string; quote: string }
// Ingredient 里：
source?: readonly IngredientSource[];
note?: string;
```

`source` 写「谁说的 + 链接 + 原文摘句」，`note` 写「这条为什么留 / 为什么带条件」。
测试锁住三件事：每条都要有出处、链接必须是 http、摘句不能是空话（`label.length > 2 && quote.length > 4`）。

### 牛腩：留着，但降级成「加菜」

反证是硬的：

- 广西摄影网 `http://gxphoto.net/archiver/?tid-13993.html` 把南宁名粉列成**三个并列品类**——老友粉、猪蹄粉、牛腩粉；
- 老论坛帖原话：「老友粉的肉……注意一是猪肉，其他的牛肉的牛腩的什么的就不说了」；
- 而施记老友粉的加菜单里确实有牛腩（`http://mp.weixin.qq.com/s?__biz=Mzk1NzY0OTkyMg==&mid=2247487940&idx=1&sn=594ef47f1c60f74e46a2eb64c1258a93`：「加菜的选择也多，牛腩、肉片、猪杂、叉烧，最贵也才 7 块钱」）。

所以它不进「本体」，进「加菜」，并且 `note` 里把这件事写明：

> 加菜，不是老友粉本体：南宁老友粉的肉以猪杂为主，牛腩粉是玉林那一系的独立品类。

## 三、街区胃口：开罗那半句的另一半

开罗 `help` 里 `Sales Areas 2` 原话：

> The **energy and appetite** of your current area will gradually decrease, while they will increase in other areas.
> Energy: Affects shop visitation rate. Appetite: Affects how much ramen is eaten.

我们的 `game/src/sim/district.ts` 早就照做了 energy（`HOME_DECAY_PER_QUARTER = 0.09`，换区要付转让费），
但只做了「来不来」，没做「点多少」。于是「这条街吃腻了」唯一的表现就是人变少 —— 玩家看到的是
「客流掉了」，读到的却是「我做得不好」。

新增四个常量与四条函数：

```ts
export const APPETITE_DECAY_PER_QUARTER = 0.04;
export const APPETITE_GROWTH_PER_QUARTER = 0.03;
export const APPETITE_MIN = 0.75;
export const APPETITE_MAX = 1.15;

homeAppetiteOf(state)   // max(0.75, 1 - 0.04 × 季度)
appetiteOf(state, id)   // 别区 min(1.15, 1 + 0.03 × 季度)
districtAppetite(state) // = homeAppetiteOf
appetiteWords(state)    // 三句人话
```

**两条通道刻意不重叠**（这条是设计约束，写进注释了）：

| 通道 | 管什么 | 乘在哪 | 玩家的体感 |
| --- | --- | --- | --- |
| energy | 来不来 | `demandCapOf` / 客流池 | 门口的人变少了 |
| appetite | 点多少 | `pickSides` 的加购概率、`pickDish` 里三两款的权重 | 客人还是要来，只是不再加饮料、不再点大碗 |

`pickDish` 那一处写得最小心：

```ts
const portionW = item.portion >= 3 ? Math.min(1, appetite) : 1;
affordable.push({ item, weight: tasteW * priceW * portionW });
```

**不动价、不动钱包**。钱包是 `walletFloor`（P233）在管，价格是菜单在管 —— 把「吃得少」做成「买不起」
是同一个数字换了个借口，玩家会立刻发现 P240 那个坑。

界面：换区面板那一行现在写两件事 ——

```
这一片：客流 ×0.91 · 胃口 ×0.96 —— 这一片有点吃腻了（点单 ×0.96，换区能重新养回来）
```

## 四、浇头熟练度：手熟长在「料」上，不长在方子上

老友粉的手艺在备料：酸笋发得干不干净、猪杂切得厚不厚、豆豉爆到什么火候。
所以这一层长在 `recipe.toppings` 上，与方子、与店铺解耦。新建 `game/src/sim/topping-xp.ts`：

```ts
XP_STEPS = [50, 150, 400]      // 升 1/2/3 级各要多少碗
XP_TASTE_PER_LEVEL = 0.2       // 每级味道 +0.2
XP_TASTE_CAP = 2               // 封顶 +2
XP_COST_PER_LEVEL = 0.02       // 每级这一份料损耗 −2%
XP_PICKY_PER_LEVEL = 1         // 每级识食客少扣 1 分，封顶 3
```

三个出口（**只有三个**）：

1. **味道末段**：`sim/score.ts` 里 `totalFinal = totalOut + xpTasteBonus(...)`。加在 total 末段而不是
   soup / noodle —— 手熟是「这一碗」的事，挂在哪一维上都会把那一维的读数搅浑。
2. **料钱按件折**：`cookedTopCost += t.cost * xpCostFactor(xp, id)`，只压这一份料，不压主料/份量/进货档。
3. **识食客少扣**：`sim/customer.ts` 里 `tierPenalty = max(0, tierSatPenalty(...) - xpPickyEase(...))`。

**明确不许抬相**：`score.ts` 的 `Math.min(100, 30 + (charmBase - 30) * (1 + qualityCharmBoost(state)))`
已经被「头手货 ×1.55」顶到天花板，再抬相等于白送。

界面：托盘上每一枚浇头右上角有一枚小小的绿色数字（1/2/3，生手不显示），
`title` 里写着「生手（做过 0 碗，再做 50 碗升一级）｜出处：……」——
**出处与熟练度用同一口气说话**，玩家不用另开一个图鉴页去查这条料是从哪来的。

存档：`SAVE_VERSION 35 → 36`，`GameState.ingredientXp: Record<string, number>`；
迁移把负数、非数字扔掉，老档一律按「一手都没练」起算。

| 种子 | 月均营收 | 日均碗 | 流失 | 期末现金 | 裁决 |
| --- | --- | --- | --- | --- | --- |
| 1 | ¥94,272 | 200.7 | 43% | ¥114,190 | PASS_WITH_NOTES |
| 2 | ¥130,615 | 217.3 | 39% | ¥773,838 | PASS_WITH_NOTES |
| 3 | ¥122,272 | 206.2 | 42% | ¥612,856 | PASS_WITH_NOTES |
| 4 | ¥91,988 | 179.9 | 42% | ¥347,136 | PASS_WITH_NOTES |
| **均值** | **¥109,787** | **201.0** | **41.5%** | **¥462,005** | 四局全过，段位都到 11 |

对照上一轮（数值校准后的基线 ¥95,897 / 188.0 碗 / 41.8% / 期末 ¥339,227）：
营收 **+14.5%**、碗数 **+7%**、流失 **−0.3pt**、期末现金 **+36%**。

变化来自三处，读法要分清楚：

1. **浇头表从 37 条缩到 20 条**，替身那条朴素策略点出来的料更便宜（料钱少了），毛利变厚；
2. **熟练度只减料钱、封顶 +2 味道**，替身一天用同一份料几十次，36 个月足够把常用那几手练到 2–3 级；
3. **加购占比从 4.6% 掉到 2.5%**（3.8% / 1.8% / 1.8% / 2.6%）—— 这正是 appetite 想要的：
   同一批客人还来，但不再每碗都配饮料。营收反而涨了，说明这条通道没有伤到主生意。

四局仍全部 `PASS_WITH_NOTES`，段位都到 11；现金离散度依旧很大（¥114k – ¥774k），
那是热卖正反馈的种子间噪声（P171），不是这一批引入的。

## 七、新缺口

- **P245**：浇头出处只到「有这一份」，没到「这一份多少钱」—— 加价的锚点是金鹏那张价目单（¥6/¥7），
  20 条里有 11 条是照比例推的，不是抄的。
- **P246**：`西红柿` 与 `生菜` 属于「有人说必须有、有人说正宗没有」的一类，现在按「可选」处理，
  但游戏里没有「某家粉店的版本」这层概念，玩家看不出这两种是分歧项。
- **P247**：胃口只影响加购与份量，**没有一条台词或打烊单说明这件事** —— 玩家只能从「今天没人加饮料」反推，
  与 P144（队满时白天看不出走人原因）同一类毛病。
- **P248**：熟练度的 50/150/400 是拍的：按替身日均 190 碗、一份料一天用 40 次算，第一级要一天多，
  第三级要十天，但「一天用几次某份料」取决于玩家点单，长局里可能一次都不点酸笋。
- **P249**：`xpPickyEase` 只削扣分、不改识食客的「识食」判据，练满三手之后识食客与街坊的差别只剩口碑权重。
- **P250**：`ingredientXp` 是全局的，不区分哪家店 —— 开分店（批 10 之后）时熟练度会跟着老板走，
  而不是跟着师傅走。
