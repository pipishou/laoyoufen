# A4 碗 + A2 配料组合（2026-11-20）

## 一、三句话

1. **碗**：开罗 `bowl.txt` 只有五只、各自加成一条轴（charisma / volume / aroma / richness）；我们照南宁的真实碗换了五只 —— 消毒不锈钢碗、搪瓷碗、大盆（pang）、瓦煲、打包碗 —— 每一只都能在现实里找到出处，加成落回本作已经有的四个乘数。
2. **配料组合**：开罗 `topping_combo.txt` 是 38 条**任意两件浇头的配对矩阵**；我们只做 **24 条**，而且每条必须能拿出「有人真把这两样放进同一碗」的证据。矩阵不是味道，是化学反应表，玩家在一局两分钟里试不出来。
3. 两个系统加起来只占 **1 个存档版本（27→28）**，改动集中在 `data/bowl.ts`、`sim/bowl.ts`、`data/pairing.ts`、`sim/pairing.ts` 四个新文件与六处接线；替身（不换碗、配料固定）在 36 个月里逐位不变 —— 这一层只对「主动配碗」的玩家生效。

## 二、开罗原表长什么样

| 表 | 行数 | 结构 | 例子 |
| --- | --- | --- | --- |
| `English.lproj__bowl.txt` | 5 | `id / name / ? / 图标id / 加成轴 / 说明` | `Normal Bowl`（无加成）、`Lacquer Bowl`→charisma、`Porcelain Bowl`→volume、`Ancient Bowl`→aroma、`Potter's Bowl`→richness |
| `English.lproj__topping_combo.txt` | 38 | 两件浇头配对 + 四条效果列 | `0 Classic 0 2 2 0 -1 2 0 -1 4 1 0 0 0`、`22 Red Hot … 36 … 36 … 0 10 0 10` |

开罗的碗是**纯加成道具**：换一只碗 = 换一条轴 +2 或 +3，没有任何一句话、没有一个具体的手感。
开罗的组合是**穷举矩阵**：38 行 = 把 44 件浇头里能配的都列一遍，效果是 `4` 或 `10` 这种抽象档位。

## 三、碗：先取证，再定五只

四条硬事实（都核过原文）：

1. 南宁粉店用**统一消毒的不锈钢碗**，由指定单位回收配送，起因是九十年代那场乙肝恐慌；「更早以前是搪瓷碗，白色和肉色两种」——知乎《为什么南宁的粉店都用不锈钢碗？》`https://www.zhihu.com/question/31292350`。
2. 广西人不叫它不锈钢盆，叫 **pang**：「用这个装还能装多些」——网易 `https://www.163.com/dy/article/KT2HGU6G0548B7QF.html`。
3. 瓦煲是冬天的法宝：「瓦煲老友粉可是冬天暖身的法宝」——搜狐 `https://www.sohu.com/a/357659783_741950`。
4. 打包套袋 + 打包费：「打包一碗二两老友粉，用袋子就行」——南宁晚报 `http://nnwb.nnnews.net:8080/nnwb/20250628/html/page_04_content_000.htm`；柳盛加收 0.2 元。

据此定五只碗（`game/src/data/bowl.ts`）：

| 碗 | 价 | 样子 | 落地场景 | 数值 | 代价 |
| --- | --- | --- | --- | --- | --- |
| 消毒不锈钢碗 | ¥0 | 亮闪闪的钢碗，碗沿贴着一张「已消毒」的小纸签 | 南宁几乎所有粉店的默认碗 | 出碗 −3% | — |
| 搪瓷碗 | ¥600 | 白底带一圈蓝边的搪瓷碗，磕掉瓷的地方露出黑铁 | 九十年代那批粉店，老店还留着几只 | 满意 +1、耐心 +3% | — |
| 大盆（pang） | ¥1,200 | 比脸还大的不锈钢盆，汤能多舀一两勺 | 广西人家里与粉摊都这么叫 | 满意 +2 | 料钱 +3% |
| 瓦煲 | ¥2,600 | 黑砂瓦煲，端上桌还在冒泡，耳朵上垫一块布 | 人民路、北二里那些只卖早市午市的瓦煲粉店 | 耐心 +12%、满意 +1 | 出碗 +6% |
| 打包碗 | ¥900 | 一次性碗，外面再套一层塑料袋，盖子扣得严实 | 赶时间的上班族、外卖、夜市收摊前的最后一单 | 出碗 −5%、料钱 −2% | 满意 −1 |

三条纪律：**同一时间只用一只**（不做 CAP，单只数值就是上限）；**买要钱、换不要钱**（一局两分钟，做「施工期」玩家感受不到）；**加成只落已有乘数**（出碗时间 / 满意度 / 耐心 / 料钱，不新开一条轴）。

`game/src/sim/bowl.ts` 只有四个乘数入口 `bowlServeFactor` / `bowlSatBonus` / `bowlPatienceMult` / `bowlCostFactor`，加上 `buyBowl` / `setBowl` / `bowlViews` / `bowlSummary` / `nextBowl`。坏存档的碗 id 会退回钢碗。

## 四、配料组合：每条都要有「同一碗里」的证据

第一次做的时候我先想的是「照开罗做 38 条」，写了两条就发现不对：**老友粉的搭配不是任意配对**，是有数的几套吃法（猪杂、牛肉、牛腩、猪脚、三鲜……）。开罗靠 44 件浇头 × 38 条组合撑起「试错」，我们只有 37 件浇头、一局两分钟，做矩阵等于让玩家瞎猜。

所以改成 **24 条，四组**，每一组都有出处：

| 组 | 条数 | 例子 | 出处 |
| --- | --- | --- | --- |
| 猪杂 | 8 | 猪肝 + 粉肠（`liver_chitterling`）、猪肚 + 花肠（双脆）、猪杂 + 鹌鹑蛋、猪杂 + 番茄 | 金鹏菜单「老友猪杂粉：猪肉碎 猪肝 猪肠 猪肉」；北山「猪肝、粉肠、瘦肉、竹肠」「每碗标配香菇、鹌鹑蛋和绿豆芽」 |
| 猪牛 | 6 | 牛肉 + 肉末、猪脚 + 腐竹、牛腩 + 牛百叶、牛杂 + 牛丸 | 其英猪脚粉「可加青菜、腐竹、煎蛋」；潮牛汤粉王「鲜牛肉汤粉+牛杂+牛丸」；周记鲜牛 |
| 素菜 | 6 | 生菜 + 葱花、空心菜 + 酸笋、番茄 + 生菜、豆芽 + 空心菜、木耳 + 牛杂、花生 + 葱花 | 百家号「青菜：生菜、空心菜等时令蔬菜」；豆果「蕃茄，酸菜，酸笋，生菜，豆鼓…放生菜，有葱花的话可以洒上几粒」；下厨房「空心菜梗切小段」；益牛堂木耳牛杂粉；舒记「炸透的花生米」 |
| 老友味 | 4 | 酸笋 + 酸辣椒、豆豉 + 酸辣椒、豆芽 + 番茄、猪杂 + 葱花 | 搜狐砂锅粉「汤底是番茄和酸笋…豆芽青菜…辣椒和酸菜可以随便加」；唐记免费酸辣椒 |

**坚决没做的三件事**：

- 38 条任意配对矩阵（理由见上）。
- 紫苏（老友粉缺出处，沿用 B1 的判断）。
- 香菇 / 虾米 / 猪天梯 / 青瓜这类我们表里没有的件 —— 不编。想加就先加浇头（A5 材料分级那批再做）。

`PAIR_CAP = {soup 3, charm 3, sat 2, patiencePct 6%, costPct 3%, servePct 4%}`：24 条全成立也不会把数值顶爆，因为味道层（7 条，加成更大）本来就该压过「顺手凑的一搭」。

## 五、接线点（六处）

| 位置 | 做了什么 |
| --- | --- |
| `game/src/sim/state.ts` | `SAVE_VERSION 27→28`；`bowls: string[]` / `bowl: string`；初始化 `bowls: [], bowl: "steel"` |
| `game/src/sim/save.ts` | 白名单加 `v.saveVersion !== 27`；v27→v28 迁移：`bowls` 过滤表内 id 并去重，`bowl` 必须在表内且（免费或已买），否则退回默认碗 |
| `game/src/sim/customer.ts` | 四处：耐心链 `pairPatienceMult(...) * bowlPatienceMult(state)`、满意链 `pairSatBonus(...) + bowlSatBonus(state)`、成本链 `pairCostFactor(...) * bowlCostFactor(state)`、出碗 `pairServeFactor(...) * bowlServeFactor(state)` |
| `game/src/sim/score.ts` | `soup` / `charm` 各加一份 `pairingBonus`（与味道层同一个写法：抬 soup，不动 total —— total 是回归锁） |
| `game/src/ui/panels.ts` | 店铺页「碗 · …」段（五行）；配方页右栏「这一碗的搭配 · 凑成 N/24 搭」；图鉴页「碗 · N/5」段 |
| `game/src/main.ts` + `ai/lines.ts` + `server/app.py` | `buyBowl` / `setBowl` action；第 10 个 AI 落点 `bowl_voice`（客人端着新碗说一句），本地 6 句 + 服务端场景一句 |

`bowl_voice` 与 `style_voice` 同一个规矩：**本地句已经由 `buyBowl` 的 toast 说过一遍**，在线句只用来补「端着这只碗的人怎么说」，拿不到就什么都不说 —— 不重复同一件事。

## 六、一个真坑（第四次撞同一类）

`style_probe.py` 抓到的现象：换碗之后状态是对的（`state.bowl === "enamel"`），但店铺页的抬头还写着「瓦煲」、那一行还挂着「正在用」。原因还是**店铺面板的渲染缓存键**里没有新字段：

```ts
key = `...|${s.style ?? ""}|${(s.styles ?? []).length}|${remoteLineCount()}`;   // 改前
key = `...|${s.style ?? ""}|${(s.styles ?? []).length}|${s.bowl ?? ""}|${(s.bowls ?? []).length}|${remoteLineCount()}`;  // 改后
```

这已经是第四次（口味 → 店面 → 碗）。规矩要写死：**面板里出现的任何 `state` 字段，都必须出现在缓存键里**，否则「状态变了但屏幕不变」。

顺带修了探针自己的两个假红：「五只碗」原来数的是按钮数，正在用的那一行没有按钮（只有 `正在用` 标签），改成数碗段的 `.lrow`；图鉴断言原来用 `includes('碗 ·')`，会被配方页「主料 · 这碗是什么肉」误命中，改成 `startsWith('碗 ·')` 并限定在 `.pane[data-pane="collection"]` 内。

## 八、与开罗逐项对照

| 项 | 开罗 | 本作 | 判断 |
| --- | --- | --- | --- |
| 碗的数量 | 5 | 5 | 同量级 |
| 碗的加成 | 一条轴 +2/+3 | 落到四个已在算的乘数 | 本作更贴玩法（开罗的轴是它自己的评分体系） |
| 换碗是否花钱 | 买断 | 买断，换免费 | 本作更省事（一局两分钟的节奏） |
| 组合数量 | 38 条矩阵 | 24 条分四组 | 少 14 条，但每条都有「同一碗」的证据 |
| 组合的获取 | 试出来 | 面板直接写「只差什么」+ 出处进 title | 本作更可读 |
| 组合的 AI | 无 | 只补一句人话（`flavor_voice` / 后续可扩） | 本作独有 |

## 九、新缺口

- **P107**：碗只有「买 + 换」，没有「碗会脏 / 要洗」（开罗也没有，但南宁的钢碗是回收消毒的，这条叙事现在是空的）。
- **P108**：24 搭里「素菜组」的随机性偏弱 —— 生菜、空心菜、豆芽三件几乎同时上桌，一局里能同时成立四五搭，CAP 一按就没有差别感。
- **P109**：`bowl_voice` 六句不分碗（与 P106 同形），瓦煲和打包碗共用一个句子池。
- **P110**：配料组合没有「第一次凑成」的瞬间播报（味道层有 `lastFlavor`，搭配层没做）。
