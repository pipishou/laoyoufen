# 多款粉同时上菜单（P47）· 2026-11-15

## 三句话

1. **开罗的菜单是「一排券」，不是一个滑块**：客人进店先买票（`Staff 3`），票上就是某一款；店铺人气按菜单里所有款聚合（`Shop Stats`）。我们照这个模型做，最多 6 款，跟段位走。
2. **代码走「编辑缓冲」而不是重写 state**：`state.menu[]` 是账本，`state.recipe/price/noodle/main/portion` 是「正在调的那一款」的缓冲，`syncEditing()` 落笔、`selectDish()` 先落笔再加载。这样 265 个既有断言、三套探针、`scoreOf()` 全都不用改。
3. **一个真坑**：客人「买不买得起」的容忍价必须按**店里最好的那碗**算，不能按每款自己的味道算 —— 按款算会把便宜款判成「没资格卖贵」，菜单做多反而摊薄客单价（替身月均 ¥92.8k → ¥45.6k，改回来才回升）。

## 一、开罗取证（`English.lproj__help.txt`）

开罗**没有** menu 表，菜单语义散在 help 的几节里，正因为散，反而更清楚地说明它怎么运作：

| 开罗原文 | 含义 | 我们照做了什么 |
| --- | --- | --- |
| `Staff 3`「**After a customer buys a ticket**, the staff will ask about their preferences」 | 售卖机卖券，客人自己挑一款买票 | 客人进店时 `pickDish()` 挑一款，`dishId` 记进排队结构 |
| `Shop Stats`「popularity and charisma are calculated based on **the total values of the dishes it sells**」 | 人气/魅力是菜单**聚合** | `menuStoreScore()` 取在架款最高分，再乘款数奖励（每多一款 +3%，最多 +15%） |
| `Ramen Stats 1`「**Ingredients Costs: Deducted at the beginning of the month**」 | 每款各有自己的料钱 | 每款各自 `cost`（按款的主料/份量/配方算），仍按碗日扣（我们的日结粒度更细，写在这里以免误读） |
| `Ramen Lab 1/2`「You can sell unneeded ramen recipes here」 | 配方是资产，可以不卖 | 每款能上下架、能删（至少留一款） |
| `Customers 2`「choose noodles and soup according to their preferences」 | 客人按喜好挑 | 挑款权重 = 味道（越好吃越多人点）× 价格（越贵越少人点） |
| `Customer Fullness`「the higher a ramen's **volume**, the more fullness…」 | 份量是独立轴 | P46 的二两/三两已经接住；`dishPrice()` 把三两的 +¥2 算进菜单价 |

**结论**：开罗的「多款拉面」不是让你一次做六碗，是让你**在菜单上挂六行**，客人自己挑。我们要做的就是这个：菜单位 + 每行一款（配方 + 粉型 + 主料 + 份量 + 价）。

## 二、菜单位跟段位走（`game/src/data/menu.ts`）

| 段位 | 菜单位 |
| --- | --- |
| 0–1 | 1 款 |
| 2–3 | 2 款 |
| 4–5 | 3 款 |
| 6–7 | 4 款 |
| 8–9 | 5 款 |
| 10 以上 | 6 款（`MENU_MAX`） |

```ts
export function menuCapOf(gradeLevel: number): number {
  return Math.max(1, Math.min(MENU_MAX, 1 + Math.floor(Math.max(0, gradeLevel) / 2)));
}
```

挂在段位上是刻意的：段位本来就是开罗的「解锁新动词」那一层（`rank.txt` 的 Buy Small/Normal/Big/Amazing Shop 就是同一思路），菜单位跟着它走，玩家升段之后第一件事就是回配方页多挂一款 —— 这就是**中期决策点**（P24/P44 一直在找的东西）。

## 三、编辑缓冲（P47 的关键设计）

```
state.menu[0..n-1]   ← 账本：每款自己的 recipe / noodle / main / portion / price / on / sold
state.recipe, state.price, state.noodle, state.main, state.portion
                     ← 编辑缓冲：配方页所有滑块改的都是这一份
```

三个入口必须成对出现，少一个就会「改了等于没改」：

| 函数 | 干什么 | 谁调它 |
| --- | --- | --- |
| `syncEditing(state)` | 把缓冲写回 `menu[editing]` | `setParam` / `setPrice` / `setPortion` / 替身每次改价后 |
| `selectDish(state, i)` | **先 `syncEditing`**，再把第 i 款读进缓冲 | 点菜单卡片 |
| `addDish/removeDish/toggleDish` | 改 `menu[]` 本身，最后统一 `selectDish` 落在合法款上 | 点「加一款 / 删 / 上下架」 |

**踩过的坑**：一开始只在 `selectDish` 里同步，`setParam`/`setPrice` 没跟 —— 玩家拖完滑块看评分变了（评分读缓冲），但卡片上的价没动，切款再切回来就丢。修法是把 `syncEditing` 补进这三个 action。

## 四、客人怎么挑（`pickDish`）

```ts
const shopTolerance = priceTolerance(menuBestTaste(state));  // ← 店铺口径，不是按款
for (const item of activeDishes(state)) {
  const sc = scoreDish(item);
  if (dishPrice(item) > wallet * shopTolerance) continue;      // 买不起这款
  const tasteW = Math.max(0.1, sc.total / 100);                // 越好吃越多人点
  const priceW = clamp((wallet * 1.6 - price) / (wallet * 1.6), 0.25, 1); // 越贵越少人点
  weighted.push([item, tasteW * priceW]);
}
```

- **加权随机**而不是「永远挑最划算的那款」：否则菜单里只有一款会真的被卖掉，菜单等于没做。
- **容忍价按店铺口径**：这是替身实测逼出来的结论（见下）。

### 替身实测（同种子，唯一差别是菜单）

| | 种子 1 | 种子 2 |
| --- | --- | --- |
| P46（单款，容忍价按那一款算） | 月均 ¥92,841 · 成长 ×3.73 · 段 11 | 月均 ¥74,754 · ×3.76 · 段 9 |
| P47 第一版（容忍价**按款**算） | 月均 **¥45,611** · ×1.73 · 段 8 | ¥49,040 · ×2.15 · 段 8 |
| P47 修正后（容忍价**按店铺**算） | 月均 **¥56,557** · ×2.43 · 段 9 | **¥67,361** · ×3.23 · 段 8 |

两季裁决都还是 `PASS_WITH_NOTES`，唯一 high 是 **T3（12 月 / 8 月持平）**。

**怎么读这组数**：P47 比 P46 低，不等于做坏了。P46 的 ¥92,841 是「只有一款、所有人的钱都按那一款的品质去判」的偏乐观值 —— 客人被强行塞进同一碗，定价权其实只有一次。菜单把客人分流到不同款之后，定价要一行一行调，而替身目前只会「加一款、换个主料、跟主款同价 +1」，**不会分层定价、也不会剪掉卖不动的款**。下一轮该教量尺的是这两个动作（记作 P48）。

## 五、UI（配方页顶部）

- **菜单卡片**：一张卡一款 —— 品名（`dishNameOfItem`，按款拼「老友猪杂粉」这类名）、价、味道分与等级、累计卖出、在架/下架、删。正在编辑的那张加绿框 + 浅绿底。
- **加一款**：菜单位没满时最后是一张虚线卡；满了就写「菜单位满了（N/6）· 评到第 X 段再挂一款」。
- **加款默认换主料**：新款自动挑一个「菜单里还没人用、且已解锁」的主料（按满意加成降序、同分取便宜的）—— 否则点两下出来两碗一模一样的老友粉，玩家还得自己点主料卡才分得开。真店的菜单就是「老友粉 / 老友猪杂粉 / 老友牛肉粉」这么长出来的。

**真点验收抓到的错**：「素粉」的 `word` 写成了「素粉」，拼出来是「老友素粉粉」。改成 `word: "素"`（`name` 仍是「素粉」）。这种错只有真截图才看得出来，单测看不出来。
