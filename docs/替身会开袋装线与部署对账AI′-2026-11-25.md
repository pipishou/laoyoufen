# 替身会开袋装线、部署前对账事件表（批 AI′）

> 三件事都发生在「替身」和「发布」这两层，玩家屏幕上**一个字没变**：
> **P374** 替身不再无视袋装线、**P389** 换底真的看得见、**P420** 打包前先对账 `server/events.json`。

## 一、开罗怎么处理这三件事

| 开罗的做法（英文版资源原文） | 这里原来漏在哪 | 现在 |
| --- | --- | --- |
| `instant_noodles` / `instant_soup` 是**店里真会去卖**的东西（不是摆设条目） | W′ 做了三档货，但替身从不置办包装机 → 这条线从没被验过 | 替身有余钱就开，报尾写「袋装线 开了」 |
| 汤底是**换着用的**，玩家会为某碗粉专门换底 | 替身换了底，但只有四种子数字在动，没人知道换过几次 | 报尾写「换底 N 次」，换几次一目了然 |
| 数据表与程序分家、由一份真表导出 | 服务端那份事件表靠人手补，补完又走散过（批 N′ 之后 health 一直是 `events 32`） | 打包前跑 `gen:server`，不一致就当场重写，失败就中断发布 |

## 二、P374：替身自己会开袋装线

`game/src/sim/standin.probe.ts`：

```ts
if (!packOwned(s) && s.cash >= PACK_SETUP.costYuan + 12_000) {
  if (buyPack(s).ok) packsOpened += 1;
}
```

放在「扩建」之前、家当之后 —— 钱先留给该留的（扩建与家当各留八千，这台机器再另算一万二周转），
和 P400 教给替身的同一个道理：**先算清该留多少，再决定花多少**。

`packsOpened` 与 `baseSwitches` 都提到模块级（`pickSoupBase` 是模块级函数，拿不到循环里的局部变量），
报尾两处都印：`… 换底 1 次 · 袋装线 开了 …`。

## 三、P389：换底到底换没换，看得见了

原来只有四种子营收在动，换底这件事是**黑箱**。现在报尾直接把次数打出来，四种子分别是 **1 / 2 / 3 / 4 次** ——
说明替身确实在用这个动词，而且用得克制（36 个月里最多四次）。

## 四、P420：打包前对账服务端事件表

`deploy/deploy-cli.ps1` 在「1. 构建」与「2. 打包」之间插了一步：

```powershell
Write-Host "[1.5/5] server table"
Push-Location $game
npm run -s gen:server 2>&1 | Select-Object -Last 2
if ($LASTEXITCODE -ne 0) { Pop-Location; throw "server/events.json is out of sync with the game" }
Pop-Location
```

生成器自己就是判据：一致不写盘，不一致整表重写，写完再读回来数行数。失败即中止发布 ——
**走散的表不该有机会上线**。这一步在 `-SkipBuild` 下也会跑（构建步骤会跳，对账不该跳）。

## 五、数字（这才是本批的重点）

| 口径 | 月均营收 | 日均碗数 | 总流失率 | 期末现金 |
| --- | --- | --- | --- | --- |
| 批 AH′（替身不开袋装线） | ¥106,534 | 199.5 | 42.3% | ¥469,495 |
| **批 AI′（替身开袋装线）** | **¥134,450** | **227.9** | **37.3%** | **¥1,028,840** |
| 差 | **+26.2%** | +14.2% | −5.0 pt | **+119%** |

四种子：¥138,602 / ¥121,759 / ¥140,559 / ¥136,879（换底 1 / 2 / 3 / 4 次，四局都开了袋装线）。

读法：**这不是把数值调高了，是把一条已经写好的产品线真正接上电**。袋装线的钱不进客流乘数，
但它让替身更早买得起灶与扩建 —— 所以碗数与现金跟着一起动。
上一批（AH′）四种子逐位不变，是因为那批只改说法；这一批改了**替身会不会用一个系统**，数字当然要动。
判断依据是：`game/src/data/pack.ts` 与 `game/src/sim/pack.ts` 一行没改，改的只是量尺肯不肯用。

## 七、新缺口

- **P422** 替身开袋装线是一步到位的（攒够钱就买），真人会算「多久回本」；界面也没有回本天数（与 P361 同型）。
- **P423** 报尾的「换底 N 次」只记成功次数，没记「想换但钱不够」被挡了几次 —— 那才是 P400 守卫的真实压力。
- **P424** `gen:server` 现在挂在部署脚本里，本地 `npm test` 抓不到表走散（只有发布时才炸）。
- **P425** 替身的包装机钱从「扩建前的现金」里出，与 P362 的扩建阶梯没有互相引用，谁先买只是代码顺序。
