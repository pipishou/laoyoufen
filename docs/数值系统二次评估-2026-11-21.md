# 数值系统二次评估：六项改造在本土化与 AI 两项约束下重排

> 上一份 `docs/开罗数值系统解剖-2026-11-21.md` 只解剖了「数值骨架」，给出了一个按**技术依赖**排的顺序（口数 → 九档 → 配料 tier → 段位 → 改良 → 行情）。
> 这一份补读 8 张此前没读的表，然后换一个坐标系重排：**按「本土化是否成立」与「AI 能不能落点」两个约束**重新评估每一项该不该做、做成什么形状、排在第几。
> 结论先行：**原顺序基本是反的**。九档该第一，产能该第二，行情从最后提到第三，而「改良扩五级」应该被「技法树」替掉。

### 三条新发现（改变判断的）

**发现 A：开罗的「档」是素材自带的，不是全局分级。**
`topping` 每行两组四维值、`soupmaterial` 每行 2–3 档效果 + 2–3 档价格、`noodlesmaterial` 每行三组数。也就是说开罗**没有「配料 tier 表」这一层**，档是长在每个素材里的。我们上一版提的「四 tier」是简化 —— 可以接受，但必须写成「品质档」，不能说成「升级档」，否则语义就假了。

**发现 B：开罗真正的成长线是「技法」，不是「改良」。**
`custom` 只有 4 行（品质/难度/价格/料钱），而 `ramen_skill` 45 + `finishskill` 11 + `clerk_skill` 21 = **77 条技法**。我们上一版把 `custom` 当成「改良」并建议扩成 5 级 —— **扩的是最小的那条线**。真正缺的是技法树。

**发现 C：开罗的同行会「卖东西」。**
`enemy_store` 每家带菜单字符串与价目（820 / 150）。我们的 `RIVALS` 只有人气一个数，所以「同行打价格战」「同款卖 ¥8 你卖 ¥10」这类玩法根本长不出来。

## 1. 六项二次评估

评估维度固定四条：**① 本土化是否成立（南宁有没有对应物）② AI 有没有落点（能不能锁成池子）③ 与现有系统的耦合风险 ④ 新证据下形状要不要改。**

### 1.1 九档显示 —— 结论：**升到第 1 位**，且四维要改名

- **本土化**：开罗四维是 味 / 香 / 量 / 气。我们照抄会得到一个不存在的东西 —— 因为本作的 `soup` / `noodle` 是**原料维度**（汤几分、粉几分），不是客人的感知维度。南宁吃粉的人评价一碗粉只说四件事：
  - **够不够味**（味道沉不沉）
  - **镬气有没有**（爆香那一下）
  - **够不够饱**（二两还是三两）
  - **好不好看**（卖相）
  → 九档要挂在这四个上：`taste9 / wok9 / fill9 / look9`。**这是本项最重要的修正**，不做这一步，九档只是给现有分数换皮。
- **AI**：九档是 12 个落点里**唯一一个能把「判断」交给数值、把「措辞」交给模型**的结构。现在 `guest_voice` / `flavor_voice` 都是自由发挥，一旦锁到「第 7 档的味 + 第 3 档的镬气」，模型的输出空间就落在可验收的范围内。→ **AI 收益最大的一项**。
- **耦合**：零。只加显示映射 + 语料池，不动任何乘数。
- **形状修正**：不是「0–100 → 9 档」一刀切，而是**四维各自九档 + 总分九档**（开罗 `eat_comment` 也是四维各九档，没有总分九档 —— 这一点跟上版不同）。
- **排序理由**：它是后面每一项的**共同语言**（配料 tier 说「+1 档」，技法说「+2 档」，改良说「锁到第 N 档」）。上版把它排第 2 是依赖方向搞反了。

### 1.2 产能三段 —— 结论：**留第 2，但模型从「口数」改成「三段」**

- **本土化**：南宁粉店的产能不是「几口灶」，而是三段串行且各有独立上限：
  - **炒锅**（爆香酸笋豆豉，一次一锅，1–2 口）
  - **汤锅**（滚汤，一口大锅，能同时下几碗）
  - **粉篓**（烫粉，4 筒 / 8 筒，一筒一碗）
  → 照搬「1/2/4 口灶」会失真；照搬「并行度」这个**建模方式**则完全成立。
- **AI**：无直接落点。但 HUD 的「2 口锅 · 每碗 1.0 分钟」与钩子的 `tightWords`（「灶台出得慢 / 座位坐不下 / 备料不够卖」）需要一个**统一的三段口径**，否则副行还会说错话（这正是试玩四轮 P144 的同类问题）。
- **形状修正**：
  ```ts
  STOVE_SLOTS = [1, 2]        // 炒锅
  POT_SLOTS   = [1, 1, 2]     // 汤锅（现有四档设备映射到三档）
  BASKET_SLOTS= [4, 6, 8]     // 粉篓筒数
  serveNow = max(单碗时间 / min(BASKET/座位需求, POT×并行), 炒锅节拍)
  ```
  三段里**炒锅是节拍器**（爆香一次只出一碗），这也是南宁粉店真实的手感：锅不够，篓再多也没用。
- **耦合**：**唯一会动替身基线的项**（P149）。越早做越早把新基线立起来，所以排第 2。
- **风险**：三段模型比「口数」多两个参数，调参空间变大。**回退闸**：替身种子 1 / 2 的月均不得低于当前 ¥74,345 / ¥89,061 的 95%。

### 1.3 行情层 —— 结论：**从第 6 提到第 3**，理由是与试玩结论正面咬合

- **本土化**：开罗 26 条（钱包/吃速/价格/材料/四季/流派热潮）在南宁全都有硬对应，且**都有出处方向**：回南天、寒潮、发薪日、开学、雨季、酸笋季节、猪杂涨价、老友粉出圈。这一项的本土化风险是六项里**最低**的。
- **AI**：行情是**唯一能同时吃两项约束**的模块 —— 它给报纸提供「为什么」，给客人闲聊提供「最近怎样」。A11 现在是**只播结果不解释原因**（P129：打烊单与报纸不呼应），行情层正好补上。
- **耦合**：乘数乘在顾客已有的五个出口上，与档位/家当/门面/碗/方子五层叠乘（P148 已记）。所以**必须有封顶与单条上限**。
- **形状修正**：不照搬 26 条，做 **8 条**（`payday` / `rainy_week` / `cold_snap` / `sour_bamboo_short` / `street_fair` / `exam_week` / `pig_offal_boom` / `old_friend_fame`），**一次只跑 1 条**，每条乘数上限 ±20%。
- **排序理由**：上一版按「技术依赖」把它放最后（因为要乘在所有出口上）。但按「解释层价值」它该靠前 —— 试玩四轮的核心发现就是「钩子只有一只眼睛」，行情层就是给玩家第二只眼睛。

### 1.4 段位重标 —— 结论：**留第 4，但改结构：降费、提门槛、加评语**

- **本土化**：南宁办证/评星是**一次性行政成本**，不会一路涨到几十万。开罗 5,000 → 5,000,000 是游戏化的「资格费」。本土化正解：**总费用压到 ¥135,000 内（≈9 个月营收），把大头放进「评审标准」**（累计人次 + 口碑 + 特色菜数 + 是否有传承人认定）。
- **AI**：`grade_voice` —— 评上那一刻由评委/老师傅说一段话，**天然适合 AI**，且是第 13 个落点。这一项因此从「纯数值」升级成「数值 + AI」。
- **耦合**：改一个数组 + 门槛权重，独立。
- **形状修正**：费用 `[500, 1000, 2000, 3500, 6000, 10000, 16000, 25000, 40000, 60000, 0]`（合计 ¥161,500，≈10.5 个月营收）；同时把 `minCustomers` 提一档、加 `minReputation`。

### 1.5 配料品质档 —— 结论：**留第 5，语义从「升级档」改成「品质档」，并与九档咬合**

- **本土化**：开罗的「两档价」是随段位升级（同一配料越买越好）。南宁现实是**同一配料不同品质/季节价差**（酸笋旺季 vs 淡季、猪杂新不新鲜）。所以档 = **品质级**（普通 / 精选 / 时令 / 招牌），不是「升级」。
- **AI**：`tier` 影响卖相与味道 → 客人评语按档选池。**AI 不许改价、不许推荐档位**。
- **耦合**：依赖九档（贡献按档数），依赖产能（备料并行决定能不能进高档料）。排第 5 是对的。
- **形状修正**：四档价 ¥0.5 / ¥1.2 / ¥2.5 / ¥4.0，料钱 ¥0.2 / ¥0.5 / ¥1.0 / ¥1.8；**任一配料价格 ≤ 一碗价的 40%**（不变式）；四维贡献 tier→+1/+2/+3/+4 档，与 1.1 直接乘。

### 1.6 改良扩五级 —— 结论：**降级，被「技法树」替掉**

- **证据**：`custom` 只有 4 行，`ramen_skill` + `finishskill` + `clerk_skill` 有 77 条。上一版把最小的线当主线扩了。
- **本土化**：南宁没有「给一道菜点五次天赋」这种事；有「学徒 → 师傅 → 老师傅 → 传承人」的手艺层。所以技法要挂在**人**身上，不是挂在**款**上。
- **AI**：技法本身无数值外落点，但「练成那一刻的一句话」可以走 `master_voice`（复用 A6 的 `line`）。
- **形状修正**：技法树 **12 条 × 3 级**（炒锅 3 / 汤 3 / 粉 3 / 接客 3），每条给「+N 档」而不是「+N%」；第 3 级要有人情门槛。A6 的方子 5 级扩展降为 P2（可选）。
- **排序**：第 6（最后），因为它依赖九档的「档」与产能的「并行度」。

## 2. 评估后新增一项：同行菜单与定价（排第 4.5）

- **证据**：`enemy_store` 每家带 `菜品 & 售价 & 成本`，人气 30、日销 14、三档资本。
- **为什么值得做**：试玩四轮的结论是「流失原因是价牌」，但玩家看不到**别人卖多少**。同行有价目之后，「隔壁卖 ¥8 你卖 ¥10」就变成可感知的，压制价牌的焦虑不需要 AI 也能成立。
- **本土化**：南宁同行是有价目表的（8 元二两、加料另计），照抄结构即可。
- **AI**：无需 AI（纯数据），但可以走 `rival_voice`（同行老板说的话，现无落点）。
- **代价**：要给 8 家同行各配 1–2 款招牌与价目，**8×2 条内容**，小。
- **结论**：插入第 4 与第 5 之间，标 P1。

## 5. AI 能力的净增量（这是二次评估的第二个产出）

现有 12 个落点里，**没有一个使用「档位」**。重排后新增两个落点，改造两个：

| 落点 | 现状 | 重排后 | 锁什么 |
|---|---|---|---|
| `guest_voice` | 按顾客类型选池 | 按「四维档位 + 顾客类型」选池 | 档位由数值定，模型只写措辞 |
| `flavor_voice` | 按味道组合 | 同上，且档位 ≥6 才触发 | 不许夸无档位的组合 |
| `grade_voice`（新） | — | 评段位成功/失败时评委说一段 | 必须含「差在哪一项」，不许空泛 |
| `market_voice`（新） | — | 行情当天报纸头条 | 必须说清「这几天为什么这样」，不许编天气 |
| `rival_voice`（可选） | — | 同行老板的口气 | 只能谈自家价目 |

**为什么这是净增量**：现在模型之所以会「空句」或「说错话题」，根子是**给它的名词太粗**（试玩四轮已经证明这条：主句与副行打架，改的是 `hookVoiceContext` 的名词粒度）。九档把「粗名词」变成「档位 + 维度」，模型的可发挥空间从「一整段自由」缩到「同一档的几种说法」—— 这正是 `ai_gate` 能验收的形状。

## 6. 验证与回退（每项都要能证伪）

1. **九档**：`tier9Of(0)===1 && tier9Of(100)===9`；四维档位与总分档位差 ≤2；改九档后替身 36 月三个数字**一位都不许变**（纯显示层）。
2. **产能三段**：替身种子 1 / 2 月均 ≥ 当前 95%（¥70,628 / ¥84,608）；`capacityGain` 与 `nextGear` 读同一个 `slots`；HUD 的「每碗 N 分钟」与 `serveNow` 同源。
3. **行情**：任一单条乘数 ≤ ±20%；连跑 60 天，同一行情不重复触发；替身流失率波动不超过 ±3 个百分点。
4. **段位**：费用合计 ≤ 12 个月营收；每一级的 `minCustomers` 单调递增。
5. **配料档**：任一配料 ≤ 一碗价 40%；四档件数分布不为空（每档至少 3 件）。
6. **技法**：每条技法 3 级、第 3 级有人情门槛；同一条技法不重复生效（P133 的教训）。
7. **同行菜单**：8 家各有 ≥1 款招牌；价目与 `PRICE_BANDS` 同区间。
