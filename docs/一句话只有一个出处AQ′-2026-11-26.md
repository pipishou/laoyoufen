# 一句话只有一个出处（批 AQ′，解 P451）—— 2026-11-26

## 一、要解决的问题

批 AP′ 把「抬了也卖不动」说到了四处，但**每处各抄了一遍字符串**：

| 位置 | AP′ 之后各自的字面 |
| --- | --- |
| 打烊单主句（`hook.ts`） | 街上就这么多人 —— 店里再添什么也卖不动 |
| 打烊单「为什么」区（`hud.ts`） | 店里这三段再添也卖不动 —— 卡在街上进来的人，得去把街面、名声、同行那几件事办一办 |
| 店铺页设备段（`panels.ts`） | 今天这三段再添也卖不动 —— …想多卖，得让街上更热闹：**修街面、比赛赢过同行、把口碑养起来、换个人多的区** |
| `todayLine` 副句（`today.ts`） | 店里再抬也卖不出去 · 想多卖，得让街上更热闹：**修街面、比赛赢过同行、把口碑养起来、换个人多的区** |

「那四条路」在两处各列了一遍，「卖不动」这个口径在四处各写了一遍。**改一处忘一处，就是 P448 复发** —— 而 P448 的病灶正是「同一件事两处说反话」。

这和 P344（`server/events.json` 靠手工重导）、P386（设置里的操作一览是手册的副本）是同一个型：**同一个事实在两份地方维护**。

## 二、做法：一份常量，四个落点

新建 `game/src/data/demand.ts`，八个导出：

```ts
export const DEMAND_WHERE = "修街面、比赛赢过同行、把口碑养起来、换个人多的区";  // 全项目只列一次
export const DEMAND_HEAD   = "街上就这么多人 —— 店里再添什么也卖不动";          // 打烊单主句 / 钩子 text
export const DEMAND_PANEL  = `今天这三段再添也卖不动 —— 灶、座位、备料都还有富余，卡在街上进来的人就这么多。想多卖，得让街上更热闹：${DEMAND_WHERE}。`;
export const DEMAND_DAY    = `店里这三段再添也卖不动 —— 卡在街上进来的人，想让街上更热闹：${DEMAND_WHERE}`;
export const DEMAND_DETAIL = `店里再抬也卖不出去 · 想多卖，得让街上更热闹：${DEMAND_WHERE}`;
export const DEMAND_SHORT  = "店里再添也卖不动";   // 「今天先不动」里那句的短版
export const DEMAND_TAG    = "卖不动";             // 打烊单那一行的前缀
```

四个调用点改成引用：

- `game/src/sim/hook.ts` → `text: DEMAND_HEAD`
- `game/src/sim/today.ts` → `detail: DEMAND_DETAIL`
- `game/src/sim/align.ts` → `demoted.push(`${DEMAND_SHORT}（${tightWords(state)}），今天先不添`)`
- `game/src/ui/panels.ts` → `<span data-demand-blocked>${DEMAND_PANEL}</span>`
- `game/src/ui/hud.ts` → `demandLine.textContent = plan.key === "capacity:demand" ? DEMAND_DAY : ""`

`DEMAND_TAG` 与 `hud.css` 的 `.daywhy [data-demand-line]::before{content:"卖不动 · "}` 同源 —— 这一条由测试盯着（CSS 读不进 JS，只能靠断言）。

## 三、防止再抄一遍：新增 `game/tools/demand-literal.test.ts`

写常量没用 —— 下次谁手一快又抄一遍，就白做了。所以配一组**扫源码**的测试（6 例）：

| 判据 | 做法 |
| --- | --- |
| 三条要指路的句子都带那四条路 | `DEMAND_PANEL / DEMAND_DAY / DEMAND_DETAIL` 各 `toContain(DEMAND_WHERE)` |
| **那四条路只在 `data/demand.ts` 里列一次** | 扫 `src/**/*.ts` + `*.css`，去掉注释后谁还含 `DEMAND_WHERE` 全文就红 |
| **别处不许硬编码「再添也卖不动」** | 同上扫这一串，命中就点名文件 |
| 主句不点名任何一件东西、不带价钱 | `DEMAND_HEAD` 不匹配 `/凳\|灶\|锅\|案台\|备料\|¥\|\d/` |
| 打烊单前缀与 CSS 的 `::before` 同源 | `hud.css` 里必须出现 `[data-demand-line]::before{content:"卖不动 · "}` |
| 五句都不带阿拉伯数字 | 服务端 `CN_QUANTITY` 会丢带数量词的整句 |

两个实现细节值得记下来：

- **测试必须放 `game/tools/`，不能放 `game/src/`**：要读盘就得 `import { readFileSync } from "node:fs"`，而本仓没装 `@types/node`，`tsc` 盯 `src` 会报 `TS2591`。第一版放在 `src/data/demand.test.ts`，`tsc` 立刻三红 —— 和批 AH′ 的 `server-events.gen.ts` 是同一个坑。
- **扫源码要先剥注释**：`align.ts` 里有一句注释「这一句和打烊单、店铺页设备段说的是同一件事，别让第三处再喊」，里面就有那几个字；注释是给人看的说明，不算玩家可见文案。`codeOnly()` 去块注释 + 去整行 `//` / `*` 开头的行，再判。测试文件本身也排除（它们断言的就是常量）。

## 六、这一批没动什么

- **没动任何数值**：`capacityOf` / `capacityGain` / `demandPerDay` / `EAT_MINUTES` / `SEAT_IDLE` 一格没改；四种子逐位不变。
- **没改任何一句话的意思**：四处字面**只重排了措辞**（打烊单那句原来尾巴是「得去把街面、名声、同行那几件事办一办」，现在改成与另外两句同一套四条路 —— 这是本批唯一的可见文案变化，探针与截图都盯着）。
- **没碰 `SaveVersion`**：仍是 37。
- **没加服务端场景**：`hook_voice` 场景不变，`LINE_BUDGET` 仍 360。

## 七、新缺口

- **P455** `DEMAND_TAG` 与 `hud.css` 的 `::before` 是「同一份事实两处写」，测试只能断言「CSS 里有这一串」，**改 CSS 的写法（比如加空格、换单引号）就会红，但改完仍然一致** —— 这类「跨语言同源」目前只有这一个靠字符串匹配的土办法。
- **P456** 这份 `data/demand.ts` 是第一个「只为文案而存在的数据模块」，`entry-counts` 的 43 项里没有它（它不是条目表）—— 也就是说**文案类常量没有条数对账**，与 P440 同型但方向相反（清单不覆盖文案）。
- **P457** 四条路里的「换个人多的区」现在只是文案，`换区` 在游戏里是**重开一局**（换初始区），不是「搬店」—— 玩家照着做会发现跟想象的不一样。
