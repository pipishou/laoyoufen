# 插件盘点与多窗口协同选型（2026-11-27）

> 老板问的是两件事：**① 本机到底装了哪些插件、还有哪些没装；② 有没有「多窗口协同」这类插件，有的话按它的指导把多任务并行排出来。**
> 这一份就是回答。所有结论都来自本机实测（`node_modules` 里的源码、`profile` 的 `cordis.patch.yml`、插件注册表 13,445 条），不是凭印象。

---

## 一、一句话结论

**跨任务记忆你已经装了两个（`hindsight-coding-agents` 0.8.8 + `dsh-project-memory` 0.7.2），它们按工作区绑定 —— 两个窗同一个 cwd 就自动共享同一份记忆，这一层不用再装。**

**但「窗口之间互相说话」这一层，本机一个都没启用。** 注册表 13,445 条里真正能用的只有两个（`dsh-parallel-sessions` v0.6.0、`dsh-tool-session-message` v0.2.0），两个都跟本机内核 0.2.2-rc.5 兼容，我把它们的服务依赖逐个在源码里核过了。

**建议的最小组合是三件，不需要装第三方团队包**：

| 件 | 作用 | 怎么开 |
|---|---|---|
| `@deepseek-ai/dsh-experimental-session-search`（**官方内置，已装未启用**） | 让 agent 能**搜历史会话**（5 个只读工具）—— 两个窗共享同一批历史，等于「跨窗口记忆」的读侧 | 插件页加 `@deepseek-ai/dsh-experimental-session-search` → 启用 |
| `dsh-parallel-sessions`（**第三方，v0.6.0**） | 窗与窗**互相发话 / 暂停 / 恢复**，消息在对话流里带归属气泡 | 插件页加 `github:CatLollipop/dsh-parallel-sessions` |
| `dsh-experimental-agent-team` 的 Team 模式（**官方内置，已挂但新会话默认关**） | 一个窗内部拆多个 agent 并行，共享任务板 + 依赖 + 写作用域 | 模型与推理等级菜单里打开「使用智能体团队」 |

**不要装**：`dsh-team-rooms`（已 RETIRED）、`dsh-session-fork`（peer 钉死在 0.2.1-rc.2…0.2.2-rc.1，本机 rc.5 不在范围）、`dsh-task-relay`（peer 上界 `<0.2.0`）。

## 五、本机 API 兼容性实测（装之前先把服务核清楚）

这一步是这轮最有用的部分：**第三方插件的 `inject` 列表里每个服务，我都在本机源码里找到了注册点。**

| 服务 | 提供者 | 证据 | 结论 |
|---|---|---|---|
| `agents` | `@deepseek-ai/dsh-agent` | `super(ctx, "agents")`（`dsh-agent\lib\index.js`） | ✓ 在 |
| `followup(input)` / `steer(input)` / `inject(input)` / `cancel(...)` | `@deepseek-ai/dsh-agent-loop` | `followup(input) { this.send(input, "next-turn", true) }`、`steer(input) { this.send(input, "next-step", true) }` | ✓ 在（`parallel_hold` 用的就是 `live.cancel()`） |
| `sessionQuery` | `@deepseek-ai/dsh-session-query` | 服务已挂；base 用 `openAt: never` 挂载，注释明写「keeps `ctx.sessionQuery` mounted — exact reads, titles, and lineage traces stay available — while search calls fail with `SESSION_QUERY_SEARCH_DISABLED`」 | ✓ 在（`parallel-sessions` 只调 `listSessions` / `readSession` / `readTitleSnapshots`，**是精确读，`openAt: never` 下可用**） |

## 六、装与开的动作（三条，都带确切写法）

### 6.1 开历史会话搜索（官方，解锁「跨窗口记忆」的读侧）

**做法 A（桌面 app，推荐）**：设置 → **插件** → 添加插件 → 输入

```
@deepseek-ai/dsh-experimental-session-search
```

选**安装** → 选**立即启用**。DSH 用随包版本，不用下载。开了 HMR 就即时生效，否则重启。

**做法 B（写进 profile）**：`C:\Users\Mo\.dsh\profiles\desktop\package.json` 的 `dsh.profile.bundles` 里加一行 `"@deepseek-ai/dsh-experimental-session-search"`，重启。

> **它能干什么**：两个窗（同 cwd）都能 `session_search` 搜到对方**和过去的自己**说过的话。这是目前最接近「跨窗口记忆」的读侧能力，而且官方维护。
> **它不能干什么**：只读；搜不到离线会话之外的东西；结果没游标，只能一次拿一批。

### 6.2 开窗与窗之间的发话（第三方 `dsh-parallel-sessions` v0.6.0）

设置 → 插件 → 添加插件 → 输入

```
github:CatLollipop/dsh-parallel-sessions
```

装完它自带 `cordis.patch.yml`（Host 半区注册 4 个工具 + Client 半区给消息加归属气泡）：

```yaml
- insert:
    - id: parallel-sessions
      name: 'dsh-parallel-sessions'
      inject: [tools, agents, sessionQuery]
      config:
        guide: true                 # 有并行会话时注入一段协调指引
        autoReleaseOnTurnEnd: true   # holder 本轮结束自动放开
        holdCancel: true             # 暂停 = 真停，不是发条消息
        maxHolds: 8
        pairMessageLimit: 10         # 一对会话 60 秒最多 10 条
        pairWindowMs: 60000
        maxTextBytes: 32768
```

**它的四条边界（决定我们怎么用）**：
1. 只协调**同一工作区的顶层会话** —— 我们两个窗同 cwd，正好；
2. **不会创建 / 唤醒会话**：目标必须是 running 或 idle，离线会被拒；
3. 暂停登记只在**进程内存**，重启就没了；
4. 一对会话限速 10 条 / 60 秒。

### 6.3 备选：只要「发一句话」的极简版

如果不想装带界面的那个，`dsh-tool-session-message` v0.2.0 只有一个工具：

```
github:BigBugy/dsh-tool-session-message
```

`session_send(session_id="session-…", message="…", mode="followup"|"steer")`，消息自动带 `from:` / `reply:` 头，对方看得见是谁发的、怎么回。
**限制**：`engines.dsh: ">=0.2.1-rc.5"` 满足；它**不列会话**（得自己知道对方 session id），也不带暂停 / 恢复。

## 七、按插件指导排出来的多任务并行推进

这一节是「怎么用它」，不是「能不能用」。

### 7.1 三种并行，分清楚层级（别把三层混成一层）

| 层 | 谁和谁 | 靠什么 | 本机状态 |
|---|---|---|---|
| **A 层 · 会话内部** | 一个窗里的主 agent + 子 agent | `subagent` / `subagent_fork` / `workflow` / `ralph`；Team 模式再加 `team_task_*` 任务板 | **通**（`delegation` 组已挂），但 Team 开关默认关 |
| **B 层 · 两个独立窗** | 侧栏分叉出来的两个 Session | 官方 `session_search`（读）+ `parallel_message` / `session_send`（写）+ 共享 cwd / git / `hindsight` / `project-memory` | **没开**（这批要开的） |
| **C 层 · 两个隔离检出** | 两个窗各在自己的 `git worktree` 里改代码 | `create_worktree`（官方，已装未启用） | **没开**，且建出来缺 `node_modules`（P521） |

**关键判断：我们这种批次制开发，B 层够用，C 层暂时不用碰。** 理由在 `docs/两窗口怎么分工-2026-11-27.md` 里量过了 —— 每批只改 10–17 个文件，但 `panels.ts` 每批必中；两个**写**窗撞车成本高于并行省下的 17 分钟。B 层让第二个窗**只读 + 跑门**，不碰写，才划得来。

### 7.2 排班（一批 96 分钟，副窗吃 17 分钟纯等待）

沿用实测时间线，只在交接点加一次 `parallel_message`：

| 分钟 | 主窗（写） | 副窗（读 / 验） | 交接动作 |
|---|---|---|---|
| 0–12 | 读场、定判据 | 读场：把本批要碰的 3 个文件的现状抄成表格 | — |
| 12–40 | 写代码 | 待命（`parallel_hold` 挂着，别空转烧 token） | — |
| **40** | 全量 `vitest` 开始 | 收到 `parallel_message("我要跑 68s 全量测，之后要你跑五门")` | 主窗发话 |

### 7.3 Team 模式怎么开（会话内部并行，与上面无关但同一件事的另一半）

1. 打开**模型与推理等级菜单**（输入框左侧那个），勾上「**使用智能体团队**」；
2. 想让它**默认开**：profile 的 `cordis.patch.yml` 里给 `agent-team` 加 `config: { defaultEnabled: true }`；
3. 开了之后：主 agent 能用 `team_task_create` 建任务、`team_task_update` 认领（带 CAS 修订号）、`send_message` 给某个成员、`wait_agent` 等；

### 7.4 三条硬约束（插件解决不了，只能安排）

1. **内存**：15.4 GB 总，常态空闲 **1.6–1.7 GB**，18 个 node 已占 1.4 GB。实测「替身 + 全量 vitest 同跑」把 vitest 拖慢 26%、空闲内存掉到 977 MB。⇒ **同时最多 1 个吃 CPU 的长任务 + 1 个短任务**。
2. **端口**：81 个探针里 4246 占 19 个，端口值散在 27 个上（P520 / P524）。副窗**必须换端口**（4247 起），且探针要用 `$env:PW_URL` 覆盖。
3. **`game/dist/` 是共享的**（P527）：主窗 `npm run -s build` 出的包会被副窗 preview 读到。⇒ 副窗跑门前**先问一句「现在这个 dist 是你刚建的吗」**，别验错包（批 BB′ 就吃过「旧 dist 造成两条假红」）。

## 八、这一轮新记的缺口

- **P528** `dsh-parallel-sessions` 的暂停登记只在**进程内存**：DSH 一重启，被 `parallel_hold` 挂住的会话就永远等不到自动恢复（`autoReleaseOnTurnEnd` 挂在 `turn/end` 上，进程没了就没这个事件）。**解法定**：开工收尾脚本里加一句「扫 handoff 目录，把 `状态: 已暂停` 的条目改成 `已恢复`」。**判据**：重启后 `parallel_sessions` 不再返回任何 `holding` 关系。
- **P529** 两个候选插件都**不列对方的 session id 给人看**：`parallel_sessions` 给的是 `cs_` 派生别名（插件内部算的），`session_send` 要的是原始 `session-…`；两者对不上时只能靠报错试。**解法定**：在 `.junshi/handoff/README.md` 里落一张「窗名 → session id → cs_ 别名」对照表并由主窗维护。**判据**：新窗第一次发话不用试错。
- **P530** `dsh-experimental-session-search` 的跨会话访问要求 **cwd 字符串严格相等**：主窗在仓库根、副窗若按 §7.4 切到 `game/` 起 preview 之后再搜，就会搜不到（cwd 已经不是同一个串）。**解法定**：起 preview 用 `workdir` 参数而不是 `cd`，别改会话 cwd。**判据**：两窗 `session_search` 能看到对方本会话内的记录。
