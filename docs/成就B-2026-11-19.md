# 成就（B 批）：30 条挂在真实动作上，AI 只补一句街坊话

**一句话**：开罗的 39 条成就是「累计到 N」——它有 115 家对手店、111 项街区投资、38 组摆件组合去堆数字；本作没有那么多数字可堆，所以 30 条成就一律挂在**玩家真做得出来的动作**上（挂哪款粉、修哪条街、让谁服气），前五条保证头两天拿到。

**第二句**：成就的判定、目标、奖励全在本地（`data/trophies.ts` + `sim/trophies.ts`），AI 只负责在达成时补一句街坊会说的话，且那句话**不许出现任何数字**（阿拉伯数字与中文数量词都拦）。

**第三句**：这一批没动任何数值曲线——客流、产能、价格、段位门槛一个都没改；替身两季的营收变化只来自成就奖金改变了它的支出时点（−4.5%，已记录为 P76）。

---

## 一、为什么不照抄开罗

| | 开罗（`English.lproj__trophy.txt`） | 本作 |
|---|---|---|
| 条数 | 39 | 30 |
| 结构 | **全部**是 `Get <0> customers!` 这类累计阈值（100/1000/3000/6000/…/3,000,000、钱 100k/500k/3M） | 六组，只有 3 条是纯累计（来客 100、碗 1000、人情 100） |
| 为什么这么设计 | 它有 115 家对手店 + 111 项街区投资 + 38 组组合 + 25 个街区，数字本身就能堆满一局 | 我们的中期出口是 8 家同行 / 12 件街面 / 12 件家当 / 4 家分店，**数字没那么多** |
| 直接照抄的后果 | — | 玩家会在第 3 天看到「累计 10000 位客人」，而他一天只做得动 70 碗 |

试玩报告里两个真人（巷内局 68 碗走 78、阿兰局 34 碗走 99）**都在第 2 天打烊后停下**。所以这批的第一目标不是「给老玩家更多收集」，是**让人在头两天就看见一件被承认的事**。

三条设计纪律写在 `game/src/data/trophies.ts` 文件头：

1. **只挂本作真的有的数**——`goal` 直接读现有 state 字段，不新增统计口径（唯一新增的是 `tally.recipesSold`，因为「转手」原本没有计数）；
2. **前五条必须头两天拿到**——第一碗、一百位街坊、第二块牌子、第一件家当、第一件街面，这五样在第 2 天全部可达（`probe:start` 的数据：D1 51 碗、D2 累计约 95 碗、第一段在 D2）；
3. **奖励给人情多于给钱**——30 条里只有 9 条给现金，其余给人情或什么也不给。给钱会直接推高现金流，让替身的成长曲线失真（P76 就是这条的代价，见第五节）。

## 三、三个接线点

```ts
// game/src/sim/state.ts —— 日结时判一次（换日会清掉今天峰值，所以必须在 day += 1 之前）
tally.bestDayRevenue = Math.max(tally.bestDayRevenue, rec.revenue);
checkTrophies(state);
state.day += 1;
```

```ts
// game/src/sim/trophies.ts —— 奖励直接落账，不走 addFavor（会被每日 40 点上限卡住）
if (hit.favor) { state.favor += hit.favor; state.favorTotal += hit.favor; }
if (hit.cash) state.cash += hit.cash;
state.trophies.push(def.id);
state.pendingTrophies.push(def.id); // 播报队列，不落盘
```

```ts
// game/src/main.ts —— tickFeedback 一次弹一条，接着问 AI 要一句街坊话
const def = TROPHY_BY_ID.get(s.pendingTrophies.shift()!);
hud.showToast(`成就 · ${def.name}（人情 +${favor} · ¥${cash}）：${def.hint}`, "like");
void fetchLine({ kind: "trophy_voice", key: def.id, context: trophyVoiceContext(def), month, day })
  .then((line) => line && hud.showToast(`街坊说：「${line}」`, "info"));
```

`pendingTrophies` 故意**不落盘**（`save.ts` 的 v23→v24 迁移把它清成 `[]`）：读档时重播一堆积压的成就 toast，比不播更糟。

## 四、AI 只补一句街坊话

第六个落点 `trophy_voice`，四铁律一条不少：

| 铁律 | 这里怎么落的 |
|---|---|
| 只出文字不出数字 | `server/app.py` 的 `sanitize_voice()`：`DIGIT` + 中文数量词 `CN_QUANTITY`（`三十五位`/`两百块`/`两家`）+ 机制词 `MECH_WORD` 三层过滤，任一层命中整句作废 |
| 每句有本地备选 | `game/src/ai/lines.ts` 的 `LOCAL.trophy_voice` 6 句（「这条街的人都看在眼里。」「做买卖做到这份上，不容易。」等），`getLine()` 先给本地、异步换远端 |
| 缓存键含日期 | `line:trophy_voice:<成就 id>:<月>:<日>` |
| 不碰机制名与数值 | `trophyVoiceContext(def)` 只返回 `{成就: 名字, 时候: 组名}`，一个数字都没有 |

服务端场景指令（`LINE_SCENES["trophy_voice"]`）：「街坊（常来的客人、隔壁摊主、巷口阿婆都行）看见老板做到一件不容易的事，放下碗顺口说一句。像随口夸的，不是颁奖词。」

真机探针的判定步骤：清档 → 建店 → 收引导 → 图鉴页断言（6 组 / 30 卡 / 0 点亮 / 「0 / 30 枚」）→ 注入 `bowls=3, totalCustomers=130, gradeLevel=1, gear=["plastic_stool"], streets=["lane_lamp"]` → 手动跑一次判定 + 反馈消费 → 读到 5 条同时点亮、人情 0→18、toast 弹出 → 回图鉴页确认卡片从虚线变实线并带 ★。

**探针的坑**：一开始没读到 toast，因为 `tickFeedback()` 只在分钟推进时跑（prep 阶段时间是停的），而成就本来就在日结后才弹。为此在 `window.__laoyou` 加了两个验收出口 `trophies()` / `feedback()`，注释写明「正常时机仍是 endDay / 下一分钟」。

## 六、与开罗逐项对照

| 项 | 开罗 | 本作 | 判断 |
|---|---|---|---|
| 条数 | 39 | 30 | 少 9 条，但没有一条是「凑数」 |
| 纯累计型 | 全部 | 3 / 30 | 有意为之：数字不够堆 |
| 奖励 | 道具 + 数量 | 人情为主、现金为辅 | 人情是本作第二货币，能立刻用掉 |
| 展示 | 未展开（`trophy.txt` 只有阈值表） | 图鉴页第 6 段，六组全列、未达成也显示名字与进度 | 这批的目的就是「让人看见还有什么」 |
| AI | 无 | 达成时一句街坊话 | 六个落点里最轻的一个：只夸，不给信息 |

## 七、缺口

- **P76**：成就奖金改变了替身的支出时点，月均比 P70 低 4.5%（¥69,992→¥66,828 / ¥48,780→¥46,694）。要不要把现金奖励改成「下月抵扣」或纯人情，等 bot 这轮数据再定。
- **P77**：图鉴页没有排序与筛选，30 条一屏滚不到底；且「下一条最近」只显示一条。
- **P78**：成就没有分享/导出，试玩 bot 看不到「玩家拿了几枚」以外的信息。
- **P79**：`close_one`（看着一家同行关门）是**被动**成就，玩家可能什么都没做就拿到，语义上更像「见证」而不是「成就」。
