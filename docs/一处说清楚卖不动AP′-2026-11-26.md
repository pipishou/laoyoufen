# 一处说清楚「卖不动」（批 AP′，解 P448）—— 2026-11-26

## 一、要解决的问题

批 AO′ 在店铺页的设备段加了一句：

> 今天这三段再添也卖不动 —— 灶、座位、备料都还有富余，卡在街上进来的人就这么多。想多卖，得让街上更热闹：修街面、比赛赢过同行、把口碑养起来、换个人多的区。

这句话只出现在**一个地方**。同一天的打烊单底下还写着「先把「猛火灶」加上（¥1,200）」。

玩家当然看打烊单 —— 那是每天必看的一屏。于是他照买，第二天一碗都没多。这就是 P448：**同一件事，两处说反话**。

账本行 151 收尾时把这句写进了缺口表；这一批就是把它收干净。

## 二、先把「谁在说话」理清楚

原来有四处会各自亮起来（批 AK′ 已经把这份裁定收到 `game/src/sim/align.ts`）：

| 位置 | 谁在说话 | 这一批之后 |
| --- | --- | --- |
| 打烊单「明天：…」主句 | `nextHook` | 新增 `capacity:demand` 这一档，主句写「街上就这么多人 —— 店里再添什么也卖不动」 |
| 打烊单「为什么」区 | 五条 span | 新增 `[data-demand-line]`，前缀「卖不动 · 」 |
| 店铺页设备段 | `capacityGain().demandBlocked` | 不动（AO′ 就是这一处） |
| 店铺页「今天先不动」 | `alignMarks().demoted` | 新增一条：「店里再添也卖不动（街上就这么多人），今天先不添」 |
| 四处红标 | `alignMarks()` | `FocusSec` 加 `"demand"`；这一档**四处都不红**，抬头写「街上的人」 |

第三列与第一列现在是同一句话的两种说法，不再是两套判断。

## 三、改了什么

### 1. `game/src/sim/hook.ts` —— 新的一档钩子

在产能段（`nextHook` 的 ⓪）末尾加一个分支：

```ts
if (capacityGain(state).demandBlocked) {
  return {
    text: "街上就这么多人 —— 店里再添什么也卖不动",
    why: sample.lost > 0 ? `${dayWord}走了 ${sample.lost} 位` : "",
    kind: "capacity",
    key: "capacity:demand",
    urgency: "high",
  };
}
```

为什么排在「推某一件」那段**后面**：`tight === "demand"` 就意味着灶、座位、备料三道的日碗量都高过来客量，抬哪一道都抬不动（`capacityGain` 增益必然是 0），`capacityPick` 到这一步一定已经返回 null。所以顺序上等价，但这样写能保证「有真能接客的件」时永远先推那一件。

这一句**不带价钱、不给 `ref`** —— 不劝人买任何东西，只把闸指出来。

顺手把 `const dayWord = …` 从 `if (pick)` 块内上提到分支外侧（原来两处各声明一次）。

`VOICE_HINT` 加 `"capacity:demand": "街上的人"`，AI 副行才知道该往哪个方向说。

### 2. `game/src/sim/today.ts` —— 副句把人往街上指

`todayLine` 里加一段（在 `price` 之前）：

```ts
if (plan.key === "capacity:demand") {
  return {
    main: plan.text,
    detail: `店里再抬也卖不出去 · 想多卖，得让街上更热闹：修街面、比赛赢过同行、把口碑养起来、换个人多的区`,
    key: plan.key,
    blocked: tightWords(state),
  };
}
```

旧版走到这里会落到最后那句兜底（`detail: ""`），店铺页的红标就会指着扩建说「今天动这个」。

### 3. `game/src/sim/align.ts` —— 给「街上的人」自己一档

- `FocusSec` 加 `"demand"`（注释写明「不是店里任何一段，四处都不该红」）；
- `SEC_WORD.demand = "街上的人"`；
- `todayFocus` 里 `plan.key === "capacity:demand"` → `sec: "demand"`，**排在落到 `expand` 的兜底之前**；
- `alignMarks` 的 `demoted` 多一条：来客封顶时（且今天说的不是这一档）补一句「店里再添也卖不动（街上就这么多人），今天先不添」—— 这是第三处「同一件事」。
- import 加 `capacityGain, tightWords`。

### 4. `game/src/ai/lines.ts` —— 副行也换池

`HOOK_VOICE` 加 `"capacity:demand"` 8 句（本地兜底，不发请求）：

> 店里头的账都够用了，缺的是街上走进来的人。
> 灶不慢、凳子也不缺，是这条街眼下就这么点人。
> 锅再大火大，也得有人推门进来。
> 想多卖，先把门口这条路走热。
> 名声传出去了，人才会拐进这条巷子。
> 同行那边赢一场，比添两口锅管用。
> 这地方的人流就这么些，换个人多的街口另说。
> 店是好店，难在街上没人往这边拐。

这一档**不许再劝人添设备**（那正是 P448 要修的两套说法），只把人往街上指：街面、比赛赢过同行、口碑、换区。一个数字都不出现（服务端会丢带数量词的整句）。

### 5. `game/src/ui/hud.ts` + `hud.css` —— 打烊单那一行

## 六、这一批没动什么

- **没有动任何数值**：`capacityOf` / `capacityGain` / `demandPerDay` / `EAT_MINUTES` / `SEAT_IDLE` 一格没改；替身四种子逐位不变就是这个的凭据。
- **没有改 `capacityPick` 的挑选逻辑**（那是批 AM′），只加了「挑不出东西的时候说什么」。
- **没有新增服务端 AI 场景**：`hook_voice` 早就有一个场景，`capacity:demand` 只是本地池多一档；`LINE_BUDGET` 仍是 360（池是本地兜底，不进预算）。
- **没碰 `SaveVersion`**：仍是 37。

## 七、新缺口

- **P451** 打烊单那一行与店铺页那句仍是**两段硬编码的字符串**，只是意思相同；真要「一句话只有一个出处」，得让它从 `todayLine().detail` 取（与 P344 同型：同一个事实两处维护）。
- **P452** `capacity:demand` 的 `urgency` 是 `high`（会标红），但它**不是一件能马上做的事** —— 红标通常意味着「点这个按钮就有用」。街面 / 比赛 / 口碑三处都不在同一屏。
- **P453** 钩子的 `why` 仍是「昨天走了 N 位」，没说「走掉的人里多少是因为没座位 / 价钱」；来客封顶那天，这个数字对玩家没有指导意义（与 P435 同型）。
- **P454** `VOICE_HINT` 的 `capacity:demand` 只给了「街上的人」三个字，服务端生成时拿不到「这家店在哪个区 / 街上有几家同行」，说出来的话泛得很。
