# A8 顾客等级 · 2026-11-21

## 一句话

开罗 `customer.txt` 90 类带 level，我们没有 90 类人，但可以让**同一批人**分成三种关系 —— 路过的、街坊、识食的。等级不是「更强的敌人」，是「更清楚的钱和更清楚的口碑」。

## 为什么不照抄 90 类

开罗的 90 类顾客是「素材」（每个都配一套脸、一段台词、一条喜好），我们 24 类已经够用；真正缺的是**同一类人里的层次**。一位上班族可以是路过的（赶时间、只肯出 ¥8），也可以是识食的（肯出 ¥13，但汤薄了当场皱眉）。这比再加 66 张脸便宜，也比加 66 张脸更影响决策。

三条设计纪律：

1. **三档只走四个出口**：钱包（选款容忍）、耐心、口碑权重、挑剔扣分。不加新机制。
2. **常客一律街坊**：老客不是抽中的，是他自己回来的。
3. **挑剔只减满意度，不减口碑**：口碑那一层已经被权重管住了，两层一起扣等于双罚。

## 三档

| id | 名字 | 小字 | 钱包 | 耐心 | 口碑权重 | 挑剔 |
| --- | --- | --- | --- | --- | --- | --- |
| `passer` | 路过的 | 路过 | ×0.85 | ×0.85 | ×0.7 | — |
| `neighbor` | 街坊 | 街坊 | ×1.0 | ×1.0 | ×1.0 | — |
| `picky` | 识食的 | 识食 | ×1.35 | ×1.2 | ×1.5 | 分 < 68 时扣 0.28×差距，上限 18 |

抽档概率（都夹住两头）：

```ts
export function pickyChanceOf(state: GameState): number {
  return clamp(0.04 + state.reputation * 0.055 + state.gradeLevel * 0.008, 0.02, 0.34);
}
export function neighborChanceOf(state: GameState): number {
  return clamp(0.32 + state.reputation * 0.05 + state.gradeLevel * 0.006, 0.2, 0.6);
}
```

口碑 4.2、段 4 时：识食约 30%、街坊约 55%、路过约 15% —— 名声越好，越多人是**专门来吃的**，他们挑得也越狠。这是这一层的意思：爬到后面不是更轻松，是标准更高。

## AI 落点：第 11 个

`guest_voice` 与别的落点不同 —— 它出现在**一次具体的失败**之后。所以 prompt 里写明「不是差评，也不是骂人；只就这一碗说事，不要提价格、段位、菜单这些外面的话」。六句本地备选按「汤薄 / 酸笋少 / 粉过气 / 火候差 / 不如上次 / 我撑你但你自己试试」铺开，都不带数量。

## 缺口

- **P130** 三档只影响「钱、耐心、口碑、挑剔」，不影响**他点什么**（识食的应该更爱点贵料）。
- **P131** 场上只是色条与小字，没有「他常来」的脸 —— 与 P122（方子没画面）同形。
- **P132** 没有专门的探针断言队列行的 `t-*` 类（逻辑有测试，DOM 只有 eye_gate 的色数）。
