## 1 · 你问的第 1 件事：Shift+E 为什么存在，现在还需不需要

`Shift+E` 是**上一轮的补丁，不是设计**。它存在的原因很具体：

| 阶段 | 当时的处境 | 结果 |
|---|---|---|
| 埋点 v1 | 只有浏览器 localStorage，且只在「月结」落盘 | 刷新/关页即归零，`Shift+E` 是唯一把数据带出来的手段 |
| 埋点 v2 | 日聚合 + 每 5 次采样落盘 | 数据不丢了，但**还在玩家机器里**，得手动导出 |
| 埋点 v3（本轮） | 带匿名设备号 + 自动上传 + 失败补传 | **不需要按了**；`Shift+E` 降级为「离线/救援用」，`Shift+U` 只是「立刻催一次」 |

### 自动运转的端到端证据（不是推断）

| 环节 | 实测 |
|---|---|
| 触发 | 同一份构建，只把 API 地址指向线上；脚本跑 130 秒、16 倍速，**没有按任何键** |
| 请求 | `POST http://8.134.86.249/laoyou-api/playtest` → **200**，console error **0** |
| 服务端 | `GET /report` 出现新设备 `d9b29c69cdd6aea9f90ec93e`，`uploads=1`，`pending=null`（没有积压） |
| 频率 | 修节流前 95 秒打了 **16 个包**（16 倍速下「推进 15 分钟」每秒都成立）→ 修后同一条件 **1 个包/95 秒** |
| 日报 | `GET /digest` 返回 markdown；`laoyoufen-digest.timer` 已 active，next `2026-11-15 03:15 CST` |

节流规则（`game/src/sim/telemetry.ts`）：时间闸**无条件生效**（≥120 秒，`force` 除外）＋增量闸（距上次上传又推进 ≥15 游戏分钟 或 跨天）。少于此不传，避免把带宽和统计都打烂。

## 2 · 数据链路与每一步的兜底

```
浏览器（每分钟采样→日聚合）
  → localStorage laoyou.telemetry.v2   （每 5 采样/跨天/卸载落盘）
  → POST /laoyou-api/playtest          （失败写 laoyou.upload.pending，联网/下次推进补传）
  → nginx 反代 → 127.0.0.1:8767 systemd laoyoufen-api
  → /var/lib/laoyoufen/playtest/<id>.json + index.jsonl
  → GET /report（按 device 取最新快照聚合）｜GET /digest（markdown）
  → laoyoufen-digest.timer 03:10 → /var/lib/laoyoufen/reports/YYYY-MM-DD.md
  → 我拉回来：tools/reviewer/playtest_ingest.py → docs/试玩记录-<日期>.md
```

每一环的失败模式：localStorage 被清 → 换新设备号（数据不串）；断网 → pending 补传；服务端挂了 → 前端无感（上传是 fire-and-forget）；nginx 配错 → 401/413/404 有明确状态码（已验）。

**已知限制（不掩盖）**：本机沙箱拦浏览器**顶层导航**到公网 IP（`net::ERR_BLOCKED_BY_CLIENT`），所以「线上页面长什么样」是用「资产字节一致 + 同构建本地截图」确认的；而「自动上传能不能落到服务器」是端到端实测过的（§1 表）。两者不是同一件事，都做了。

## 6 · 上不上线：可以上，但别把「能玩」当「玩得下去」

- 能上线：L1–L12 里没有阻塞项；玩家玩、数据回、日报出，闭环成立。
- 但 B12（玩三小时后没决策）和 B8（钱没去处）是**留存杀手**，属于「上线后第一优先级」，不是上线前必修。
- B6/B9 是「玩深了有没有新东西」，可以放到第一个内容版本。

## 7 · 玩家视角须知（给你自己玩时对照）

1. 第一次进来：4 步引导，走完就没了；第 3 个月左右会觉得「没事可做」——这是 B12，不是错觉。
2. 看到 `¥8` 的学生仔走人，是价格信号；想留住他要么降价、要么把味道做上去（味道涨 → 他能接受的价格涨）。
3. 玩完不用做任何操作：跨天会自动传；想立刻确认，按 `Shift+U` 看提示；真要离线留档再按 `Shift+E`。
