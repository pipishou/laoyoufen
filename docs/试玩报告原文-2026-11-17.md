## 现代手机操作 vs 开罗开发年代（体验原则）

这是今晚做修复时必须遵守的**常驻设计原则**，尤其适用于空页签、引导、配方 / 售价控件，以及任何新补上的界面。它**不替代**上文的 P0 顺序（空页签 → 引导 ①②③ → 开场节奏 → 街边摊上手），也**不是**要求今晚把整款游戏重做成手机产品。

开罗式经营游戏诞生的年代，和现在大多数人的玩法已经不是同一回事：现在多数人在手机上玩。现网若只按桌面键鼠来修界面，手机屏上的适配和操作习惯会不过关，空页签和引导修好了也还得再做一遍。游戏应补上拖拽等直接操作，并把复杂操作减下来。

**请诚实对待证据范围：** 本轮两局现网实机都在**桌面浏览器**里完成，**没有做手机实机试玩**，下文不把未发生的触控测试写成已验证。但桌面上已经出现、且在手机上只会更糟的摩擦，可以作方向依据（均已见于试玩笔记 / 截图）：

- 售价、米粉等滑杆沉在底栏（配方 / 员工 / 店铺 / 时间）下面，几乎拖不到（阿兰日志；引导 ③ 确认价牌时同样被挡住）。
- 配方面板盖住引导卡片和浇头排（两局都复现，见 `07-recipe-panel-covers-guide.png`）。
- 信息密集的 HUD、底栏六个页签，再加上引导 ⑤ 大卡片挡在店中央（阿兰第 1 日白天，见 `runs/alan/13-day1-mid-tutorial-still-up.png`）。
- 关键规则写在悬停 `title` 里：音乐按钮「开罗风 BGM 与音效开关」、热卖槽「开罗 Ramen Frenzy…」、目标「开罗 trophy…」。手机无法悬停；热卖槽 title 在桌面上还可能被 Phaser 画布挡住。
- WASD 能移动厨师精灵，但不参与出餐。这是桌面习惯且帮不上忙，手机上也没有对应的触控走位需求。本轮不要为此加手工炒菜，界面也不要依赖 WASD。

**建议方向（只给方向，不写补丁，不部署现网）：**

- 布局和点击热区先按手机屏幕来考虑，再放到桌面，不要先做成桌面专用。
- 配方滑杆、浇头、售价等调节，优先做成拖拽或其他直接操作，少用“翻开大面板再找被挡住的控件”。
- 高级、复杂的面板默认收起或延后出现，一次不要把整页研究界面压在引导和店铺上。
- 不要依赖悬停，也不要依赖 WASD。需要让玩家知道的规则，应在点按或常驻文案里能读到。
- 引导进行中，同一时刻只突出一个主操作。

不要去仿写或克隆某款现代手游的界面；机制仍可对照开罗式经营节奏，但 **IP / 文案 / 美术不可复用**，也不要借「手机化」去补更像开罗的内容。现网改动须 Mo 另拍，今晚只做本地优化候选。

## 今晚修复顺序

下列优先级不变。执行这些修复（尤其是空页签、引导、配方 / 售价与任何新 UI）时，须按上一节原则做手机屏与触控友好的交互，不要先做成桌面专用再返工。

1. **P0 四个空页签：店铺 / 比赛 / 图鉴 / 账本**（I-05）  
   现网 DOM 里 `<div data-body="shop|contest|collection|ledger">` 为空。包内已有渲染函数与装饰 / 分店逻辑，但现网点不开。**要修空页签把已有系统挂上去，不要重做一套 S3 布置 / S6 分店。** HUD 仍写「比赛 5 个月后」，日标出现过「老友图鉴 23项 / 30项」，点进去是空白。员工页同一套面板是有正文的，说明通路本身通。

2. **P0 引导 ①②③**（两局都复现；I-02 / I-03 / I-04 / I-01）  
   - ①：一打开配方就跳步。文案让「往右拨」：阿兰拨完口味 68 B → 64 C；巷内局拨到 80 时实时评分 66 C，菜单卡仍写 68 B。配方面板盖住引导和浇头排。  
   - ②：文案写「最下一排」，酸笋 / 豆豉在第一行。巷内局只点酸笋就进入 ③。完成条件理应 `recipe.toppings.length >= 2`，但第一次加料 notify 可能提前跳步。  
   - ③：标题「先卖 ¥9」，代码 `done: e => e.price !== 9`，默认价已是 9。巷内局改成 ¥10 才过关；阿兰价已是 ¥9 不自动过，点了「下一步」才离开。完成条件应对准「当前售价为 ¥9」（已满足就过），不要逼玩家改离 9。

3. **P0 开场节奏**（I-16）  
   默认 ×4 时一天约 30 秒现实时间；引导 ⑤ 大卡片挡在店中央，直到卖够 20 碗。阿兰局约 10:48 才 toast「引导完成，接下来看你自己」。建议：引导未完成时默认 ×1，或让引导不挡店铺。

4. **P0 街边摊开局难度**（I-17，阿兰局新证据）  
   免费默认选项第 1 日 34 碗 / 99 人走 / 评价 1.2；第 2 日按提示降价到 ¥8、改 ×1 后评价掉到 0.0。先查产能 vs 客流（HUD 曾写客流 160/日，街边摊日上限 120、2 座）、引导与学生预算 ¥8 的冲突、评价为何在流失减少时仍掉光。不要一上来猜月目标 21,000 的调参。

5. **P1 账对不上**（I-08，附 I-13）  
   两局打烊营业额都对不上现金增量；打烊时顶栏「今日客流」归零。日报应拆开进账 / 成本 / 事件。注意：巷内局现金增量大于营业额，街边摊第 1 日则小于营业额，不要按单一方向假设根因。

6. **P1 事件金额符号**  
   见下方「截图核对」。两局选项均写 `¥+90`，选完现金均 +90。工程师笔记里的「标签 ¥-90、入账 +90」与 I-10 走客文案写反，均为误读，**不要当缺陷修**。

7. **P1 流失反馈**（I-18，附 I-12）  
   看价离开有 toast；队满 / 耐心离开白天基本没有，只在打烊一句「嫌贵或者等太久」。排队可显示 9/8、12/8（超上限）。
