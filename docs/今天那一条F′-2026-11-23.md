## 一、这一轮解决什么

试玩报告第 5 条把问题说得很直白：同一屏上「← 现在最缺」、橙色「最慢：炒锅 2.2 分」、「可评定「摆摊仔」/ 交费评定」三处一起抢眼，玩家读完不知道该动哪一件。第 4 条又是另一头：副行「人多起来是好事，接不住就成了坏事。」被三家、四天一字不差地连用；「为什么 · 灶和座总有一个先撑不住」四天三局同一句模板，而且和日注重复。

两条合起来是一个病：**话是有的，但话不指向任何具体的东西**。

开罗怎么处理：

- `balloon.txt` 102 条是**按处境分的短口气池**（`Need money.` / `Too much...` / `Nice choice.` / `I'm full.` / `No effect...` / `Success!` / `Too busy...` / `Time to go.`）—— 一句一处境，不是一句模板套到底。
- `help.txt` 的 `Shop Stats` 写得很清楚：左侧菜单进去，才是 Staff / Equipment / Deco 三段 —— **同一时刻只指一件事**。
- `Construction (Other)` 专门说明「线砖、盆栽这类不被客人直接用的东西，是给邻近设施加成的」—— 开罗没有「高亮红标」，它靠**说明这件东西在哪一段**来指路。

我们照这三条改：店铺页顶部只留一条「今天」；主句沿用钩子（本地算），副句给出**回本天数 + 在第几行**，并给那一行加 `→` 高亮；其余的读数（最慢、卡在哪）降级成小字；副行的池子扩到一处境八句，键按天轮换。

## 五、新缺口

- **P273** 副句里的「一天多卖约 N 碗」用的是 `capacityGain` 的估算，不是实测；读起来像承诺，实际上是几何平均。
- **P274** 「在「家当」第 K 行」的行号按 `data/gear.ts` 的顺序算，玩家改了排序（如果以后允许）就全错。
- **P275** `paybackDays` 用今天的毛利除，价格一改回本天数就变；界面上没有「这是按今天算的」这一层。
- **P276** 预算 260 是「键空间 ≈ 170 + 落点 19 + 余量」估的，长局（36 月以上）仍可能顶到。
- **P277** `pointer_voice` 的上下文只有 `{事, 在}` 两个名词，模型不知道店里的实际瓶颈，只能说人味不能说「为什么卡这里」。
