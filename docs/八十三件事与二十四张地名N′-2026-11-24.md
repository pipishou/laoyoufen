# 八十三件事、二十四张熟面孔、十二页手册（批 N′，2026-11-24）

> 上一批（M′）把世界加厚了：行情十六个、大会二十四场、同行十六家。
> 这一批做的是**「里面有什么」**——街坊会碰上什么事、客人张嘴说什么、
> 地图上写着哪些真地名、玩家想知道「为什么」时去哪里翻。

## 一、开罗这边是什么样（照 `TheRamenSensei` 的取证表）

| 开罗 | 体量 | 本作原状 | 这一批做完 |
| --- | --- | --- | --- |
| `talk.txt`（顾客台词表） | 244 行，按场面分组 | 六种场面各 4 句，共 24 句 | **六种场面各 10 句，共 60 句** |
| `fixevent.txt`（固定事件） | 500 行 | 32 条 | **83 条** |
| `mapchip.txt`（地图格子上写什么） | 218 行 | 12 个区，格子上只有区名 | **24 张熟面孔地名，每区 2 处** |
| `help.txt` + `topics.txt`（手册与条目） | 57 节 + 9 条 | 无（只有阿婆的笔记本 12 条） | **手册 12 页，四章** |

四点说明，写在前面免得以后有人照抄数字：

1. **不追行数**。开罗 `fixevent` 500 行是它把同一件事的十几种写法都算一行；
   我们的 83 条是 83 件**不同的事**，每条都带两条以上的选择与一个具体后果。
2. **地图不是加区**。原计划「地图 24 张」如果照字面加 12 个新行政区，会连带动
   `DistrictId` 联合类型、GDP 客流、转让费、同行归属、存档迁移一整圈 ——
   而客流这条线已经叠了五层乘数（见 P301），再加区只会让乘数更不可读。
   所以改成**在现有 12 个区上各挂两处真地名**：格子还是那 12 格，但玩家知道自己站在哪。
3. **手册不报数**。十二页正文一个阿拉伯数字都没有，理由是它讲的是「为什么」，
   而具体数字在打烊单、钩子、店铺页顶部那一条里已经给过了。手册要是也报数，
   就成了第二份数据面板。
4. **地名带出处**。二十四条每一处都有 `source{label,url}`，来自本地媒体与政府网站，
   写进 `game/src/data/places.ts`。

## 二、事件：32 → 83

新文件 `game/src/data/events-more.ts` 装 51 条，`game/src/data/events.ts` 末尾合并：

```ts
export const EVENTS: readonly GameEventDef[] = [...EVENTS_BASE, ...EVENTS_MORE];
```

`EVENTS_BY_ID` / 抽签逻辑 / 存档结构一概没动 —— 事件是**无状态内容表**。

### 五十一条都写的是什么

按处境分七组，全部是南宁街面上真会发生的事：

- **清早与备料**：凌晨批粉、送粉师傅迟到、豆豉断货、青菜涨、猪肉涨、酸柠檬
- **门口与街面**：城管、共享单车堵门、修路、楼上邻居、小学门口、庙会、垃圾清运
- **人情往来**：老客带人、店员家事、喜事、满月酒、旧照片、偷师传言、挖人
- **合作与单子**：团购券、团餐、公司订餐、外卖平台、门口直播、糖水搭售、学生兼职
- **检查与合规**：卫生检查、消防、收银机、扫码、WiFi、桶装水、纸碗
- **天气与季节**：台风尾、回南天、三伏、清明、端午、毕业季、军训、空调
- **比赛与名声**：组委会来电、同行上门、外地人问路

出口只用三种 —— `cash` / `reputation` / `trend`（`sourBamboo` / `douchi` / `porkOffal` / `broth`）。
原因：这一批是**内容**，不是新机制；加一个出口就得同时在 `effects` 消费端、面板、
打烊单、AI 上下文里接一遍。

### 一条真实改动：免费选项的纪律改了写法

原来写的是「每条至少有一个**不花钱**的选项」。写到最后发现有九条做不到 ——
停水、气价、青菜涨、垃圾清运这类**环境压迫型**事件，本来就没有「不花钱」这条路，
硬塞一个「不管它」的选项会让事件变成白给。

改成：

> **每条都留一条「花钱买口碑」的路；绝不出现「怎么选都掉口碑」。**

`game/src/data/events-more.test.ts` 按这条锁：

```ts
const keepFace = e.choices.some(
  (c) => !c.effects.some((f) => f.kind === "reputation" && f.amount < 0),
);
expect(keepFace).toBe(true);
```

## 八、新缺口

- **P321 内容开始收租**：事件从 32 条涨到 83 条，同样的 36 个月里「路过的事」多了六成，
  花在这些事上的钱也多了六成 → 替身营收 −5.0%、现金 −22.5%。要么给事件加一个
  「今天已经碰过事，后面降权」，要么把环境压迫型事件的默认选项挪到不花钱那条。
- **P322 地名只写名字**：二十四张熟面孔目前只有名字和一句说明，没有「这一片的人爱吃什么」
  这种能落到数字上的差异（物产已经有 `data/local.ts` 三条，地名这条线刻意空着）。
- **P323 手册与数值两张皮**：十二页里的 `where` 是手写的，改 `sim/` 或 `data/` 的人
  不会被迫回来同步 → 和 P244（解读层台词跟着数值口径走）是同一类病。
- **P324 长对白仍是「六种场面」**：60 句按场面分，不按客型分。开罗的 `talk.txt` 是按
  「谁在说」+「什么处境」两维分的，我们少一维 —— 同一个场面里学生和出租车司机说的话一样。
- **P325 事件与对白不共享上下文**：事件里刚「送粉师傅迟到」，同一个客人的对白不会提；
  反过来也一样。要连起来得给 `CustomerFlow` 加一条「今天街上发生了什么」的记忆。
