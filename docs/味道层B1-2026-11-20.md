# 味道层 B1：六条南宁真有人这么吃的组合

> 2026-11-20 · 老友粉模拟器 · B1（对应开罗 `soupaffinity.txt` 28 行 + `topping_combo.txt` 38 行）

## 一、三句话

1. **没有照抄开罗的 28 行亲和矩阵，改成 6 条成型吃法**，每条都绑定「什么时候卖、给谁吃」，因为老友粉的味不是任意配料两两相加的化学反应，是几套被南宁人吃了几十年的固定搭配。
2. **每条都有两条以上真实出处**（新闻、菜谱、探店），出处随卡一起进 `title`，图上点得到；没有出处的搭配一律不做 —— 紫苏、猪心猪肚这类「好像该有」的东西全砍了。
3. **加成只落在已有乘数上**（汤底分、魅力、满意度、耐心、料钱、出碗），不进 `total`，所以替身 36 个月两季数字与上一批逐位一致 —— 这层只对「玩家主动配料」生效。

## 二、为什么不照抄矩阵

| | 开罗 | 本作 |
|---|---|---|
| 表 | `soupaffinity.txt` 28 行（位掩码 + 加成，含 −1 惩罚） | 无 |
| 表 | `topping_combo.txt` 38 行（任意两件配对矩阵） | 无 |
| 做法 | 6 条 `FLAVORS`，每条 2–3 件 + 可选粉型 + 场景 | 采用 |

否决理由写进了 `game/src/data/flavor.ts` 的文件头：

- 开罗一局几十分钟、配料二十几件，玩家有时间把 38 对试一遍；我们一局 120 游戏分钟、一天 2 分钟真实时间，**试错成本比开罗高一个数量级，矩阵在玩家眼里等于噪声**。
- 老友粉的真实吃法是「几套成型搭配」（老友三味、番茄底、猪杂三样、干捞肉末、砂锅猪杂），不是「酸笋 + 任何东西都有化学反应」。做成矩阵等于把本土化做成了占位符。
- 6 条上限还有一个副作用是好的：每条都能在面板上写清「还差哪一味」，玩家看一眼就知道下一步试什么。

**被 6 条上限挤掉、但证据留在台账里的**：

- 柠檬辣椒酱（南宁夜宵摊常见）—— 有出处，但和「老友三味」的辣重复，先让位。
- 「三大脆」（猪心 / 猪肚 / 猪粉肠）—— 我们只有粉肠，缺两件原料，**不编**。
- 紫苏 —— 广西其他地方粉里常见，老友粉缺出处，**不用**。

## 四、三条纪律（写在 `game/src/data/flavor.ts` 文件头）

1. **只吃已有浇头与粉型**：`toppings` 里出现的每件都必须是 `TOPPINGS` 里已有的 id，`noodle` 只认 `NOODLES` 里的粉型。不新增可买件，避免为了凑组合去造一个没有出处的配料。
2. **加成只落已有乘数**：`soup` / `charm` 进 `scoreRecipe` 的分项分，`sat` / `patiencePct` / `costPct` / `servePct` 进 `sim/customer.ts` 已有的四条链。`total` 不动 —— 它是替身回归锁，动了就得重跑三年基线。
3. **总量封顶**：`FLAVOR_CAP = { soup: 5, charm: 6, sat: 4, patiencePct: 0.12, costPct: 0.06, servePct: 0.08 }`，逐项 `Math.min`。六条同时成立也涨不出格。

## 五、四个接线点

| 位置 | 改了什么 |
|---|---|
| `game/src/sim/score.ts` | `scoreRecipe` 里 `soup` 加 `flavor.soup`、`charm` 加 `flavor.charm`，各 `Math.min(100, …)` |
| `game/src/sim/customer.ts` 满意度 | `satisfactionOf` 的 bonus 链加 `flavorSatBonus(...)` |
| `game/src/sim/customer.ts` 成本 / 出碗 / 耐心 | `gearCostFactor(state) * flavorCostFactor(...)`；`gearServeFactor(state) * flavorServeFactor(...)`；`patienceScale` 乘 `flavorPatienceMult(...)` |
| `game/src/sim/customer.ts` 结算 | `settle()` 里 `flavorHits(...)` → `unlock(state, "flavors", def.id)` → `state.flow.lastFlavor = def.id`，由 `main.ts` 的 `tickFeedback()` 消费成 toast + AI 一句 |

## 六、AI 第 8 落点：`flavor_voice`

- 本地池 6 句（`game/src/ai/lines.ts` 的 `LOCAL.flavor_voice`），例：「这个味道对了，就是这个味道。」「我阿婆以前也是这么煮的。」「天冷的时候来这一口，整个人都活过来。」
- 服务端场景（`server/app.py` 的 `LINE_SCENES`）：「客人吃到一口熟悉的老味道，放下筷子跟老板说了一句。像街坊随口讲的，不是评分，也不要夸过头。」
- 红线照旧：`sanitize_voice` 拦阿拉伯数字、中文数量词、机制词；**「一碗」也会被 `CN_QUANTITY` 拦**，本地池已经改成「这一口」。
- 触发时机：只有**第一次**凑成某条（图鉴 `unlock` 返回真）才弹，重复做同一碗不再播。

## 八、与开罗逐项对照

| 开罗 | 本作 | 判断 |
|---|---|---|
| `soupaffinity.txt` 28 行（材料对汤的亲和，含惩罚） | 6 条成型吃法，无惩罚 | 开罗的惩罚是为了让玩家背表；我们的玩家没时间背表，走「试一次就记图鉴」 |
| `topping_combo.txt` 38 行（任意配对） | 不做矩阵 | 理由见第二节 |
| `custom` 4 类 × 5 级（客人分级偏好） | 6 条各自绑场景（早市 / 晚市 / 夏 / 冬 / 热天） | 等效，但用「场景」而不是「客人等级」表达，因为我们的顾客只有 24 类没有等级（P95） |
| `eat_comment` 4×9 档（吃后评论） | AI `flavor_voice` 一句 + `line` 固定句 | 我们只用一句，因为 toast 只够一句 |

## 九、缺口

- **P100** 六条上限挤掉了有出处但暂缓的搭配（柠檬辣椒酱 / 三大脆缺原料 / 紫苏无老友粉出处），台账留在 `docs/味道层B1-2026-11-20.md` 第三节，将来要扩先看这里。
- **P101** 图鉴只记「做过一碗」，面板上凑齐但不做不会点亮 —— 这是有意的（怕玩家在面板上白嫖成就感），但要在帮助里说一句。
- **P102** 味道加成不进 `total`，若将来要动 `total` 必须重跑替身三年基线（它是回归锁）。
- **P103** 季节绑定让 4–5 月、10 月出现空窗：那两个月只有 1–4 条可用，`dry_mince` 与 `claypot_offal` 都不成立。
