# 汤底三底与两处调平（批 Z′）· 2026-11-25

这一批做三件事：给「这一碗」加一层**打底**的选择（Z′），给十二幕里那五件提前来的事加一道
**余钱闸**（P364），给第二圈八条行情里偏重的负值**收一收**（P316）。三件事都只动已有出口，
不新开乘数。

## 一、开罗怎么放「汤底」

`_逆向上游/TheRamenSensei/取证/textassets/xls_out/English.lproj__soupaffinity.txt` 是 28 行
「位掩码 + 加成」的**相性矩阵**：把选的几种汤料当位掩码查出一格，那一格给分数。它不是
「三选一」，而是「哪几味凑一块更好」。

我们的对应物已经有两层了：`game/src/data/flavor.ts` 的七条成型吃法（酸辣 / 鲜香…），
`game/src/data/pairing.ts` 的二十条搭法（猪肝粉肠、猪杂打蛋…）。再抄一张 28 行矩阵，会把
`game/src/sim/score.ts` 里已经排好的「八参 → 汤底分」结构推翻一次（R-11 撤过一回），
所以这一批**换成一个玩家一句话就懂的选择**：这一款的汤，拿什么打底。

顺带对照了同目录的 `English.lproj__storeequip.txt`：开罗的座位是**要钱**的（柜台行
0 / 700 / 1750 / 7800 换 4 / 6 / 8 / 12 位），这和我们批 P′ 撤掉「成套白送一个座位」
是同一条判据 —— 位置和锅底这类东西，不能白送。

## 二、三底表

| 底 | 锅里在干什么 | 汤底分 | 料钱 | 解锁 |
|---|---|---|---|---|
| 老友底 | 热油先爆酸笋、豆豉、蒜末与辣椒，香味起来了再冲骨汤 | 不动 | 不动 | 一开始就有 |
| 番茄底 | 番茄下锅炒到出沙、化进汤里，再压一勺酸笋 | +3 | +¥0.5 | 卖出 120 碗 |
| 猪脚底 | 骨头汤里再吊一锅猪脚卤水，汤面挂一层胶质 | +5 | +¥1.2 | 卖出 400 碗 |

出处（都核过原文，写在 `game/src/data/soupbase.ts` 的 `source[]` 里）：

- 南宁日报《把冬天酿成暖暖的甜》：「将酸笋、豆豉、蒜末在热油里爆炒出浓香。」→ 老友底
- 搜狐《南宁的人气砂锅粉……灵魂酸辣椒》：「汤底是番茄和酸笋，酸酸甜甜很开胃。」→ 番茄底
- 下厨房《猪杂老友粉》：「搭配独特的酸笋豆豉番茄」→ 番茄底的第二出处
- 大众点评《南宁老友粉》：「汤底浓郁，由骨头汤加猪脚卤水而成」→ 猪脚底

## 三、不做的四条（都写进文件头了）

1. **不做「清汤底」** —— `game/src/data/dish-name.ts` 里我们自己核过一句「南宁粉店没有浓汤
   清汤之分」，再加一档清汤就是拿自己的说法打自己。
2. **不做矩阵** —— 相性已经在 `flavor.ts` 与 `pairing.ts` 两层里，加第三层只是重复。
3. **不碰乘数** —— 三底只走 `soup` 与 `cost` 两个已有出口；客流、耐心、出碗、满意度一个都不动。
4. **不许「又便宜又好喝」** —— 测试 `game/src/sim/soupbase.test.ts` 有一条专盯这件事：
   任何 `costDelta <= 0` 的底，`soupDelta` 必须 `<= 0`；任何 `soupDelta > 0` 的底，`costDelta`
   必须 `> 0`。老友底是零偏移，因为它是标准答案。

## 八、替身四种子与归因实验

判据：月均营收不低于 ¥100,000，碗数不塌。

| 跑法 | 四种子 | 均值 | 碗 | 流失 | 期末现金 |
|---|---|---|---|---|---|
| X′ 基线（上一批末） | 106,354 / 86,621 / 102,987 / 106,124 | ¥100,522 | 191.2 | 42.8% | ¥357,293 |
| 本批代码 + 闸门，**行情还原** | 106,354 / 86,621 / 102,987 / 106,124 | **¥100,522** | 191.2 | 42.8% | **¥357,293** |
| 本批代码 + 闸门，**闸门临时改成 0** | 117,795 / 112,736 / 86,201 / 114,305 | ¥107,759 | 193.4 | 41% | ¥497,450 |
| 本批全量（当前上线状态） | 117,795 / 112,736 / 86,201 / 114,305 | **¥107,759** | 193.4 | 41% | **¥497,450** |

三条结论，都是从上面这张表读出来的，不是估的：

1. **汤底三底在替身里一格没动**：把行情还原之后，四种子与 X′ 基线**逐位一致**。替身从不换底
   （默认老友底零偏移），所以这一批的收益侧没法靠替身验 —— 记为新缺口。
2. **P364 那道闸在替身里从不触发**：闸门 0 与 2000 两次跑出来的四种子逐位相同。替身的现金
   始终在两千以上，闸门等于没开过。留着一行代码当穷店兜底，但**不能算验过**。
3. **营收 +7.2%、期末现金 +39.2% 全部来自行情那六条负值收 25%**：这是唯一能让四种子动起来的
   改动，三项退出量（营收 / 碗数 / 流失）同向变好，不是单点挪数。

## 九、新缺口

- **P389** 汤底三底替身从不选，收益侧零验证（要真验得让替身在「客人多、现金松」时试一次换底）。
- **P390** 面板「汤底 · 8 参」的分组合成值不随底变，玩家只能从总分和成本看出「汤底 +3」，
  看不见它落在哪一格。
- **P391** `SCRIPT_EVENT_MIN_CASH` 在替身里从不触发，等于未验；真穷局才用得上。
- **P392** 行情六条一起乘 0.75，没有逐条归因，哪一条最有感说不清（要跑六次单点开关）。
- **P393** 三底的 `costDelta` 与 `soupDelta` 是照「贵五毛换三点」的口径拍的，没做「一点汤底分
  值多少钱」的统一换算。
- **P394** `dishName()` 不体现打底：玩家把一款改成「阿婆那碗」，界面上仍看不出它是番茄底。
