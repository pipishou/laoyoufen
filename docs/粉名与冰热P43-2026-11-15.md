# 粉名与饮料冰热（P43）—— 开罗「四轴拼名」怎么落地到南宁

日期：2026-11-15 · 目标：把开罗的 `ramen_name.txt` 四轴拼名本土化，并补饮料冰热

---

## 一、三句话结论

1. **开罗的四轴不是配料轴，是品质轴**：`ramen_name.txt` 4 行 × 9 档，每档一组同义形容词（`Weak/Light/Simple…` → `Ultimate/Lovely/Prime/Flavorful`），拼出来是「Ultimate Heavenly Titanic Legendary ramen」——**等级越高词越夸张**，跟碗里放了什么无关。
2. **南宁不这么叫**：老友粉没有「浓汤/清汤」之分（汤底就是酸笋+豆豉+猪骨那一锅），也没人给一碗粉堆四个形容词。真实点单是四个**实轴** —— 做法 × 主料 × 粉型 × 加料，而且**默认项省掉**：说「一碗老友粉」，老板默认汤粉、切粉、碎肉。
3. 所以我们照抄结构、换掉内容：品名 = `[做法]老友[主料][粉型]粉 [＋加料]`，开罗那套「形容词随品质升级」搬到**评语**里（5 档南宁话）。另外补上饮料冰热（夏天冰、冬天热），这是开罗售货机没有、南宁必须有的一层。

## 二、开罗取证

`English.lproj__ramen_name.txt`（4 行，每行 `9|` 后接 9 档、档内 4–6 个同义形容词）：

| 轴 | 低档（第 1 档） | 高档（第 9 档） | 是什么 |
|---|---|---|---|
| 0 | `Weak / Light / Simple / Fresh / Plain` | `Ultimate / Lovely / Prime / Flavorful / Yummy` | 风味／好吃程度 |
| 1 | `Velvety / Soft / Gentle / Delicate / Fragrant` | `Dazzling / Phantom / Galactic / Decadent / Heavenly` | 口感 |
| 2 | `Mini / Small / Healthy / Micro / Petite` | `Towering / Galactic / Ultra / Titanic / Infinite` | 份量 |
| 3 | `Smiley / Everyday / Normal / Basic` | `Legendary / Gods' / Optimal / Radical / New Age` | 修饰（噱头） |

`English.lproj__text.txt` 里对应两条界面词：`ラーメンの名前 / Ramen Name`、`名前を変更 / Rename` —— 玩家给自家那碗粉取名。
`help.txt` 的 `Customers 1` 讲 `Wallet`、`Toppings` 讲「单品也涨经验」，都没有「汤浓淡」这个词。

**判断**：开罗这套是「给品质起个响亮的名字」，不是菜单学。硬搬到老友粉上会变成「顶级醇厚砂锅猪杂粉」，本地人不会这么说。

## 三、我们的四轴

`game/src/data/dish-name.ts`：

| 轴 | 取值 | 从哪来 | 为什么不写进名字 |
|---|---|---|---|
| **做法** | 汤粉（默认）／干捞／砂锅 | 粉型推导：`dry`→干捞、`claypot`→砂锅、其余→汤粉 | 汤粉是默认 |
| **主料** | 碎肉（默认）／猪杂／加蛋／腐竹／油条／青菜 | 在架加料里加成最高的那件（`data/sides.ts` 的 `satBonus`） | 碎肉是默认 |
| **粉型** | 切粉（默认）／圆粉／伊面／湿面 | `state.noodle`（P42 的六种粉） | 切粉是默认 |
| **加料** | 「＋腐竹」「＋油条」 | 除主料之外还挂在架的加料 | 只在多于主料时才写 |

拼法：

| 配置 | 名字 |
|---|---|
| 汤粉 + 切粉 + 碎肉 | **老友粉** |
| 干捞 + 切粉 + 猪杂 | **干捞老友猪杂粉** |
| 砂锅 + 切粉 + 碎肉 | **砂锅老友粉** |
| 汤粉 + 伊面 + 碎肉 | **老友伊面** |
| 汤粉 + 圆粉 + 加蛋 | **老友加蛋圆粉** |
| 汤粉 + 切粉 + 猪杂 + 腐竹 | **老友猪杂粉＋腐竹** |
| 任意 + 套餐 | 名字后加 **（配饮料）** |

**关键设计**：主料从「在架加料」推出来，而不是新增一个「选主料」字段。现实里老板挂什么料，客人就点什么粉——你上了猪杂，菜单上自然就有「老友猪杂粉」。这样 P43 不动数值、不新增存档字段（除了冰热）。

## 四、评语 5 档（替代开罗的夸张形容词）

`DISH_NOTES`，按实时评分 `score.total` 分档，显示在评分卡名字下面：

| 分数 | 词 | 一句南宁话 |
|---|---|---|
| ≥85 | 镇店之宝 | 这条街做不出第二碗，熟客进门只点这个。 |
| ≥75 | 街坊都识 | 坐下来不用看牌子，老板自己知道你要哪碗。 |
| ≥65 | 酸笋够镬气 | 锅气足，酸笋的酸是炒出来的，不是泡出来的。 |
| ≥55 | 老友味正 | 该有的都有，就是还差一点火候。 |
| <55 | 家常水平 | 自己吃得下，拿出去卖要再练。 |

## 五、饮料冰热

`data/sides.ts` 新增 `DrinkTemp = "ice" | "hot"` 与 `tempFitOf(temp, season)`：

| 季节 | 冰 | 热 |
|---|---|---|
| 夏（月 6–9） | **+1 满意** | −1 |
| 冬（月 11–2） | −1 | **+1 满意** |
| 春秋 | 0 | 0 |

- 只对**点了饮料**的单子生效（`tempBonus` 先判 `items.some(d => d.kind === "drink")`）。
- 玩家在店铺页签「饮料冰热」一行切换，状态存 `state.sides.drinkTemp`（`SAVE_VERSION 15 → 16`，老档补 `ice`）。
- 替身（游戏测试员）也会跟着季节换：冬天上热的、其余上冰的——量尺不换，冬天冰绿豆沙就白扣分。

## 七、与开罗对照

| 开罗 | 我们 | 说明 |
|---|---|---|
| `ramen_name.txt` 4 轴 × 9 档 | 四轴（做法/主料/粉型/加料），每轴取实际值 | ✓ 结构照抄、内容换成实轴 |
| 形容词随品质升级 | 评语 5 档（镇店之宝 → 家常水平） | ✓ 换成本地口语 |
| 玩家给自己那碗粉取名（`Ramen Name` / `Rename`） | 名字自动生成，不给玩家手输 | △ 手输容易出「最强老友粉」，先不做；要做得配审核或只给 AI 候选 |
| 售货机卖饮料（`Vending`） | 饮料柜 4 种 + 冰热 + 套餐 | ✓ 比开罗多一层季节 |
| 份量轴（Mini → Infinite） | 未做（两/三两大碗） | ✗ 缺一层「二两/三两」，见下 |
