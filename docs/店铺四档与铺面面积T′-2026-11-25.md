# 店铺四档与铺面面积（批 T′）

> 第三轮 GAP 的第一条：**店没变大**。扩建四档的数据早就在（`data/expansion.ts`），
> 座位/灶位/日上限也一直给，但界面上从来没说过「你现在这家店有多大」。

## 一、开罗那边是怎么让店变大的

| 开罗 | 原文 / 表 | 做法 |
| --- | --- | --- |
| 主店等级 | `store_data` Lv1–4 容量 **50 / 150 / 270 / 420** | 一次扩建，座位上限跳一大截 |
| 柜台 | `storeequip` `0 / 700 / 1750 / 7800` → 4 / 6 / 8 / 12 位 | 多坐几个人**要花钱买** |
| 内装 | `storeparts` 34 件、`storepattern` 六套 | 只管气氛，不管容量 |

本作的问题是：容量其实都给了，但**没有「现在多大」这句话**——96 格永远全亮，
玩家看不到「打通隔墙之后多了一片」。

## 二、这一批做了什么（只有「看得见」，一个数值都没改）

### 1. 铺面阶梯 `STORE_AREAS`

`game/src/data/slots.ts` 新增五档面积（与 `EXPANSION_ORDER` 同序）：

| 档 | 名字 | 画面里的铺面 | 总格数 |
| --- | --- | --- | --- |
| 0 | 街边摊 | x 2–9 · y 2–7 | **48** |
| 1 | 打通隔墙 | x 1–10 · y 2–7 | **60** |
| 2 | 后厨扩容 | x 0–11 · y 2–7 | **72** |
| 3 | 后巷雨棚 | x 0–11 · y 0–7 | **96** |
| 4 | 二楼清出 | 同上 + 楼上 24 格 | **120** |

四条纪律写在文件头上：

1. **一格数值都不改** —— 座位、灶位、日上限、产能仍由 `venue` / `equipment` / `expansion` 决定。
2. **槽位永远照画** —— 后墙那条灶位（y=0）是固定墙位、不算铺面格，所以矩形从 y=2 起，
   不会出现「灶摆在没铺开的地上」。
3. **二楼另计** —— 12×8 画不下二楼，第四档只把数字加上去，抬头写「另有楼上 24 格」。
4. **单调、嵌套** —— 升一档，原来亮着的每一格都还亮着（`store-area.test.ts` 逐格验过）。

### 2. 店里那一段的口径

`game/src/ui/panels.ts` 的 96 格抬头改成：

```
铺开了 48 / 48 格（第 0 档 · 街边摊）
```

没铺开的格子用 45° 斜纹灰掉（`.g96 .gc.bare`），`title` 写「还没铺开 —— 下一步「打通隔墙」」。
买了东西但落在没铺开的那片上的槽位，同样带 `data-out="1"`（探针靠它数格）。

### 3. 四档成长阶梯

扩建那一段原来是「只写下一步」，现在四步全列出来：

- 已买的 → 打绿勾、写「已扩建」，并写明这一步当初给的是什么（座位 +N · 灶 +N · 日上限 +N）；
- 下一步 → 带价钱按钮，段位不够时按钮写「段位不够」；
- 后面还没到的 → 写「先买上面那一步」，同样把收益写出来。

## 五、剩下的缺口

- **P359**：铺面面积只是画法，格子本身仍不参与玩法（P304 还在）——要真让位置有用，得等「摆放位置影响翻台路径」那一层，且不能再叠乘数。
- **P360**：第四档的「楼上 24 格」只在抬头里，画面里看不到二楼。
- **P361**：四档阶梯把价钱与收益并排写了，但没说「值不值」——回本天数这件事在「今天」那一条里（`todayLine`），两处没有互相引用。
- **P362**：`STORE_AREAS` 的矩形是手量的，与 `SLOTS` 的槽位坐标没有互相校验；将来挪槽位要记得同时改面积。
