# 三条缺口的本土化 / AI / 像素风方案 · 2026-11-24

上一轮验收留下三条最要紧的缺口：成套奖励白送在产能瓶颈上（P301）、世界变厚的成本全落在玩家头上（P311/P316/P321）、新手期撞上压迫型事件（P325）。这一份是对着开罗《The Ramen Sensei》的原始表，把这三条拆成可施工的方案，并按本土化 / AI / 像素风三条线各给一个落点。

---

## 一、开罗怎么做的（取证原文）

### 1. 成套内装：`storeparts` + `storepattern`

`English.lproj__storeparts.txt` **34 行**，八列：`id / 名字 / 类别 / 贴图 / ? / 套号 / 是否成套件 / 价`。前四行是基础件（Line Floor、Kitchen Floor、Kitchen Wall、Vending Machine），后面六套各五件：

```
0	Line Floor	0	-1	1	-1	0	0
1	Kitchen Floor	1	3	1	-1	0	0
4	Chic Floor	4	7	0	0	1	50
5	Chic Wall	5	8	0	0	1	100
6	Chic Entrance	6	6	0	0	1	500
7	Chic Chair	7	13	0	0	1	50
8	Chic Table	8	14	0	0	1	150
19	Cafe Floor	4	24	1	3	2	100
21	Cafe Entrance	6	23	1	3	2	1000
```

`English.lproj__storepattern.txt` **6 行**，就是「套号 → 五件」的索引：

```
0	Vintage	5	10	9	11	13	12
1	Chic	5	5	4	6	8	7
3	Cafe	5	20	19	21	23	22
```

读出来两件事：

1. **成套的每一件都要花钱**，而且是差价分布 —— 椅子 50、桌子 150、墙 100/200、门头 500/1000。后半三套（Cafe / Retro / Natural）价格整体翻倍。成套不是一个「凑够了白拿」的机制，是**「买齐了才好看，买齐也不便宜」**。
2. **座位不在内装里**。座位在 `storeequip` 表的柜台行：`0 / 700 / 1750 / 7800` 换 4 / 6 / 8 / 12 位 —— **座位是要单独掏钱买的设备**，内装管的是气氛（开罗的 `Appeal`）。

对照本作：`game/src/data/slots.ts` 的 `SLOT_SETS` 只有两条，`room_done` 凑齐六张桌 → **`seats: 1` 白送**；`front_done` 凑齐四件门面 → `attractPct: 0.04`。第一条正是 P301 的病根：座位是本作唯一的真瓶颈（`EAT_MINUTES = 6`），白送一个座位等于白送一天十碗，替身因此多赚 21.6%。

### 2. 行情：`economy` 的 26 条全是**成对**的

`English.lproj__economy.txt` 26 行，最刺眼的是这个结构：

```
2	Customer Wallet Up	3	…
3	Customer Wallet Down	1	…
4	Customer Movement Up	2	…
5	Customer Movement Down	1	…
6	Cust. Eating Speed Up	2	…
7	Cust. Eating Speed Down	1	…
8	All Ramen Flavor Up	4	…
9	All Ramen Flavor Down	1	…
10	All Ramen Appeal Up	4	…
11	All Ramen Appeal Down	1	…
12	All Ramen Prices Up	4	…
13	All Ramen Prices Down	1	…
14	All Ingr. Costs Up	1	…
15	All Ingr. Costs Down	4	…
```

**七对上下**。开罗没有「只来坏消息」的年份：钱包会涨也会跌，吃速会快也会慢，料钱会涨也会落。而且每一行都带月份窗口（如 `Spring Weather` 只在 2/3/4 月）和几率列，玩家能在手册里把整张表看完。

对照本作：`game/src/data/market.ts` 十六条里，`waterCut`（进店 −16%、料钱 +5%）、`gasUp`（料钱 +10%、耐心 −4%）、`roadWork`（进店 −18%、耐心 +6%）**三条是纯减益，没有任何对冲** —— 这就是 P320。而 P316 说的「世界变厚、成本落玩家」是同一件事的总账：同行 8→16、行情 8→16 之后，替身营收从 ¥111,395 掉到 ¥104,185。

### 3. 新手期：`fixevent` 与开场提示

`English.lproj__fixevent.txt` **500 行**，`English.lproj__ev_message.txt` **20 行**。开罗的固定事件是有先后顺序的（`fixevent` 的行号就是顺序），开场那段是「店开起来了 / 该买锅了 / 有人来吃了」这类教学，不是「房租涨了 / 猪肉涨价」这类压迫。`help.txt` 的 `Customer Fullness`、`Construction (Other)` 也都是先讲规则再讲惩罚。

对照本作：`game/src/data/events-more.ts` 五十一件里有 **二十六件环境压迫型**（停水、气价、青菜涨、垃圾清运、城管、修路……），`game/src/sim/events.ts` 的 `eventEligible` 只在 `def.minDay` 存在时才设门槛，而这批**一件都没写 `minDay`** —— 第 7 天就可能撞上「青菜涨」，第一次玩的人会觉得怎么选都亏。这就是 P325。

## 二、方案：三条，每条三个落点

### A ″ 成套不再白送座位（解 P301）

**改法**：`game/src/data/slots.ts` 的 `room_done` 把 `seats: 1` 换成 **`patiencePct: 0.12`**（桌与桌之间让开，坐着不挤，愿意多等一会儿），`line` / `why` 同步改写；「多坐一位」这件事明确交回 `plastic_stool` / `bamboo_chair`（各 ¥150，`game/src/data/gear.ts`）。

**为什么这么改**：开罗的座位在 `storeequip` 里要花 700–7,800，内装套装只管气氛；本作现在是反过来的 —— 装饰白送产能，设备收钱。改完「成套」是**软收益**（耐心、进店），产能只能靠钱买，这也是 D′ 那条 `EAT_MINUTES = 6` 之后唯一说得通的形状。

**本土化**：南宁的粉店多是自家屋子改的，桌子摆得开是因为「把杂物间清了」；但**多坐一个人**得有凳子、得有地方放，这是要买的，不是凑齐桌子就有。`why` 一句写这个因果，不引外部出处（这是系统取舍，不是考据）。

- **AI**：新落点 `set_voice`（键 = 成套 id，只有两个键 `room_done` / `front_done`），凑齐当天说一句街坊话；上下文 `{事, 在}`。预算 320 → **330**。
- **像素风**：成套那一行在凑齐后加金色勾标（复用 `icon("chalk")`），未凑齐保持虚线框 —— 与手艺页 `.pc.on` 同一套像素语言（2px 实边 + `steps(2)`），不新增颜色。

**判据**：替身四种子回到 M′ 量级（月均 **≤ ¥110,000**，现在 ¥98,949 但含白送；改后预计相近或略低，且**碗数不该上升**）；`room_done` 完成后 `venue.seats` 不变；矮凳仍能买。

---

### B ″ 行情成对 + 一条能对冲的杂货（解 P316 / P320）

**改法一（系统层，不需要出处）**：`game/src/data/market.ts` 的 `MarketDef` 加 `pair?: MarketId`，把三条纯减益各配一条正向：

| 减益 | 配对 | 关系 |
| --- | --- | --- |
| `waterCut` 停水（进店 −16%） | `payday` 发薪日（客单价 +16%） | 停水那周人少，但发薪日出手大 |
| `gasUp` 气价（料钱 +10%） | `marketRush` 赶圩（进店 +） | 成本涨的日子街上人多 |
| `roadWork` 修路（进店 −18%） | `schoolOpen` 开学（进店 +） | 围挡挡了散客，学生照来 |

`game/src/sim/market.ts` 的 `todayMarket` 抽到减益时，**次日优先抽它的配对**（把配对塞到池首位）。这样一段窗口内涨跌自洽，玩家不会连着三天只挨打。

**改法二（本土化，只有一条有出处）**：杂货铺加一件应急货 **`water_bucket` 借两桶水**（人情 4，当天把 `waterCut` 的进店 −16% 抵成 −6%）。出处：手机广西网《南宁一小区连续停水4天，上千户居民生活受影响》 `https://v.gxnews.com.cn/a/20244703` ——「因为停水，楼下餐饮店的生意也受到了影响」「我们小区负二楼备有大水箱储备水，通常外面主水管道停水后，可以从大水箱抽水二次加压供给居民用水」。**气价与修路这两条的对冲件查不到能引原文的本地出处，先不设** —— 这条纪律与前几批一致，宁缺不编。

- **AI**：新落点 `market_answer_voice`（键 = marketId，只用在那条对冲货上），上下文 `{天, 事}`；本地池四句。预算 330 → **340**；分项配额给 `market_*` 一族设 24。
- **像素风**：HUD 今日行情条后面，若有对冲件可买，挂一枚 `icon("bean")` 小标（豆=水桶，同一套 24×24 网格，不加新图标）；杂货铺那一行沿用 `.lrow.hotrow` 的 `→` 前缀。

**判据**：四种子月均营收回升到 **¥105,000 以上**；`market_pair` 测试保证「减益后一期必出配对」；停水那天买水桶后 `attract` 从 −16% 变 −6%。

### C ″ 新手期不挨压迫（解 P325）

**改法**：`game/src/data/events-more.ts` 的二十六件压迫型统一加 **`minDay: 30`**（第一个月不抽），并在 `game/src/sim/events.ts` 加一条软规则 —— 记录 `state.events.lastKind`（`pressure` / `plain`），**同一类压迫型两次之间至少隔三期**（21 天）。分类写在数据里（`GameEventDef` 加可选 `kind?: "pressure" | "plain"`），不靠猜标题。

**为什么是 30 天**：开罗的固定事件是排好顺序的教学，本作是每周抽一件；第一个月四个抽取点全给「平淡/善意」，玩家先学会「怎么选都不亏」，再慢慢遇到「怎么选都要付一点」。这不需要新出处，但它把 P325 那句「怎么选都亏」直接消掉了 —— 压迫型本身仍然一条都没删。

- **AI**：不加新落点。压迫型事件第一次出现时，用已有的 `loss_explain` 语气……不行，那是打烊单。改成复用 `hook_voice` 的 `street` 一族（已有 8 句），在事件弹窗副行里请一句「这条街就是这样」的口气，键加 `#e` 后缀，不新增预算。
- **像素风**：压迫型事件的标题条加一枚 `icon("flag")` 浅色小标（`--sand`），让玩家一眼分辨「这是今天的麻烦」还是「这是来送东西的」。

**判据**：新局前 30 天抽取的压迫型次数 **0**；第 31 天之后恢复正常；`events.test.ts` 新增两条（门槛、间隔）；替身四种子不受影响（替身不选事件）。

## 三、二次确认：撤掉了什么

| 原本想做的 | 撤掉的理由 |
| --- | --- |
| A ″ 改成「凑齐后花 ¥400 请木工让过道」 | 查不到南宁粉店拆改的原文出处；而且这等于把白送改成打折卖，形状比「成套只管气氛」更绕 |
| A ″ 直接把 `room_done` 整条删掉 | 成套机制本身是对的（开罗就有），病在出口选错，不在机制 |
| B ″ 给气价、修路也配对冲件 | 两条都找不到能引原文的本地出处，按纪律不设（见 P331） |
| B ″ 行情池整体改成「正负各半」 | 会把天气类（回南天、台风、寒潮）也一起抹平，南宁的天气本来就不对称 |
| C ″ 把二十六件压迫型改成「一件都不掉口碑」 | 会把事件变成没有代价的文案，等于删掉一半内容；改门槛不改内容 |
| C ″ 给新手期做一套独立事件池 | 要多写二十件，且与 N′ 刚写的那批重复；门槛+间隔两条规则就够 |

## 五、新缺口（P331–P336）

- **P331** 气价与修路的对冲件没有本地出处，暂时无解；要么接受纯减益，要么以后找到报道再补。
- **P332** 行情配对是「次日优先」，玩家看不见「明天会补一条」，容易读成随机。
- **P333** 成套从产能改成耐心之后，`patiencePct` 会不会与杂货「借三台电扇」叠加过度，未验。
- **P334** `set_voice` 只有两个键，凑齐两次之后永远重复。
- **P335** `kind: "pressure"` 是手写分类，新加事件忘了标就绕过门槛 —— 与 P323 同型的手写同步问题。
- **P336** 新手期 30 天是拍的，没有实测数据支撑（需要新玩家的第一次试玩报告）。
