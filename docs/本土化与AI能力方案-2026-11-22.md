# 本土化 + AI 能力方案（对照开罗《The Ramen Sensei》）

日期：2026-11-22　｜　依据：REA 逆向取证表 46 张（`D:\项目\REA\REA\逆向\_逆向上游\TheRamenSensei\取证\textassets\xls_out\`）+ 本作 `game/src/{data,sim}` 现状（SAVE_VERSION 35、AI 落点 18、65 文件 750 用例）

## 0. 结论先行

1. **玩法骨架我们已经抄到八成**，缺的不是系统数量，是**三处"会变的东西"**：浇头会熟练、街区会腻、升段给点数。开罗这三处让「同一套界面玩三十小时不腻」，我们目前是「系统很多，但世界不动」。
2. **钱没有去处**（P231 期末 ¥339k）不是数值问题，是我们少了开罗最厚的一层：**用钱换时间**（`investment` 111 条限时上货/请人/打广告）。加维护费、涨段位费都是拿假成本压现金，正解是给钱一个能买到"十天窗口"的货架。
3. **AI 的正确边界是"说人话"，不是"算数"**。现有 18 个落点全在同一层（说话层）。真正缺的是**解读层**（把已有数值翻成一句归因）与**裁决层**（在本地算好的候选里挑一个）。内容层（批量生成候选句）应离线做，不进运行时。
4. **不能照搬的三样**：轮盘制面（赌性 vs 手艺）、光环 aura（数值爆发 vs 我们的热卖）、多店全模拟（成本与可读性）。理由见 §3.5。

## 1. 开罗的玩法骨架（六层，逐层有原文）

### L0 时间与节奏
- 月结：材料费**月初一次扣**（`Ramen Stats 1`：Ingredients Costs: Deducted at the beginning of the month）。
- 大会固定在**六月与十二月**（`Contests 1`：Contests are held in June and December each year），三型五档。
- 段位 11 级，费用 5,000→5,000,000 KCU，带人次门槛 100→7,000（`grade_review`）。

### L1 单品层（一碗粉的四步）
| 步骤 | 机制 | 原文 / 表 |
|---|---|---|
| 制面 | 小麦 + 碱水 + 加水率 + 形状 → **轮盘**（win rate 决定中奖格出现率，variability 决定格子数值上限） | `Making Noodles 1–3`；`boiltime` 8 行修正 |
| 制汤 | 按顺序下料，**相性好触发 combo**，combo 越多倍率越高 | `Making Soup 1–2`；`compatibility` 3 汤种 × 4 面 = 12 行 |
| 配料 | 卖出去的浇头拿 XP 升级；技能点够触发 **ramen skill** | `Editing Toppings` / `Toppings`；`topping` 44、`topping_combo` 38、`ramen_skill` 45 |
| 碗 | 5 只碗各抬一维（拉面/漆器/青瓷/古碗/陶碗 → 味/气/量/魅） | `bowl`：Normal +0、Lacquer +气、Porcelain +量、Ancient +香、Potter's +味 |
| 菜单 | 販売メニュー + サイドメニュー 两条菜单 | `softkey`/`text`：Sales Menu / Sides Menu |

四维：**味（Richness）/ 香（Aroma）/ 量（Volume）/ 魅（Charisma）**，四维各自挂一个出口——味→食后评分、香→排队时长、量→吃的时间、魅→光环触发。这段话在 `help` 里写成 13 个字的四条（`Ramen Stats 2`），是全作最重要的一张映射表。

### L2 经营层（一间店的一天）
卖券机 → 店员**问出口味**（service 越高问得越快，只问总店）→ 出碗 → 客人吃 → **饱食度满给魂点** → 常客化 → 拉面馆里串店。
- 客人四参数：钱包 / 速度 / 耐心 / 等级（`Customers 1`），钱包不够的产品**更难卖出去**。
- **热卖槽**：要"外面有人排队" **且** "吃到喜欢的拉面"两条同时成立才涨；满了触发 frenzy，来客 stats 更高、店员得光环（`Ramen Frenzy 1–2`）。

### L3 空间层（店、街区、拉面馆）
- 店铺容量：Main Shop Lv1–4 = **50 / 150 / 270 / 420**（`store_data`），另有 Small/Normal/Big/Amazing 四档可买（5,000 / 8,000 / 15,000 / 50,000 KCU）。
- 设备是**并行口数**：灶 1/2/4/8 口（250 / 800 / 1,500 / 8,000）、粉篓 4/8/12/16 筒（0 / 650 / 1,400 / 7,500）、柜台 4/6/8/12 位（0 / 700 / 1,750 / 7,800）（`storeequip`）。
- 内装 6 套 pattern（Vintage / Chic / Amazing / Cafe / Retro / Natural）+ **家具格位表**（`casket` 14 行 × 227 列）。
- 区域 7 个，各自的 **energy 与 appetite 会慢慢衰减**，别区会上涨 → 玩家要挪店（`Sales Areas 2`）。`hidearea` Lv1–14 按段位逐块揭开。

### L4 竞争层
- **同行**：出现后按产品强弱压低我的人气/产品值；资金耗尽会走人并留下 XP/钱/物；但"他自己赚够走了"就什么都没有——所以要么拖死他，要么正面打（`Rival Shops 1–3`）。
- **落场（arena）**：三指令 Pop Up（抬人气）/ Charisma Up（抬魅力 + 给一位客人光环）/ Spirit Bowl（给全场光环），每场对四维权重不同（`arena` 4 条说明）。
- **评定**：11 段，费用 + 人次门槛 + rank 门槛。
- **大会**：三型（店员总属性 / 全部店铺人气魅力 / 全部客人等级）× 五档门槛。

### L5 成长层
- **经营者等级 + rank bonus 点数树**：升段给点数，点数换永久加成（`rank` 17 行：面条含水量上下限、形状、汤料上限、浇头上限、战术槽、同时道具、馆地扩建…）。
- **投资 111 条**：材料 / 人 / 设施三类，单笔 5,760–20,250 KCU，**限时**（`investment`）。
- **Pumpkin 食材店**（买面/汤/浇头原料）、**Item Shop**（魂点买道具，`itemdata` 44 条：加速、双倍耐心、触发光环…）。
- **Ramen Lab**：把不需要的配方卖掉，换魂点 / 经验 / 抽奖（`Ramen Lab 1–2`）。
- 收集与叙事：`trophy` 39、`news` 24 期（Noodle News）、`topics` 9 条手册、`talk` 244 句闲聊、`fixevent` 500 + `ev_message` 20（事件）、`economy` 26 条限时全局 buff（含四季天气与三种拉面热潮）。

### L6 设置项（界面清单，`text` 第 280–302 行）

## 3. 本土化方案（一层换一层，换成南宁的东西）

### 3.1 三处"会变的东西"（补开罗会变的三样）

**① 浇头熟练度（对 `topping` XP）**
- 南宁版本：**「这家店的牛腩，我认」**。每卖出 N 份带某浇头的粉，该浇头涨一级；等级只抬这一款的两个出口（相 charm 小幅、挑剔客扣分减免），不抬味道总盘。
- 落地：`data/ingredients.ts` 加 `xpStep`，`state.ingredientXp: Record<string, number>`（1 级 50 份、2 级 150 份、3 级 400 份，封顶 3 级）；`sim/score.ts` 只在 `charm` 与 `pickyPenalty` 上读等级。**好处**：玩家有"专精某几款"的动机，菜单从"勾 8 样"变成"挑 3 样做绝"。

**② 街区会腻（对 `Sales Areas 2` 的 energy/appetite）**
- 南宁版本：**「这条街吃腻老友粉了」**。每区两个值：`palate`（口味新鲜度，0–100）与 `traffic`（人流），两者互相拉扯——新鲜度高但人流低（新街区），人流高但吃腻了（老街区）。
- 规则：在本区连开一天 `palate −0.6`，换菜单主料变化 ≥2 样 `palate +3`，开新店/搬区 `palate` 重置 70；`palate < 40` 时进店 ×0.8、满意 −3；`palate > 75` 进店 ×1.1。
- 落地：`sim/district.ts` 加 `palateOf/tickPalate`，接进 `spawnChance` 与 `settle` 的满意链。**好处**：地图不再只是视野，搬区成为策略；同时给 P219（四圈与转让费同序）一个非价格的理由。

**③ 段位点数（对 `rank bonus`）**
- 南宁版本：**「段位牌子上的面子」**。每升一段给 2 点（首段给 3 点），点数换**永久小加成**：+1 座 / 出碗 −2% / 耐心 +4% / 料钱 −1.5% / 每日 +1 位常客，每项 3 级，共 15 点。
- 与技法树分工写死：**技法 = 手上的功夫（要人情 + 钱，练一支是一支）；段位点 = 招牌的面子（要段位，全局微加成）**。这样 P158（两套并存）与 P187（支间无依赖）有了明确边界。

### 3.2 钱与时间的去处（补 `investment` 与 `itemdata`）

**限时投资三条**（每条 10 天，可取消耗，替掉"拍脑袋的维护费"）
| 投资 | 花费 | 效果 | 南宁说法 |
|---|---|---|---|
| 让料商留货 | ¥1,200 / 10 天 | 料钱 −6%、断货不涨价 | 「跟粉行老板打好招呼」 |
| 请老师傅来帮 | ¥2,400 / 10 天 | 出碗 −8%、当天满意 +2 | 「请阿伯来看两天火」 |
| 公众号推一篇 | ¥3,000 / 10 天 | 进店 +15%、只对新客 | 「本地号写你一篇」 |

**杂货铺（对 item shop，付人情不付钱）**：多备一筐粉（当天产能 +15 碗）/ 借两台风扇（当天耐心 +20%）/ 买一箱冰（当天饮料销量 ×1.5）。人情 6–12 点一件，一天最多买一件。

**卖配方（对 Ramen Lab）**：把一款配方卖同行，得现金 ¥2,000–6,000 + 人情 10，但该同行味道 +3（他学会了）。给出"要不要教会对手"的真选择。

### 3.3 已对但值得再压一次的

- **热卖**：把"排队"从 ×1.5 加成改成"排队人数进槽的斜率"，或干脆按开罗原句把它做成**门槛**（≥3 人排队才起槽），但当日结算去噪（P199）。
- **内装 96 格**：从"只画"到"占一格给一点"——灶格 +出碗、桌格 +座、备料格 +案台、门面格 +进店。**每格 0.5%**，满格 +48%，够薄不破平衡。
- **口味调研**：店员 `memory`（记性）专精已给耐心 +8%，再加一条：有记性专精在岗时，打烊单多一行「今天有 N 位想吃 X」，指向明天该主推哪款。

### 3.5 刻意不照搬（并写理由）

1. **轮盘制面**：开罗的乐趣在"赌一把"，我们的主题是"手上的功夫"。强行加轮盘会让"四维九档读数"变成噪音，也让玩家把失败归给运气。**替代**：随机只到"天"级（当天粉的干湿、火候窗口），一碗之内不掷骰。
2. **光环 aura**：开罗的 aura 是纯数值爆发（客人身上冒光、属性翻倍），视觉与手感都很"手游"。我们的热卖槽已覆盖同一心理需求，再加一层只会让 HUD 变吵。
3. **多店全模拟**：开罗拉面馆能同时经营多店并跑模拟，代价是界面与 AI 复杂度翻倍。我们用**分店 4 家轻量代理**（只结算、不模拟），保住"开分店"的叙事而不付那份成本。

## 4. AI 能力方案

### 4.1 现状（说话层，18 落点）

- 通道：`game/src/ai/lines.ts` 的 `fetchLine(ask, timeoutMs = 800)` → `POST /laoyou-api/line` → `server/app.py` 的 `deepseek_line()`（`deepseek-chat`，temp 0.95，max_tokens 180，12 s 超时）。
- 18 个落点：`street_request / rival_rumor / recipe_buyer / arena_call / hook_voice / trophy_voice / tourney_open / flavor_voice / style_voice / bowl_voice / guest_voice / guest_talk / tier_voice / market_voice / retail_voice / grade_voice / notebook_voice / district_voice`。
- **三道红线**：prompt 里写死"任何数字都不许"→ 服务端 `sanitize_voice()` 用 `CN_QUANTITY` + `MECH_WORD` 正则整句作废 → 客户端 `isCleanLine()` 双保险。
- **两级缓存**：服务端 `data/ai_cache.jsonl` 按 `kind:key` 命中；客户端 `CACHE` + `INFLIGHT` 去重。
- **降级顺序**：客户端缓存 → 服务端缓存 → DeepSeek → 本地池（18/18 都有本地池，`offline_only` 可全局关）。
- 线上实测：`audit_ai.py` 18 / 18 remote。

### 4.2 缺的那三层

**B. 解读层（最高价值，先做）**：把已经算出来的数值翻成一句人话。
| 新落点 | 触发 | 上下文（只给名词） | 解决 |
|---|---|---|---|
| `loss_explain` | 打烊，流失 > 35% | 主因维（队满/价牌/等不及）、最慢那段、街名 | P146/P157 |
| `menu_advice` | 打开菜单页，某款连续 3 天销量垫底 | 款名、主料、浇头名、街上最便宜那家 | P232 |
| `palate_voice` | 街区 `palate < 40` 第一次触发 | 街名、本周主推、隔壁开的是什么 | 新机制的回声 |

**C. 裁决层（只选不算）**：本地先算好候选与增益，再让模型在候选里挑一个并给理由。
```ts
// sim/hook.ts 已有 nextHook；新增一层"让模型选，但选的必须在候选内"
const picks = hookCandidates(state);           // 本地算：[{id, kind, gain, why}]
const line = await fetchPick({ picks, ... });   // 模型只回 id + 一句理由
const chosen = picks.find((p) => p.id === line?.pick) ?? picks[0];  // 越界即回退本地第一
```
落点 `hook_pick`（第 19 个）。判据：模型选中的 id 必须在候选里、理由不许含数字、回退率 < 20%。

**D. 内容层（离线产线，不进运行时）**：用同一套 prompt 批量生成候选句，人工/正则筛过后落成静态数据（街坊报 100 条、笔记本 30 条、同行传闻 50 条、熟客闲聊 80 条）。**好处**：质量最高、零运行时成本、且天然满足"册子上的字不许模型改"。

### 4.3 工程约束（沿用现状，补三条）

1. **预算制取代魔数**：现在"一天最多两次四维评价"这类数字是拍的（P161）。改成**每次开局远程调用预算 60 次**，用完走本地池；HUD 不看预算、只看有没有句子回来。
2. **缓存键必须名词化**：`kind` + 名词 key（街名/粉名/段位名），**绝不含日期以外的数字**；日期只用于"第几天"的语感，不参与 key，否则缓存永不命中。
3. **红线三层不许省**：prompt / 服务端正则 / 客户端校验。AI 空句率要变成可测指标（`audit_ai.py` 里加：200 句里被 `sanitize_voice` 拒掉的比例，判据 < 15%）。

### 4.4 成本

一句话约 200 tokens（prompt ~120 + 输出 ~40）。60 次/局 ≈ 12k tokens/局；内容层一次性生成 260 条 ≈ 60k tokens。按 `deepseek-chat` 现价可忽略，**真正的成本是"玩家看到一句废话"**，所以宁可空着也不要凑句子。

## 6. 风险

- **P235**：浇头熟练度会让最优解收敛到"三样做绝"，菜单 8 款变装饰——需要在界面上给"多样化"一个出口（如常客各有偏好）。
- **P236**：`palate` 会与"搬区成本"打架；若搬区太贵，玩家只能挨着腻，等于加了一个惩罚而非选择。
- **P237**：段位点数 + 技法树 = 两套加成，叠满后出碗可能过低（`SKILL_CAP` 与段位点需一起实测，见 P189/P227）。
- **P238**：`hook_pick` 的约束解码若模型频繁越界，用户会看到"AI 选了候选外的选项"——必须有本地回退且日志可查。
- **P239**：内容层批量生成的句子容易"语气同质"，需要按人物分池（阿婆/街坊/同行/外乡人）生成，否则第 50 条开始都像同一个人。
