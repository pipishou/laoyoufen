# 灶位缺口要多少工钱（批 AS′）

> 依据：用户 m34559 的三条口令（不装插件、按建议施工、做完验收）。本批解 **P458**（补一个人要多少钱、补不补得上）与 **P460**（掌勺这句打烊单还没有）。上一批 AR′ 让界面第一次说出「灶位 3 口，只有 1 个人掌勺」；这一批回答玩家紧接着会问的下一句：**那再招一个呢，多少钱？**

## 一、先量一遍：雇人到底多卖几碗

临时脚本（已删）用 `createInitialState` + 每天 120 分钟推进 + `ackDayReport`，`totalCustomers = 2600`（人手槽全开）、`cash = 60000`，六天取后三天均值，种子 1/2/3。

两句话：

1. **雇人最多多卖 0.6 碗**（6 座那一行），加灶一碗不动 —— 因为四道闸里最紧的一直是座位或来客，不是厨房。这与批 AR′ 的结论同源，只是这次连「招人」也一起量了。
2. 所以本批**一个数值都不改**。要改就得改「人手是真瓶颈」的配平，那是另一批的事（P459 记的就是这件事）。

## 二、于是这一批只做一件事：把取舍摆出来

批 AR′ 的 `crewFacts` 只说「几个人掌勺」。玩家知道卡在哪，却不知道贵不贵 —— 与 P453 同型（副行只是跟随，不给取舍依据）。本批把它扩成五段事实：

| 字段 | 什么时候出现 | 长什么样 |
| --- | --- | --- |
| `words` | 永远 | 灶位 3 口，眼下只有 1 个人掌勺 —— 第 2 口起没人看，火开不起来 |
| `why` | 只有缺口时 | 不过今天卡的不是灶：座位和街上的人先顶着天花板，多开一口火也不会多卖。 |
| `cost` | 只有缺口时 | 今天有人来问工：阿强 日薪 ¥150 · 介绍费 ¥300 · 月薪约 ¥3,900 |
| `cost`（人手槽满） | 只有缺口时 | 人手槽还差 500 位累计接待（到 800 位才有人肯来） |
| `cost`（没人来） | 只有缺口时 | 今天没有煮粉的来问工 |
| `brief` | 只有缺口时 | 灶 3 口，只有 1 个人掌勺 —— 第 2 口起没人看（打烊单用短句） |

三条纪律写在 `game/src/sim/crew.ts` 的文件头：

- **只说事实，不劝买、不给推荐、不算 ROI**（ROI 是另一件事：实测买了也不多卖，写「划算」就是骗人）；
- **主句一个价钱都不许出现**（`words` 与 `brief` 都不含 `¥`），价钱只许在第三行；
- **价钱只报最便宜那个煮粉的**（`candidates.filter(role === "cook").sort(wage)[0]`），不替玩家挑、也不列整张表。

### 一个口径踩坑（值得记）

`cost` 的第一版无条件说「人手槽还差 N 位累计接待」。`crew.test.ts` 首跑就红：

```
expected '人手槽还差 500 位累计接待（到 800 位才有人肯来）' to be '今天没有煮粉的来问工'
```

因为**人手槽有空位却说「还差 500 位」会把能立刻雇的人挡住**。改成：

```ts
const full = state.staff.roster.length >= staffSlots(state.totalCustomers);
const need = full ? nextStaffNeed(state.totalCustomers) : null;
```

只有「槽真满了、招不进来」时才谈累计接待。

## 三、打烊单也说了（P460）

`.daywhy` 里加一行 `<span data-crew-line>`，前缀 CSS 写「灶位 · 」，内容用 `brief`（短句，不带价钱）。它同时进了 `foldWhyLines()` 的折叠清单，所以打烊单最多还是三行、点开看全部（P406 / P411 的规矩不变）。

**第十六次「键漏字段」**：店员页缓存键原来只有 roster 与 `cash/100`，不含灶位与候选日薪 —— 买了灶、换了候选，DOM 不重画，那一块停在旧话。已补：

```ts
`${roster}|${candidates.map((c) => `${c.uid}:${c.wage}`).join(",")}|${Math.floor(s.cash / 100)}|${s.staff.lastEvent}|${s.venue.stoves}|${s.totalCustomers}`
```

店铺页缓存键也把 `crewFacts(s).cost` 拼进去了（只说 `idle` 不够：候选换了、价钱变了，DOM 也得重画）。

## 四、探针（22 条，全 true）

`tools/gate/crew_probe.py` 从 12 条扩到 **22 条**。四态：

1. 开局（灶 1 口、老板一人）→ 整块不出现；
2. 灶 3 口、人手槽没开（`totalCustomers = 0`）→ 主句「第 2 口起没人看」、副句「今天卡的不是灶」、价钱句说「还差 300 位累计接待」且不含 `¥`；
3. `totalCustomers = 3000`（槽开了、有钱）→ 价钱句变成「日薪 ¥… · 介绍费 ¥… · 月薪约 ¥…」；
4. 雇一个煮粉 → 主句跟着改成「只有 2 个人掌勺 / 第 3 口起没人看」；灶退到 2 口 → 整块消失。

另三条：员工页同一句（同源）、打烊单那一行在 3 灶 1 人时出现且不带价钱、灶 1 口时不出现。

新增判据：`words_no_price`（只判主句）、`why_says_not_kitchen`、`gate_says_short`、`gate_no_price`、`rich_still_warns`、`rich_costs_money`、`rich_says_fee`、`day_line_shows`、`day_line_says_stoves`、`day_line_no_price`、`day_line_quiet_when_fit`。

**帧差门这次逮到一件真事**：加了「灶位」这一块之后，1440×900 变化 451 px、768 变化 284 px、375 变化 66 px。原因不是渲染不稳，是**候选人是开局随机挑的**（姓名与日薪每局不同），那行价钱句跟着变。修法是在 `PIN` 里 `s.staff.candidates = []`，价钱句固定成「今天没有煮粉的来问工」。这与批 AL′ 那次「随机店名出现在 toast 上」是同一类问题：**随机内容混进了被当成稳定的画面**。

## 六、这一批没动什么

- `cookSlots` / `serveParallel` / `serveMinutes` / 座位公式 / 来客公式**一格没动**；替身四种子逐位相同就是证据。
- 没给玩家「把灶用起来」的路：招人还是散在店员页，`crewFacts` 只是把价钱搬过来。

## 七、新缺口

- **P461** `cost` 报的是「最便宜的煮粉」—— 但候选人的技能等级不同（`skill 20` vs `skill 60`），日薪高低不等于值不值，这一层没说。
- **P462** 打烊单那一行 (`brief`) 与店面页 `words` 是同源（`crewFacts`），但**句子不同**（短句 vs 全句），与 P451 同型只是目前同源，不是一份常量。
- **P463** 「介绍费」是 `wage * HIRE_FEE_RATE`（两倍日薪），玩家看不出这是一次性还是每月都收。
- **P464** 探针 `rich_*` 三条允许「没有煮粉的来问工」也算过 —— 候选池为空时那三条其实没验到价钱格式（弱判据）。
