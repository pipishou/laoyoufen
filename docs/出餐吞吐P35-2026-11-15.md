# P35：出餐吞吐照开罗改成「并行槽」

日期：2026-11-15 · 提交：`feat(serve)` · 前置：`docs/中期节奏P24-2026-11-15.md`

## 0. 三句话

1. 上一轮把比赛日历、段位门槛、区县能量都搬进来了，营收却还是一条直线 —— 根因不是节奏，是**一天能出多少碗被焊死**：旧实现是「一段全局冷却、冷却到点出**一碗**」。
2. 开罗的产能不是「时间除以几」，而是**并行槽**。`help.txt` 里 `Staff 2` 原文：「When a staff member's cooking skill increases, they will be **able to boil more noodles at once**. When service increases, they will be **able to carry more at once**，etc.」——一锅同时煮 N 份、一趟同时端 N 碗。`Staff 1` 还写明 `Speed: Movement speed`，速度只是走位快慢，不直接等于产量。
3. 照这个形状改完之后：**来客终于会超过产能**（流失率从 19% 升到 63%），扩建第一次有可测收益（4 座 69.7 碗/日 → 8 座 87.9 碗/日，**+26%**；改之前是 +0%）。

## 1. 开罗取证（原文原句）

| `Construction (Shops)` | 「The size of the shop determines the **number of staff, seats, and facilities**」 | 与我们的扩建改 seats/stoves 一致 |

## 2. 改了什么

| 位置 | 旧 | 新 |
|---|---|---|
| `game/src/sim/staff.ts` `inNoodlesNum` | `1 + min(2, 厨师技能/50)` | `3 + 粉篓等级 + min(2, 厨师技能/50)`（粉篓本来就有几格；南宁粉店的粉篓也是多格的） |
| `game/src/sim/staff.ts` `serveParallel`（新） | — | `max(1, min(灶位, 掌勺数)) × inNoodlesNum` |
| `game/src/sim/staff.ts` `serveMultiplier` | `(boil × setout) / parallel` | `boil × setout`（只管「一轮多快」，不再兼职并行度） |
| `game/src/sim/staff.ts` `bowlMinutes`（新） | — | `冷却 × 效率 / 并行槽`，HUD 与面板都改用它，保证「显示＝引擎」 |
| `game/src/sim/customer.ts` 出餐 | 冷却到点出 **1 碗** | 冷却到点出**一批**（上限＝空座位数），没人排队就不进冷却 |
| `game/src/sim/customer.ts` 来客 | 每分钟**一次伯努利**，一天最多 120 人 | 每分钟来**一批**：`floor(期望) + 余数掷骰`，上限 4 人/分钟 |
| `game/src/ui/hud.ts` / `panels.ts` | `6 × 效率 × 设备系数` | `bowlMinutes(...)`，并把产能行改成「座位 4 · 每轮 3 碗 · 2.0 分/碗 · 日上限 200 · 客流 160/日 · 比赛 5 个月后」 |

**两道天花板连着拆**：只改出餐不改来客，产量还是被「一天 120 人」卡住；只改来客不改出餐，队列会被挤爆而没人上菜。两条一起改，才有「需求 > 产能 → 扩建/买灶/雇人 → 产能上去 → 又不够卖」的循环。

## 3. 实测

`npm run probe:win`（不操作、5 seeds × 36 月，¥9 定价）：

| 配置 | 日均碗数 | 流失 | 月均营收 | 期末现金 | 改动前日均 |
|---|---|---|---|---|---|
| 4 座 | 69.7 | 63% | ¥18,818 | ¥167,672 | 66.9 |
| 8 座 | 87.9 | 63% | ¥23,725 | ¥260,782 | 92.5 |
| 8 座 eat×0.8 | 88.1 | 54% | ¥23,797 | ¥262,587 | 87.6 |

**关键读法**：流失率从 19% 跳到 63%，说明**现在真的是客人在等、位置不够**，而不是「没人来」。4 座→8 座 +26%（旧模型下几乎无差别）。

`npm run probe:standin`（替身，种子 2）：月均营收 ¥21,424、日均 83.9 碗、总流失 62%、期末现金 **−¥36,966**。

替身亏钱的原因**不再是产能**，而是它自己的两条笨策略（见 P36）：
1. 满意度被「排队太久」拉低 → 一路把价打到 **¥8**（毛利 ¥3.2），而房租+工资已到 ¥10k/月；
2. **它从来不知道去买设备**（灶/粉篓/案台），所以新的三个产能杠杆它一个都没用。

## 4. 与开罗的对照

| 开罗设置 | 我们 | 状态 |
|---|---|---|
| 一锅同时煮 N 份 | `inNoodlesNum` 3 + 粉篓 + 技能 | ✓ |
| 一趟同时端 N 碗 | 一批出「空座位数」碗 | ✓（没区分「端」与「煮」，简化） |
| 厨师越多越能多开火 | `cookSlots = 1 + 在职掌勺` | ✓ |
| 店铺大小决定座位/设施数 | 扩建两档 seats+2 / stoves+1 | ✓ |
| 排队太久客人走 | `patience` + 流失原因 | ✓（63% 流失就是它的体现） |
| Ramen Frenzy：排队 + 吃到喜欢的 → 大批客人 | — | ✗ 见 P37 |
