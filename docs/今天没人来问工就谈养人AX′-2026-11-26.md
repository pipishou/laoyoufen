## 一、这两条是同一件事的两头

批 AW′ 让「补进来的是谁」进了模型（`capacityWithCooks(state, 1, hire.skill)`），于是副句能说
「补一个**技能 5** 的师傅……约多卖 35.5 碗」。留下的两条尾巴正好在两端：

- **P476（说给谁听）**：这句话默认「今天真有人来问工」。可候选池是按天重掷的 ——
  池子空着的时候，这句话把玩家指向一张空名单；更糟的是它还会退到
  「补齐人手这口灶才烧得上（**多一个人约多卖 不到 1 碗**）」，前后半句互相打脸。
- **P477（算哪条路）**：模型只会算「**多一个人**」，可店里还有一条真实存在的产能路 ——
  在职师傅**手艺涨点**（`sumSkill("cook")` 变大 → `boil` 变快，且每 50 点再 +1 份）。
  这条路在数值上一直有效，在文案上从来没有名字。

两条一起解完，副句才第一次把「今天到底有哪条路可走」分清楚。

## 二、模型补了一条路：`grow`

`game/src/sim/staff.ts`（批 AW′ 的函数，批 AX′ 加第四个参数）：

```ts
export function staffWithExtraCooks(
  state: GameState,
  add: number,
  skill: number,
  grow = 0,            // ← 批 AX′：现有的人往上长多少点
): { parallel: number; multiplier: number } {
  const extra = Math.max(0, Math.floor(add));
  const slotsAfter = Math.max(1, cookSlots(state) + extra);
  const cookSkillNow = sumSkill(state, "cook");
  const cookSkillAfter = cookSkillNow + extra * Math.max(0, skill) + Math.max(0, grow);
  // …并行槽与 boil 都由 cookSkillAfter 推
}
```

`game/src/sim/bottleneck.ts` 同步透传：

```ts
export function capacityWithCooks(state, extra, cookSkill = 0, grow = 0): Capacity
```

于是「雇一个技能 10 的人」与「现有的人涨 10 点」在同一口灶下是**同一个模型值**
（`crew.test.ts` 里 `expect(grow).toBeCloseTo(hire, 9)` 钉住）。这不是巧合：
`sumSkill` 只看总和，人多人少它不管；差别只出现在 `min(灶位, 人数)` 那一步 ——
灶位还有空时，多一个人能多开一口火；灶位已经顶满时，两条路完全等价。

## 三、三句话各自的作用域

`crewFacts` 的副句现在按「今天有哪条路」分三档：

| 情况 | 说什么 | 判据 |
| --- | --- | --- |
| 灶不是最紧那道 | 「不过今天卡的不是灶：座位和街上的人先顶着天花板……」 | `kitchenBinds === false` |
| 卡在灶 + **今天有人来问工**，且补上真抬得动 | 「……补一个技能 5 的师傅，这口灶就烧得上了（约多卖 35.5 碗）」 | `cookGain > BOWL_EPSILON` |
| 卡在灶 + 今天有人来问工，但**补上也抬不动** | 「今天卡的就是灶，可今天补一位进来也抬不动 —— 这口灶得一直有人盯着才烧得起来」 | `cookGain <= BOWL_EPSILON` |
| 卡在灶 + **今天没人来问工** | 「……今天没人来问工，只能靠现有的人往上长：手艺每涨 10 点，约多卖 X 碗」 | `hire === null && growGain > BOWL_EPSILON` |
| 卡在灶 + 没人来问工 + 手艺也封顶了 | 「……现有的人再练也抬不动 —— 该去理座位和街上的人了」 | `growGain <= BOWL_EPSILON` |

`game/src/data/crew.ts` 里新增 `crewWhyNoHandsWords(growGain, step)`，
`COOK_GROW_STEP = 10` 放在 `sim/crew.ts`（**提问的刻度，不是经济数值** ——
它不进 `FLOW`，不改任何量，只给那句「手艺每涨 N 点」一个可算的落点）。

## 四、批 AW′ 留下的那道缝

`bowlGainWords(0)` 诚实地写「不到 1 碗」，可它被塞进

> 今天卡的就是灶 —— 补齐人手这口灶才烧得上（约多卖 **不到 1 碗**）。

前半句说「就烧得上了」，后半句说「一碗都多不出来」。这不是数字错，是**一句话里塞了两个结论**。
现在 `cookGain <= BOWL_EPSILON` 单独成一档，抬不动就只说抬不动，**一个数字都不出现**
（`crew-literal.test.ts` 用 `expect(thin).not.toMatch(/\d/)` 钉住）。

- `COOK_GROW_STEP` 只活在 `sim/crew.ts`，不进 `FLOW`、不被 `resetFlowTuning` 管（**这本身是 P482**）。

## 八、本批新记的缺口

- **P480** `COOK_GROW_STEP = 10` 是「提问的刻度」，可玩家看不出「涨 10 点要几天」——
  这句话离开时间就没有意义，而模型里没有任何一处能回答「一天涨几点」。
- **P481** 「现有的人再练也抬不动」在煮技封顶（`sumSkill ≥ 12.23`）时就成立，
  可 `inNoodlesNum` 每 50 点还有一档台阶 —— 句子分不清「完全没救」与「再涨 20 点才有一份」。
- **P482** 打烊单上那一行（`brief`）仍然只说缺口（`crewGapWords`），
  「今天没人来问工，只能养人」这条没进打烊单 —— 与 P448 同型（一处说清，另一处还没跟上）。
