# 三段工序一句话（批 AF′）· 2026-11-25

> 这一批把两条自己留下的缺口合成一件做：**P408**（工序反馈只指最慢那一段，另外两段卡了看不出来）+ **P409**（设备页与配方页各说一半）。一格数值没动。

## 一、原来两张嘴各说一半

| 页面 | 原来写的 | 问题 |
| --- | --- | --- |
| 配方页（`[data-stepheld]`） | 「眼下最吃手的是爆香 —— 炒锅 1 口，一段 2.2 分钟」 | 只点最慢那一段，另外两段的时间与口数一个都看不到 |
| 店面页 · 设备段（`stageLine`） | 「炒锅 2.2 分/1 · 汤锅 2.2 分/1 · 粉篓 1.6 分/1」 | 三段都在，但不说是哪道工序、也不说卡在哪 |

同一件事（`stageMinutes` 那三个数）被两个页面用两套说法各说一半 —— 玩家得自己把两张对起来看。

## 二、合成一句：一个函数，两页都读

`game/src/sim/soupbase.ts` 新增两个出口：

```ts
export interface SoupStage {
  station: StationId;   // wok / pot / basket
  step: string;         // 爆香 / 吊骨汤 / 冲汤下粉
  name: string;         // 炒锅 / 汤锅 / 粉篓
  minutes: number;
  count: number;
  slow: boolean;
}

export function soupStages(state: GameState): SoupStage[];
export function soupStagesWords(state: GameState): string;
```

`STAGE_UNIT`：灶与汤锅论**口**，粉篓论**筒**（沿用设备页原来的量词，不另起一套）。

实测开局那一句（1440×900，配方页与设备段字面一致）：

> 爆香 1 口 2.2 分 · 吊骨汤 1 口 2.2 分 · 冲汤下粉 1 筒 1.6 分 —— 卡在「爆香」

- `soupStages` 读的是 `stageMinutes` + `slowestStation` + `stationCount`，和出碗速度共用同一个事实，没有新增任何系统；
- `slow` 那一位由 `slowestStation` 决定，三段里恰好一段为真（测试锁死）；
- 句子不带「买 / 升级 / 更快」这类劝说，跟 AC′ 那条纪律一致。

## 四、测试（`game/src/sim/soup-step.test.ts` 重写，7 例）

1. 三段都列出来，顺序是爆香、吊骨汤、冲汤下粉；

6. 粉篓论筒、灶与汤锅论口；
