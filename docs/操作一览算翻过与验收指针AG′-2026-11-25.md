## 二、P413 落在哪几行

- `game/src/ui/hud.ts`
  - `HudOptions` 加 `onManualRead?: (id: string) => void;`。
  - 那四条从**静态字符串**改成 `const howHtml = (): string => …`：每行 `<div class="prefrow wide how" data-how="${p.id}" role="button" tabindex="0">`，按钮写「翻一下 / 再看看」，已翻过的行在 `.prefname` 后挂 `<span class="mread">翻过</span>`。

  - `prefsWrap` 的点击监听：先判 `target.closest("[data-how]")`，命中就 `opts.onManualRead?.(id)` 后 `renderPrefs()` 再 `return`，不再往下走到那五行设置。
- `game/src/main.ts`：`mountHud` 的选项里加 `onManualRead: (id) => { if (markManualRead(state, String(id))) refresh(); }`，用的就是批 AD′ 写的 `markManualRead`。
- `game/src/ui/hud.css`：`.prefrow.how` 手型光标、悬停名字变红、`.mread` 那枚小印章（和图鉴页手册同一套）。

## 三、一个白屏级的坑（写下来防下一次）

第一版把 `howHtml` 写在 `prefsWrap.innerHTML` 里直接调用，而它读的是 `lastState` —— 那个 `let lastState` 原先声明在**下面第 570 行**。`let` 的 TDZ 让首屏 `prefsWrap.innerHTML` 一求值就抛：

```
Cannot access 'G' before initialization
```

整页白屏，控制台只有这一句（压缩后变量名是 `G`）。探针第一次跑全是红的，`sitecards: 0`。
修法：把 `let lastState: GameState | null = null;` 挪到 `howPages` 之前，并在注释里写明原因。
**这是本项目第二次栽在 TDZ**（第一次在批 F′ 的打烊单），所以规矩加一条：**模板字符串里调任何读闭包变量的函数，都要先确认那些变量在它上面已声明。**
