# A7 袋装老友粉：把店里的味道装进袋子

**三句话**：开罗的 `instant_noodles.txt`（20 行）+ `instant_soup.txt`（22 行）是「袋装 / 速食」这条产品线，本作整块没有。这一批补上，但**不做「工厂生产线」那一套**（本作只有一家店、一条街），而是做南宁真的做成了的那件事：**预包装老友粉**。一次置办包装机，之后每天按口碑出货，出货量由「店里的粉到底好不好吃」决定 —— 这条线不占餐位、不占人手，但它是唯一一条「味道可以带走」的收入。

## 一、取证：南宁确实把老友粉装进袋子了

| 出处 | 原话 | 用来定什么 |
| --- | --- | --- |
| 南宁日报《一碗老友粉 嗍出「创新味」》`http://www.nnrb.com.cn/nnrb/20240515/html/index_content_001.htm` | 「打开酱料包，倒入锅中简单加热出味，然后加入清水以及包装内备好的酸笋、米粉，约 2 分钟后，一碗酸辣可口的老友粉便做好了」 | 一袋卖出去、客人自己煮，两分钟 |
| 同上 | 「预包装老友粉的生产存在两大难点：**风味还原**、米粉口感保持」 | 出货量吊在「还原度」上，不是凭空产量 |
| 复记老友粉（非遗工坊）词条 | 2024 年日产能提升至 **20 万包**，自动化率超 90% | 上限不是无穷，但确实能规模化 |
| 零售价 | 复记 4 袋 ¥39.9（≈¥10/袋）；邕州老街 252g×10 袋 ¥25.64（≈¥2.6/袋） | 一袋 ¥10、成本 ¥5，毛利率一半 |

## 二、数值：出货量吊在「味道」上

`game/src/data/pack.ts`：

```ts
export const PACK_SETUP = {
  costYuan: 3_800,   // 封口机 + 首批包装（袋子、酱料包、干粉）
  basePacks: 6,      // 一天最少出这么多
  perRep: 4,         // 每 0.1 口碑多四袋
  perGrade: 2,       // 每段多两袋
  capPacks: 40,      // 小铺子不是工厂
  priceYuan: 10,
  costPerPack: 5,
  floorRate: 0.6,    // 味道再差，还原度也不会低于六成（不然一袋都卖不出，码没意义）
};
```

- `packRate(state)` = 昨天这碗粉的味道分折算到 **0.6–1.0** —— 味道 70 分 → 约 0.79，95 分 → 1.0。
- `packDailyOf(state)` = `(base + 口碑×4 + 段位×2) × rate`，夹在 1..40。
- `packNetOf(state)` = 袋数 × (10 − 5) —— 一天大概 ¥30–200，**小于一碗一碗卖的钱**（一天 ¥600–900），所以它是补充，不是主线。
- `settlePack(state)` 在打烊时结算：进 `state.cash`、累 `tally.packSold`，并写进当天的 `dayReport.packSold / packNet`（打烊单能看到「袋装 N 袋 · ¥M」）。

**为什么不是「买了就每天固定赚钱」**：固定产出就等于买断一条现金流，玩家买完不用再管，这条线就死了。吊在味道上，玩家每次改配方都会回头看一眼这个数 —— 它变成了一个**味道的仪表盘**。

## 三、三条纪律

1. **只落已有出口**：不新开一条「生产线」系统，一天一次结算，走 `endDay` 已有的打烊流程。
2. **不占人手、不占餐位**：包装是「夜里做的活」，与店里经营不抢资源 —— 否则这条线和雇人、扩座直接对冲，玩家会被迫做取舍。
3. **不能比一碗一碗卖更划算**：一天最多 ¥200，且买机器要 ¥3,800（约十天的袋装净收入）。它是「睡着也在进一点钱」，不是「换个方式赚更多」。

## 五、两个坑

**坑 1：白名单漏版本号，等于老档读不进来。**
`save.ts` 的判废白名单是一串手写的 `v.saveVersion !== N`。A5 加 v29 时，写成了 `!== 29` 追加在 `!== 27` 上面 —— **28 从此不在白名单里**，A4 时期的存档全部被判废。这一批的测试（喂一个 `saveVersion: 28` 的脏档要求它退回默认米骨）把它抓了出来。补上 `!== 28` 之后 564 个用例全过。
教训：白名单这种「一串数字」的结构，每加一版都要**倒着数一遍**；更好的做法是 `v.saveVersion >= MIN_SUPPORTED && v.saveVersion <= SAVE_VERSION`，可惜当初没这么写。

**坑 2：`packSec` 包不包 `.sec`。**
第一版把段内容直接拼进店铺页，少了外层 `<div class="sec">`，结果是标题和说明挤进上一段（碗）的框里。这类错误 eye_gate 的色值看不出来（色数只差几个），**只能靠截图肉眼**。

## 七、与开罗逐项对照

| 开罗 | 本作 | 差别与理由 |
| --- | --- | --- |
| `instant_noodles.txt` 20 行（速食面品类） | 一条袋装线，不分类 | 我们只有一种粉；开罗分 20 种是因为它有 20 个地区与多种汤底 |
| `instant_soup.txt` 22 行（速食汤） | 不单独做 | 老友粉的汤就是酱料包，拆开卖没有现实对应 |
| 产线、产能、工厂升级 | 一台封口机、一个日上限 40 袋 | 本作是一家店，不是企业 |
| 进货与铺货渠道 | 不做出货渠道，直接算钱 | 一局两分钟，跑渠道会变成点击游戏 |

## 八、缺口（本批新增）

- **P124 袋装线只有一个出货数字**，没有「哪个口味卖得好」——开罗有品类，我们只有一个味道。
- **P125 还原度只读昨天味道分**，客人投诉/退单这类负反馈不存在（现实里预包装最难的就是还原度被骂）。
- **P126 没有「第一批货」的仪式**：买完机器当天就出货，缺一个「试产一锅，自己先尝」的小节点。
