# 家当搭配（D 批）

**一句话**：店里十二件家当之间加了八组「两件凑一块才有的那点好处」——不加可买件、不新开引擎入口，只让已有的东西互相认。

**为什么是这一批**：P73（家当无组合）是账本里挂了很久的结构性缺口。开罗 `build_combo.txt` 38 行做的是同一件事，而且它那一列末尾的 `1/2/8/10` 正好说明「组合要等级」。我们照结构、不照内容。

---

## 一、开罗怎么写的（对照源）

`D:\项目\REA\REA\逆向\_逆向上游\TheRamenSensei\取证\textassets\xls_out\English.lproj__build_combo.txt`，38 行，制表符分隔：

```
7	Comfy Corner	1	2	2	-1	199	2	-1	184	10
1	Basic Corner	0	2	2	-1	185	2	-1	195	1
```

列：`id / 组合名 / ? / 2 / 2 / -1 / 件 A / 2 / -1 / 件 B / 等级`。三个可读出来的事实：

1. **组合 = 两件设施**，不是「任意 N 件」；
2. **同一个组合名可以有多行件对**（`Gym Style` 三行、`Stall Corner` 三行）——即「凑法不止一种」；
3. **末列是等级门槛**（1 / 2 / 8 / 10）。

开罗的组合名是 `Plant Corner / Gym Style / Comfy Corner` 这种「摆出个角落」的思路，英文、抽象、跟 It's a ramen shop 的具体生活无关。

## 三、三条设计纪律

1. **不加可买件**。八组全吃现有 12 件，补的是「东西之间的关系」，不是货架长度。
2. **不新开引擎入口**。八个效果分别落到 `sim/gear.ts` 已有的八个乘数（`gearServeFactor / gearCostFactor / gearSatBonus / gearPatienceMult / gearAttractMult / gearDrinkMult / gearFatigueMult / gearRivalShield`），一处新公式都没写。
3. **总量封顶**。`sim/combo.ts` 的 `COMBO_CAP`：进店 +15%、出碗 −10%、料钱 −10%、耐心 +20%、饮料 +20%、疲劳 −20%、抢客 −15%、满意 +3。八组凑齐正好接近但不超过。凑齐是目标感，不是数值爆炸。

## 四、三个接线点

```ts
// data/combo.ts — 组定义
export interface ComboDef {
  id: ComboId; name: string;
  pairs: [GearId, GearId][];   // 任一对凑齐即成立（照开罗同一组合名多行件对）
  note: string; line: string;
  effect: ComboEffect; kairo: string;
}
```

```ts
// sim/combo.ts — 成立判断与总量
export function comboActive(state, def) {
  return def.pairs.some(([a, b]) => owns(state, a) && owns(state, b));
}
export function comboTotals(state): Required<ComboEffect>  // 逐项 Math.min(CAP, sum)
```

```ts
// sim/gear.ts — 八个乘数各自加上搭配那一份（举例）
export function gearServeFactor(state) {
  return Math.max(0.7, 1 - sumPct(state, (g) => g.servePct) - comboTotals(state).servePct);
}
```

`sim/combo.ts` **不 import `sim/gear.ts`**（那边要反过来 import 它），直接读 `state.gear`，避开循环依赖 —— 这条写进文件头了。

面板：「家当」段下方新增「搭配 · 1/8 组」段，八行全列，凑齐的实线 + `凑齐了`，没凑齐的虚线 + `差 1 件 / 差 2 件`，副行写这一组为什么搭。抬头还会提示「再添一件竹躺椅就能凑「凳子管够」」。

探针跑出来的三态：

```
买之前：搭配 · 0/8 组
买一件：搭配 · 0/8 组 · 再添一件竹躺椅就能凑「凳子管够」   ← 那行标「差 1 件」
买两件：搭配 · 1/8 组                                     ← 那行标「凑齐了」、变实线
```

另外两条断言专防「照抄」：`no_kairo_combo_name`（界面里不许出现 `Corner` / `Style`）、`no_kairo_combo_name` 同源的件名必须都在 `GEAR_BY_ID` 里。

## 八、缺口（记进账本）

- **P86**：每组只有一种凑法。开罗 `Gym Style` 有三行，玩家换着搭也能成；我们八组都是死配一对，十二件里有两件（排风扇、锦旗）被两组共用，其余各只进一组。
- **P87**：搭配没有「达成瞬间」的提示 —— 买下第二件时只有 toast「XX 搬进来了」，不会说「凑齐了「凳子管够」」。目标感少了那一下。
- **P88**：面板只显示「差 1 件 / 差 2 件」，不显示「凑齐能涨多少」。玩家看不到具体数值，只能凭副行的话猜。
