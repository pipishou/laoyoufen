# P70 产能引导：让「明天该做什么」说人话（2026-11-19）

A 批（决策件里的第一项）落地。三句话说完：

1. **病灶**：流失从第 2 天的 44% 一路爬到第 7 天的 63%，而玩家拿到的那行提示说的是「明天再来 N 位客人」——
   他要的是「再加一对灶」，不是更多客人。
2. **改法**：当天流失过 45%，打烊单第一句就换成产能建议，并把店铺页「店面 / 设备」两段标成「现在最缺」。
   **一个数值都没动**。
3. **本土化 + AI 的结合点**：那一行分两层 —— **数字与目标由本地算，口气与理由由 AI 说**。
   AI 写不出数字（服务端 + 前端双拦），也写不出「段位 / 口碑」这类机制词；本地池永远有 6 句备选。

## 一、为什么是「引导」而不是「调数值」

首周实测（5 个种子，不操作）：

| 天 | 卖出 | 走掉 | 流失 | 营收 |
|---|---|---|---|---|
| D1 | 51 碗 | 17 | **25%** | ¥492 |
| D2 | 72 碗 | 57 | **44%** | ¥697 |
| D3 | 70 碗 | 75 | 52% | ¥679 |
| D5 | 71 碗 | 100 | 59% | ¥691 |
| D7 | 70 碗 | 117 | **63%** | ¥688 |

D2 起卖出就一直卡在 70 碗 —— 那是**一口灶的日上限**。也就是说：
**问题不在「客人来太多」，在「玩家不知道 70 是上限、也不知道该在哪加」。**

所以 A 批刻意不碰 `spawnScale`、灶效率、耐心这些数值：
调低客流会让替身 36 个月退 11%（上一批试过：¥78,485 → ¥62,385、热卖 138 → 12 次）；
而把「该加什么」说到玩家脸上，成本近乎为零。

## 二、三处改动

### 1. 钩子排序：产能插到段位前面

`game/src/sim/hook.ts` 新增 `nextHook(state): HookPlan`（`nextHookOf` 保留为兼容壳）：

```ts
export const CAPACITY_LOST_RATE = 0.45;

export function lostRateOf(state: GameState): number {
  const rep = state.dayReport;                 // 打烊单快照优先（endDay 会把 flow 清零）
  const lost = rep ? rep.lost : state.flow.lostToday;
  const served = rep ? rep.served : state.flow.servedToday;
  const visited = lost + served;
  return visited <= 0 ? 0 : lost / visited;
}
```

排序变成 **⓪ 产能 → ① 段位 → ② 家当 → ③ 街面 → ④ 落场**。
产能那一句取「设备下一档 / 下一档扩建」里最便宜的一件：

```
明天先把「猛火灶（第 1 档）」加上（¥1,500）—— 今天走了 60 位
```

钱不够时改口径（`卖了钱先添…`），**但不把这条降级** —— 流失 60% 的日子，「明天先凑钱」比「明天再来 20 位客人」有用得多。

### 2. 打烊单：红边 + 副行

`game/src/ui/hud.ts`：

```ts
const plan = nextHook(s);
hookMain.textContent = plan.text;
dayHook.hidden = plan.text === "";
dayHook.classList.toggle("bad", plan.urgency === "high");
dayHook.dataset.hookKind = plan.kind;
hookLine.textContent = plan.kind === "none" ? "" : getLine(voiceAsk, localLine(voiceAsk));
```

`game/src/ui/hud.css`：`.dayhook.bad` 换红边、`::before` 从「明天 · 」变成「**明天先处理 · **」；
副行 `.hookline` 11px 灰字，`prefers-reduced-motion` 下不额外做动画（本来就是静态字）。

### 3. 店铺页：哪两段现在最缺

`game/src/ui/panels.ts` 里 `shopHtml()` 顶部算一次：

```ts
const hot = lostRateOf(s) >= CAPACITY_LOST_RATE ? " hot" : "";
```

只给「店面」「设备」两段的 `.sechd` 加 `hot`，CSS 补 `← 现在最缺`。
`hot` 是纯展示状态，不进存档 —— 玩家一走开就自动消失，不会永久挂红。

## 三、本土化 + AI 是怎么结合的

这是本轮的核心，也是后面所有 AI 落点的**分工模板**：

| 层 | 归谁 | 例子 |
|---|---|---|
| **做什么**（目标、种类、门槛） | 本地规则 | `capacityPick()` 挑最便宜的产能件；`checkGrade()` 算差几位客人 |
| **多少钱、几个人**（一切数字） | 本地计算 | `¥1,500`、`今天走了 60 位` |
| **为什么值得做**（口气、理由） | AI，失败回落本地池 | 「灶台不趁手，再好的手也伸不开。」 |

### 四条硬约束（前端 + 服务端各拦一遍）

1. **不许出数字**：阿拉伯数字拦；**中文数量词也拦** —— `三十五位 / 两百块 / 两家` 都算违规。
   ```ts
   const CN_QUANTITY =
     /[一二三四五六七八九十百千万两][十百千万]?(?:几|多|余|来)?\s*(位|碗|元|块|天|人|件|张|个|家|份|次|名|斤)/;
   ```
   放行「一口锅」「两口子」这类日常说法 —— 只有「数词 + 量词」才算数字。
2. **不许碰机制词**：`菜单|段位|口碑|人气|份额|评分|数值|版本|AI|系统`（服务端 `MECH_WORD`）。
3. **上下文只递名词**：`hookVoiceContext()` 把种类翻成「灶台与座位 / 门口的招牌 / 店里的旧家当 / 街上的事 / 落场」，
   不把 `grade`、`rep` 这种字段名递过去。
4. **每天最多一次**：缓存键 `hook_voice:capacity:月:日`，打烊那一刻由 `main.ts` 的 `prefetchHookLine()` 触发一次，
   回来就 `refresh()` 换字；拿不到就一直是本地池那句。

### 与开罗的对照

开罗的街区投资表 `investment.txt` 111 项，**每一项都自带一句 NPC 请求**：

```
0  Clean Park 5760 … "The park's so dirty these days I can't practice my comedy act. Clean it up."
1  Tea Room   7290 …
2  Billboard  20250 …
```

它从来不用「投资回报率」说服玩家，而是让街坊用一件具体的小事开口。
我们这轮把这套搬到了打烊单上：**本地算清「该修什么、多少钱」，AI / 本地池说清「为什么」**。
区别是我们把「说什么」交给了模型，所以必须把「算多少」死死钉在本地。

## 六、缺口

- **P74**：钩子口吻的本地池只有 6 句，一个月就见全 —— 需要按种类分池（产能/段位/家当各 4 句）。
- **P75**：`hot` 只标了店面与设备，家当里同样能接客的三件（洗碗池、大砧板、冰柜）没标。
- 玩家仍然可能无视提示 —— 这轮只保证「他说了」，玩家听不听要等 bot 的下一轮日志。
