# AI 接入（四个落点）· 2026-11-18

一句话：AI **不接管任何机制**，只接管「人说话」这一层 —— 街坊提事、同行传闻、收配方的人开口、落场那声喊，四句话，都有本地备选，都只出文字不出数字。

---

## 一、为什么是这四个落点，为什么按这个顺序

开罗本身没有 AI 文案层（`English.lproj__help.txt` 里没有任何对话生成）。它给的是**四条能挂语声的玩法骨架**，我们照着本土化：

| 开罗 | 原句 | 我们的落点 |
|---|---|---|
| `▼Ramen Hall Road Work` / `▼Construction` | 街区可以花钱修东西 | **街区请求**（街坊来提一件街上的事） |
| `▼Rival Shops` | 对手店有名气、会抢客 | **同行传闻**（街坊说一句同行闲话） |
| `▼Ramen Lab 1` | `You can sell unneeded ramen recipes here. … Get Spirit Points` | **转手买家的话**（买下配方的人开口） |
| `▼Ramen Arena 3` | `Pop Up: Raise popularity` | **落场战况**（冲自家摊位喊一声） |

风险从低到高的排序理由（也是实施顺序）：

1. **街区请求** —— 面板里一行字，一句说完，最坏情况是句子不好看。
2. **同行传闻** —— 同上，但挂在「谁抢你的客」旁边，写歪了会误导判断。
3. **转手买家的话** —— 玩家刚做完一次不可撤销的操作（配方卖了），此刻弹一句话很显眼。
4. **落场战况** —— 在每秒重渲染的擂台浮层里，最容易变成性能问题或闪烁。

---

## 二、四条铁律（写死在代码里，不是自觉）

1. **只出文字，不出数字。** 前端 `/\d/` 命中即丢；服务端 `sanitize_line()`（既有）再拦一遍阿拉伯数字。
2. **每句都有本地备选。** `ai/lines.ts` 的 `LOCAL` 四组池子（6/6/5/5 句），哈希确定性选句 —— 没有代理、代理超时、代理乱说，界面都是完整的中文句子。
3. **缓存键 = `kind:key:month:day`。** 同一天同一对象的同一句话，只问一次；`CACHE` 命中即时返回，`INFLIGHT` 复用同一次请求。
4. **不碰机制名与数值。** 服务端 `MECH_WORD` 过滤 `菜单|段位|口碑|人气|份额|评分|数值|版本|AI|系统`；场景指令里明写「绝对不要出现任何阿拉伯数字、金额、百分比、名次」。

超时 800ms，超了就永远是本地句，**界面不留任何痕迹**（没有「AI 生成中」的转圈）。

## 三、三层结构

```
界面（panels / arena）          只调 getLine(ask, 本地备选)  ← 同步，永不阻塞
        ↓ 没有缓存就 null
ai/lines.ts                    fetchLine(): 800ms 超时、/\d/ 丢弃、inflight 复用
        ↓ POST {kind,key,context,month,day}
server/app.py  POST /line      sanitize_line()→数字过滤；sanitize_voice()→再加机制词过滤
        ↓ 缓存 line:{kind}:{key}:{month}:{day}
        DeepSeek（temperature 0.95 / max_tokens 180 / timeout 12）
```

预取调度在 `main.ts:onMinute()` —— 每天最多问一次，只问「今天会被看到的那几条」：街坊今天提的那件事 + 本区抢得最凶的两家同行。拿到就 `refresh()`，拿不到就一直是本地句。

## 四、四个落点的接线点

| 落点 | kind | 在哪 | key | context |
|---|---|---|---|---|
| 街区请求 | `street_request` | `panels.ts` shop 页「街面」段 | 街面件 id | `{街: 名字}` |
| 同行传闻 | `rival_rumor` | `panels.ts` shop 页「同条街」段每行 | 同行 id | `{店, 档}` |
| 转手买家 | `recipe_buyer` | `main.ts` 的 `sellRecipe` 成功后 toast | `${noodle}-${main}` | `{粉, 街}` |
| 落场战况 | `arena_call` | `ui/arena.ts` 擂台上的 `.acall` | `${arena}:${idx}` | `{场}` |

落场那条特殊：**局内只读缓存，绝不在 rAF 里等网络**。`startArena` 成功时先 `for i in 0..2` 预取三句，局内按 `(hits + burstsDone) % 3` 换着显示。没有预取到就一直是本地句「手别停，节奏在你这边。」

## 五、AI 门（`tools/gate/ai_gate.py`）

三个阶段各 build 一次（把 `VITE_AI_LINE_URL` 内联进包），各起一次 preview，跑同一套流程：

| 阶段 | 代理 | 断言 | 结果 |
|---|---|---|---|
| `01-offline` | `http://127.0.0.1:45999/line`（连不上） | 游戏照常、界面是本地句、**没有 JS 异常** | ✅ `街坊来提：「明秀路那段路灯坏了半年…」` |
| `02-online` | 本地假代理，回「这条巷子晚上黑，娃娃放学走这儿我不放心。」 | 在线句**真的上屏**（请求 / 传闻 / 喊话三处） | ✅ 三处全换成在线句 |
| `03-digits` | 假代理回「这条街现在有 3 家粉店，我们家最便宜。」 | 整句被丢，界面仍是本地句 | ✅ 界面没出现「3 家粉店」 |

判定口径：只把 `pageerror`（JS 异常）当失败；offline 阶段的 `ERR_CONNECTION_REFUSED` 是预期行为，不算。

## 七、过程中抓到的两个真问题

1. **跨源被浏览器拦掉，表现为「AI 从来没生效」。** 页面在 preview 端口、代理在另一个端口，假代理不加 `access-control-allow-origin` 时 fetch 直接 reject，回落本地句 —— 一切看起来都正常，只有断言不通过。生产环境同源（`/laoyou-api/line` 由 nginx 反代），所以只在验收脚本里暴露。
2. **面板缓存键不含文案版本，换字了也不重画。** `panels.ts` 的 shop 缓存 key 原来只有数值字段，`refresh()` 后命中旧 key，DOM 不更新 —— 在线句其实已经进了缓存，但界面还是本地句。修：key 末尾追加 `remoteLineCount()`（`ai/lines.ts` 里已有的计数器）。**凡是「异步换文字」的功能，缓存键必须包含文字版本。**

## 八、与开罗逐项对照

| 开罗 | 我们 | 差异 |
|---|---|---|
| 没有 AI 文案 | 四落点语声层 | 我们没有抄它的任何文本 |
| 街面修东西有居民反应 | 街坊来提一件事（本地池按 id 哈希） | 我们把它做成「一句请求 + 一句南宁话」 |
| 对手店有名字与等级 | 8 家同行 + 一句传闻 | 传闻只描述性格，不给数字 |
| 卖配方换 Spirit Points | 转手换人情 + 买家开口 | 我们的买家会说话（开罗只结算点数） |
| Arena 三命令 | 三命令 + 一声喊 | 喊话是语声，落点最显眼、风险最高 |

## 九、缺口（已记账）

- **P61**：四个落点的本地池各只有 5–6 句，玩家玩到第三个月就会见过全部句子；且同一句话在「街坊来提」与「街坊说」两条通道里不共享池子。
- **P62**：`/line` 没有做「同日不同对象」的批量接口，四家同行要四次 POST；DeepSeek 侧单次约 1s，首页首屏可能出现「先本地、后换字」的轻微跳动。
- **P63**：AI 只写话，不写「语气」—— 没有随口碑变化的口吻（街坊对一家 4.8 分的店和对一家 1.2 分的店说话方式一样）。
