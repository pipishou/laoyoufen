# 养人这一步到底怎么走 —— 批 AY′（P480 / P481）

> 2026-11-26。批 AX′ 让副句在「今天没人来问工」时改谈养人，可它报的刻度是**游戏里不存在的一步**：
> 「手艺每涨 10 点」。这一批先把「手艺到底怎么往上长」查清，再让那句话只指真有的路。

## 一、两条是同一个毛病：句子在指一条走不通的路

| 缺口 | 原文 | 症结 |
| --- | --- | --- |
| **P480** | `COOK_GROW_STEP = 10` 是「提问的刻度」（问「涨 10 点值几碗」），可玩家看不出「涨 10 点要几天」，模型里也没有一处能回答「一天涨几点」 | 刻度是我拍的，玩家照着算不出明天该花什么 |
| **P481** | 「现有的人再练也抬不动」在煮技封顶时成立，可 `inNoodlesNum` 每 50 点还有一档 +1 份 —— 句子分不清「完全没救」与「再涨 20 点才有救」 | 两个不同处境说成同一句，其中一种根本够不着 |

## 二、取证：手艺往上长，游戏里只有两条路，都是一档

`game/src/sim/favor.ts`：

```ts
case "teach_staff": {
  const roster = [...state.staff.roster].sort((a, b) => a.skill - b.skill);
  const weakest = roster.find((m) => m.skill < 5);
  if (!weakest) return { ok: false, reason: "店里的人手艺都到顶了" };
  weakest.skill = Math.min(5, weakest.skill + TEACH_STEP);
}
```

`game/src/data/favor.ts` 里 `TEACH_STEP = 1`，`teach_staff` 的价钱是 `costPoints: 12`。
另一条入口是 `game/src/sim/specialty.ts:88` 的 `learnSpecialty`，也是 `Math.min(5, member.skill + 1)`。

所以「手艺涨」这件事，**只有「涨一档」这一种步长**，没有「涨 N 点」的入口。

### 那「涨 10 点」到底值多少？扫一遍

临时脚本（`game/src/sim/tmp_ay1.test.ts`，跑完已删）：`capacityWithCooks(state, 0, 0, g)`，`g = 1..50`。

| 配平 | tight | g=1 | g=3 | g=5 | g=10 | g=15 | g=20+ |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 12 座 / serve 20 / 1 个 cook1 | stove | 1.86 | 6.21 | 11.04 | **32.91** | 32.91 | 32.91 |

g ≥ 10 就撞上座位 / 来客天花板，再涨一格不动。也就是说：

- 「涨 10 点」在多数配平里**不达**（玩家手上没有这一档）；
- 就算能涨 10 点，它给出的碗数在 g ≥ 10 后与 g = 10 完全相同，**不比「涨一档」多信息**。

### 那「每 50 点一档」有没有救？

`game/src/sim/staff.ts:102-106`：

```ts
inNoodlesNum =
  3 + equipLevel(state, "strainer") + Math.min(2, Math.floor(sumSkill(state, "cook") / 50) + grown);
```

四个人满编 4 × 5 = 20 点，`Math.floor(20 / 50) = 0` —— 这一档**永远够不着**。
另一条实测（`tmp_ay4.test.ts`，已删）：8 座 / serve 24 / 三 cook1，+1 手值 **1.553 碗**，而离下一个 50 点台阶还差 49 点、那一档值 **39.195 碗** —— 值钱，但拿不到。
所以「再涨 N 点才有救」这句话**一句都不写**（P481 的处理不是修刻度，是不许说）。

## 三、改法

### `game/src/sim/crew.ts`

```ts
/**
 * 手艺往上长的**唯一一条真实路径**：人情「让师傅带一手」（批 AY′ 解 P480）。
 *
 * 真实入口只有两个，效果都是**手艺涨一档**：
 *   ① `useFavor(state, "teach_staff")`：每用一次挑在职里手艺最低的那位 +1 档，封顶 5 档，花 12 点人情；
 *   ② `learnSpecialty(...)`：送人学专精，也 +1 档（还额外给专精效果）。
 */
const TEACH_RANKS_PER_USE = 1;

const growGain = capacityWithCooks(state, 0, 0, TEACH_RANKS_PER_USE).total - now.total;
```

`why` 的第三分支（今天没人来问工）：

```ts
: kitchenBinds ? crewNoHandsWords(growGain) : crewWhyWords(kitchenBinds, cookGain, null);
```

### `game/src/data/crew.ts`

```ts
export function crewNoHandsWords(teachGain: number): string {
  if (teachGain <= BOWL_EPSILON) {
    return "今天卡的就是灶，可现有的人手艺都到顶了 —— 再带一手也快不了，该去理座位和街上的人了。";
  }
  const cost = FAVOR_BY_ID.get("teach_staff")?.costPoints ?? 0;
  return (
    `今天卡的就是灶 —— 今天没人来问工，只能靠现有的人往上长：` +
    `让人情带一手（${cost} 点人情，手艺涨一档），约多卖 ${bowlGainWords(teachGain)}。`
  );
}
```

三条要点：

1. **12 点只写一处**：从 `FAVOR_BY_ID` 读。人情哪天调价，句子跟着变（这一条正是批 AU′ P467 的同型处理）。
2. **抬不动时一个数字都不出现**：`teachGain <= BOWL_EPSILON` 只说「手艺都到顶了」，不让「约多卖 不到 1 碗」再出现一次（批 AX′ 那道缝的彻底修法）。
3. **一句「再涨 N 点」都没有**：`not.toMatch(/\d+ 点(?!人情)/)` —— 唯一的「点」是「12 点人情」，那是玩家真能付的东西。

## 四、测试

`game/src/sim/crew.test.ts` 21 → **23 例**：

- 新增「『养人值几碗』问的是手艺涨一档，不是凭空的 10 点」：`crewFacts(s).growGain` 必须等于 `capacityWithCooks(s, 0, 0, 1).total - capacityOf(s).total`（9 位），且 `(s,0,0,10)` 确实更大、但 `why` 里不许出现「10 点」。
- 新增「『再涨 N 点才有救』这种话一句都不写」：`crewNoHandsWords(0 / 2.5 / 30)` 三档都 `not.toMatch(/每涨|再涨|还差/)` 且 `not.toMatch(/\d+ 点(?!人情)/)`。
  - 踩坑：第一版写的是 `not.toContain("点")`，被「12 点人情」判红 —— 判据要判「不是说刻度」，不是「不许出现这个字」。
- 改：「一口灶时，雇一个技能 3 的人」与「现有的人涨一档」是同一个模型值（`toBeCloseTo(9)`）。

`game/tools/crew-literal.test.ts` 仍 **14 例**：扫描词从「现有的人再练也抬不动」换成「再带一手也快不了」，其余判据（只许一处出处 / 不劝购 / 与 `hud.css` 的 `::before` 对齐）不变。

## 七、新缺口

- **P483** `TEACH_RANKS_PER_USE = 1` 把两条路说成同一条：`teach_staff` 挑「手艺最低的那位」、`learnSpecialty` 由玩家指定谁去学 —— 上限相同（都 5 档）、**可选空间不同**，句子里没有这一层。
- **P484** 那句报的是「一手」能多卖几碗，不是「12 点人情」能多卖几碗。人情还有两条花法（`hint_recipe` 8 点、`treat_street` 6 点），玩家拿这句话算不出机会成本（与 P466 同型：只说了效力、没说价钱换来的比例）。
- **P485** `useFavor` 挑的是**在职里手艺最低的那位**，而句子说的是「现有的人往上长」—— 谁会长没对上；店里手艺最低的可能不是煮粉的（`roster` 里还有备料、端粉），那一手可能涨在没用的人身上。
