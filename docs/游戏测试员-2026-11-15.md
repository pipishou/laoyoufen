# 游戏测试员：把替身从「会玩的脚本」改成「会出裁决的 QA」

> 日期：2026-11-15 · 目标：按 Claude Code Game Studios 的 QA 结构改造替身，并把替身测出来的问题按开罗拉面店的设置本土化修掉。

## 一句话结论

替身现在不只是打数字，它跑完 36 个月会交一张**裁决单**（通过 / 通过但有清单 / 无法评估 / 不通过）和一份**问题四桶**。这次它抓到两个真缺陷（换区在被绕过状态机的情况下永远被拒、转让费按 GDP 线性定价贵到买不起），修完之后同一套策略的三年成绩从「越做越小（×0.72）」变成「三年长 37%」。

## 二、替身自己的策略也修了（P36 的根）

上一轮替身的结论是「热卖只值 +0.1%、扩建没收益」——那其实是**替身从不买设备**造成的：它一直用 1 灶 1 掌勺的产能去扛 8 座店的客流。

改了三处：

1. **会买设备**：流失率 >40% 且现金 > 下档价 +¥4,000 就买（顺序 灶 → 粉篓 → 案台）。
2. **价格下限钉在 ¥9**（南宁老友猪杂粉现实价），不再一路滑到 ¥8。
3. **每天先点掉日结单**（`ackDayReport`）—— 这条不是策略，是替身绕过了状态机：它用 `advanceMinute` 直推时间，`phase` 永远停在 `closing`，而 `moveShop()` 要求 `phase === "prep"`，于是**换区从第一天起就被静默拒绝**。

## 三、被替身抓出来的两个真缺陷

### 缺陷 A：换区永远失败（已在替身侧修）

- 现象：36 个月一次都没搬过家，区能量衰减到 55% 也没人动。
- 原因：替身绕过 `tickMinute`，从不确认日结单 → `phase === "closing"` → `moveShop()` 返回「打烊后再搬」。
- 修法：替身每天开门前 `if (s.dayReport) ackDayReport(s)`。
- 教训：**模拟器绕过状态机，就会测出一个假世界。**

### 缺陷 B：转让费按 GDP 线性定价，买不起（已改数值）

- 现象：修好 A 之后仍然搬不动，因为青秀要 ¥120,000 ≈ 4.4 个月营收，替身三年只攒到 4–6 万。
- 开罗口径：`region.txt` 的解锁费是 0 / 1,000 / 5,000 / 5,000 / 15,000 / 30,000，而一碗拉面 1,050 —— 换区的心理成本是「一两天的营业额到一两个月」，不是「按 GDP 算命」。
- 改法（`game/src/data/nanning.ts`）：全部按「本作一个月营收（≈¥2.7 万）」重定 —— 县域 ¥6,000–10,000、中池 ¥18,000–22,000、城区 ¥32,000–55,000、西乡塘 ¥70,000、青秀 ¥95,000。
- 同时把转让费改成**一次性解锁**（`moveShop` 查 `tally.districts`）：付过一次的区以后随便搬回，对齐开罗「买个区就归你了」；否则从免费区搬出去再搬回，等于白嫖一个新池子。

## 四、修完之后的实测（`npm run probe:standin`，种子 1/2）

| 指标 | 改前（不买设备、换区被拒） | 改后 |
|---|---|---|
| 裁决 | BLOCKED | **PASS_WITH_NOTES** |
| 月均营收 | ¥20,557 | **¥31,470** |
| 三年成长（后 6 月 / 前 6 月） | ×0.72（在缩） | **×1.37** |
| 日均碗数 | 85.4 | **116.6** |
| 期末现金 | −¥69,524 / ¥52,487 | **¥41,476 / ¥40,813** |
| 段位 | 8 | **10** |
| 比赛 | 6 场 | 6 场（含 1 次冠军 ¥20,000） |
| 买设备 | 0 次 | **12 次**（灶 4 / 篓 4 / 台 4，全满） |
| 搬家 | 0 次 | **4 次**（良庆 → 兴宁 → 武鸣 → 良庆） |

剩下的唯一 high 问题：

> **T3 有 11 个月营收几乎不动** —— 月营收最长持平段 11 个月。

原因不是亏钱，是**产能到顶**：8 座 + 2 灶 + 1 掌勺 + 设备全满 = 116 碗/日 ≈ ¥31.5k/月，而区池子还有 189–229 客/日没用完。要继续长，只能加灶/加人 —— 而加灶靠 S5（已到顶）、加人靠累计客流解锁（每天 116 碗一个月就够 2600 人了）。也就是说：**中期缺的不是数值，是「新动词」**。

## 五、对着开罗找这一条该怎么补

开罗的 `rank.txt` 16 行奖励里，本来就排着：

- `Ramen Hall Expansion`（扩建）
- `More Line Tiles`（加排队位）
- `Buy Small / Normal / Big / Amazing Shop`（买更大的店）

即「扩建」在开罗不是一个动作做到顶，而是被 rank 一层层解开的；同时 `grade_review.txt` 的门槛（4/7/10/15/20/24/30/34/40/50 人次/千次）保证你隔几个月就必须去「交钱升段」才有下一批奖励。

我们的现状：S5 只有两档、段位有费有门槛但**段位不给奖励**（`applyGrade` 只加口碑和 ¥500–30,000 现金），所以「升段」是花钱买名声，不是买新动词。

**结论（下一批该做的）**：把 `rank.txt` 的解锁树做成 P3 那批里的 `data/unlocks.ts` —— 段位每升一级，解锁一条新动词（第三个扩建档 / 第二排排队位 / 分店 / 设备第五档）。这样 T3 的 11 个月持平会被「下一次升段」切开。

## 六、已知缺口

- T3 未解决（等 P3 解锁树），当前是 `PASS_WITH_NOTES`。
- 替身仍只雇 1 人（只补掌勺且要求现金缓冲），跑堂/备料从不雇 —— 这是替身的保守，不代表游戏上限。
- 热卖 410 次/3 年（≈每 2.6 天一次），但 T6 判据只查次数不查收益，因为收益已经在 T2/T3 里体现。
- 判据阈值（1.15 成长、4 个月持平、¥9 均价）都是我按现实与开罗定的，**还没用真人数据校准** —— 等真人试玩够 3 局再调。
