## 一、三句话

1. 次日一早流失率恒为 0 —— 红标一次没亮、产能钩滑走的病灶在 `lostRateOf` 只读打烊单快照。
2. 产能钩按「最便宜」排序，买完灶就稳定点名粉篓 —— 粉篓只省料钱，救不了排队。
3. 「明天」被说了两次（CSS 前缀 + 正文），主句也过长。

## 二、F1：次日仍然算得清流失

### 病灶

`game/src/sim/hook.ts` 的 `lostRateOf()` 只读两处：`state.dayReport` 与 `state.flow.lostToday / servedToday`。
玩家点「明天继续」时 `ackDayReport()` 把 `dayReport` 清成 `null`（`state.ts:865-868`），`endDay()` 早把 flow 计数清零 —— 第二天一早 **0 / 0 = 0%**。

同一个 0 让 `panels.ts` 的红标判定 `lostRateOf(s) >= CAPACITY_LOST_RATE` 永远为假。

### 修法

`state.days` 里本来就存着最近 120 天的 `DayRecord`，直接读末条即可，**不动存档结构**：

```ts
const MIN_SAMPLE = 5; // 头几分钟只有两三个人走，比例噪声太大

export function lostSampleOf(state: GameState): LostSample {
  const rep = state.dayReport;
  if (rep) return sampleOf(rep.lost, rep.served, true);      // 打烊当时：今天
  const liveVisited = state.flow.lostToday + state.flow.servedToday;
  if (liveVisited >= MIN_SAMPLE) return sampleOf(...live, true); // 今天样本够
  const last = state.days?.[state.days.length - 1];
  if (last) return sampleOf(last.lost, last.served, false);   // 次日早上：昨天
  return live;
}
```

顺带把「哪一天」也带出来（`live`）：打烊单写「今天走了 N 位」，次日写「昨天走了 N 位」。

### 实测

| | 改前 | 改后 |
|---|---|---|
| 打烊时（`dayReport` 在） | 0.6 | 0.6 |
| 次日一早（清空后） | **0** | **0.6** |
| 店铺页红标 | 0 处 | **2 处**（店面 / 设备，都带「← 现在最缺」） |

## 三、F2：产能钩要挑真能接客的那件

### 病灶

```ts
// 改前：三件设备 + 下一档扩建全进候选，谁便宜选谁
return picks.sort((a, b) => a.cost - b.cost)[0] ?? null;
```

猛火灶第 1 档与粉篓第 1 档都是 ¥1,500，粉篓排在前面 → 买完灶之后钩子稳定改口「粉篓」。
而粉篓在商店里写的是「一碗省 ¥0.14」，**它降的是单碗料钱，对一天最多出多少碗毫无帮助**；
真正能接住排队的「打通隔墙 ¥12,000（座位 +2）」因为最贵，永远选不上。

### 修法

给三件设备定性（对应它们自己的 `effects` 文案），只让「真能接客」的两类参与推荐：

```ts
type CapKind = "seat" | "speed" | "cap" | "cost";
const EQUIP_KIND: Record<EquipId, CapKind> = {
  stove: "speed",   // 出碗 5.1 → 4.3 分/碗
  bench: "cap",     // 日上限 +40 碗
  strainer: "cost", // 一碗省 ¥0.14  ← 不参与
};
```

- 扩建按 `seats > 0 ? "seat" : "speed"` 归类（后厨扩容 `stoves +1` 算提速）；段位锁住的扩建直接不进候选。
- **座位 ≤ 4 时，能加座的扩建优先于任何设备档位**（`SEAT_TIGHT = 4`）——街边摊 2 座、小店 4 座都属于「坐不下」。
- 排除 `cost` 之后仍按价格取最便宜；万一设备全满级只剩省钱件，才退回它（不让钩子哑掉）。

### 实测（真点，街道办级的街边摊配置）

```
改前：明天先把「粉篓与汤勺（第 1 档）」加上（¥1,500）—— 今天走了 60 位
改后：明天最要紧 · 先把「打通隔墙，多摆两张桌」加上（¥12,000）—— 今天走了 60 位
      街坊愿意来，就别让人家站在门口干等。
```

新增两条缺口（记进账本）：

- **P84**：`lostSampleOf` 的「昨天」只看 `state.days` 末条 —— 若玩家连着几天没开门（或刚换区），末条可能是很久以前的数，红标会一直亮着提醒一件早就不成立的事。可加「末条 `day` 与今天相差 > 3 天就不算」。
