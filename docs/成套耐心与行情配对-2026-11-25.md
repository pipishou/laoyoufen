# 成套耐心、行情配对、前一个月的体面（批 A″/B″/C″）

日期：2026-11-25 · 对标：《The Ramen Sensei》逆向素材 `storeparts.txt` / `storeequip.txt` / `economy.txt`

这一批只做三件事，全部来自上一轮验收列出的三个真缺口：

| 缺口 | 症状 | 本批做法 |
| --- | --- | --- |
| P301 | 六张桌凑齐就白送一个座位，座位又是真瓶颈，替身营收凭空 +21.6% | 成套改成「耐心」，座位必须自己买 |
| P320 | 停水、气价、修路三条纯减益，玩家只能挨着 | 坏日子配一条好消息，另有「借两桶水」可以对冲停水 |
| P325 | 五十一件新事件里有二十六件「怎么选都要掏钱」，头一个月来只能借钱 | 这类事件满一个月才出场，且两次之间隔三周 |

---

## 一、开罗怎么做的（原文）

`storeparts.txt` 34 行，八列 `id / 名字 / 类别 / 贴图 / ? / 套号 / 是否成套件 / 价`。六套内装每套五件，**每件都要钱**（Chic 那套 50 / 100 / 500 / 50 / 150）。`storepattern.txt` 六行只是「套号 → 五件」的索引，不是加成表。

座位不在内装里：`storeequip.txt` 的柜台行是 `0 / 700 / 1750 / 7800`，换 4 / 6 / 8 / 12 位。

也就是说，开罗把「看起来成套」和「真的多坐一个人」分得很清楚 —— 内装管气氛，座位明码标价。前一版本作把这两件事并成一件（凑齐六桌送一个座位），代价是替身立刻学会「不买凳子，去凑桌」。

`economy.txt` 26 行有七对上下（Wallet / Movement / Eating Speed / Flavor / Appeal / Prices / Ingr. Costs 各 Up + Down），每行都带月份窗口 —— 坏行情在开罗里从来不是单独来的。

## 二、A″：成套改成耐心

- `game/src/data/slots.ts`：`SlotSetDef.seats` 整个去掉，换成 `patiencePct`；`room_done`（六张桌）给 `patiencePct: 0.12`。
  - 白话：「桌子摆开六张，桌与桌之间还能侧身过 —— 坐着的人不挤，等的人也不催。」
  - 说清：「多一个人坐还是得多一张凳，那是要另外买的；成套买的是这一口气。」
- `game/src/sim/slots.ts`：`slotSeatTaken` / `claimSlotPrizes` 删除，新增 `slotPatienceMult(state)` 与 `announceSlotSets(state)`（同一套只报一次，写回 `flow.slotsAnnounced`）。
- `game/src/sim/customer.ts`：`patienceScale` 乘上 `slotPatienceMult`。
- `game/src/ui/panels.ts` + `hud.css`：行加 `.setdone` 与金色 `✔`，提示句改成「配齐一类，坐着更松、门口更显眼；多坐一个人还是得另买凳子」。
- AI 落点 26 `set_voice`（`LINE_BUDGET` 330）：凑齐那天的打烊单上，街坊说一句。

**一个反直觉的实测**：把 `patiencePct` 从 0.12 调成 0.08 再跑替身，四种子**逐位不变**（¥107,428 / ¥109,436 / ¥113,718 / ¥112,473）。原因是替身那种局里流失几乎全是「门口站满」，等不及那部分本来就小。所以这条加成在机器玩法里感觉不到，它是给玩家的（等人不催 = 不流失在耐心那一段）。已改回 0.12 与方案一致。

**替身在 A″ 之后反而变好**：¥110,764 · 201.7 碗 · 40% · 期末 ¥551,732（对照上一轮 ¥98,949 / 192.9 / 39% / ¥315,748，营收 +11.9%）。推测机制：不再白送座位，钩子不会误判「座位够了」，替身把钱花在更值的地方。

## 三、B″：坏行情配一条好消息

- `game/src/data/market.ts`：`MarketDef.pair?: MarketId`，只给三条坏行情填 —— `waterCut → payday`（停水那阵正好发薪）、`gasUp → marketRush`（气贵了但街上人多）、`roadWork → schoolOpen`（修路围挡，学生开学照旧）。
- `game/src/sim/market.ts`：`PAIR_WEIGHT = 0.6`，`marketTotals` 四项各算「本条全额 + 配对那条六成」；`pairedMarketOf` 在配对那条不当季时退回 `marketRush`；`marketPairWords` 给一句人话（「借到了水，人还没散」）。
- 对冲件：`game/src/data/goods.ts` 加第十件 `water_bucket`「借两桶水」（人情 4 点，`fixes: "waterCut"`）。借到之后停水的进店惩罚从 −16% 收到 −6%。
  - 出处：手机广西网《南宁多个小区停水 居民：因为停水，楼下餐饮店的生意也受到了影响》`https://v.gxnews.com.cn/a/20244703`。
- AI 落点 27 `market_answer_voice`（`LINE_BUDGET` 340）。

配对的做法与开罗 `economy.txt` 同构（成对上下），但只做了三条 —— 因为**只有这三条找得到南宁出处**，另外几条（气价、修路）的对冲件写不出来源，就没有加（见 P331）。

## 四、C″：前一个月的体面

判据是**算**出来的，不是手写标签（手写会漏标，见 P335）：

```ts
// game/src/sim/events.ts
export function isPressureEvent(def: GameEventDef): boolean {
  const cash = …每条选项的现金效果…;
  if (cash.length === 0) return false;
  if (cash.some((a) => a >= 0)) return false;      // 有免费/进项就不算
  return Math.abs(Math.max(...cash)) >= PRESSURE_COST; // 最便宜那条也要 ≥ ¥100
}
```

按这条算出 **25 件**压迫型（方案里估的是 26 件）。处理三件事：

1. `PRESSURE_MIN_DAY = 30`：满一个月才进池子（与事件自己的 `minDay` 是「与」的关系，第一个版本写成二选一，被测试抓出来）。
2. `PRESSURE_GAP = 21`：两条压迫型之间至少三周。第一版按「上一条事件的类型」算，中间插一件普通事就把间隔清零了（实测出现 14 天间隔），改成记 `lastPressureDay` 才对。
3. HUD 标题加 `⚠` 记号（`.eventtitle.pressure`），玩家点开之前就知道这一件要花钱。

`GameEventDef.kind?: "pressure" | "plain"` 保留成手动覆盖：`plain` 可以把某条从压迫型里摘出来（其实是个机会，只是碰巧每条都要钱），`pressure` 可以硬标。

## 七、这一批带出的新缺口

- **P337**：成套的耐心加成在替身那种「门口站满」的局里无感（0.12 与 0.08 逐位相同），它只对「等不及」那一段流失有效 —— 而那段一直很小。
- **P338**：`announceSlotSets` 只在打烊记账时跑，白天凑齐要等收市才说话。
- **P339**：配对只按当天算，玩家看不到「明天会配哪条」，B″ 的「次日优先」在界面上没有预告。
- **P340**：`water_bucket` 只在停水当天有用，其余日子它在杂货铺里占一行没有理由。
- **P341**：`isPressureEvent` 的 ¥100 门槛是拍的；换成 ¥80 会多出七件，换成 ¥150 会少七件，没有对局证据。
- **P342**：`PRESSURE_GAP = 21` 正好是三个抽取周期（7 天），读起来能对上「隔三期」；但抽取周期一改（比如改成 5 天），这条要重算。
- **P343**：`⚠` 用的是字符而不是图标（图标表里没有对应图形），与 B2 批「页签与面板行首一律用图标」的纪律不一致。
