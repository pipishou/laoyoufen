## 一、开罗怎么做的 / 本作原来怎么做的

开罗那套不用对照 —— 这条不是玩法，是运维。真实对照是「同机多站」这件事本身：一台 ECS 上跑着四个站（`laoyoufen` 老友粉、`x7k2beta` 东方命理、`aimicro` AI 课件、`x7k2preview` 预览）+ 一个目录页，全部由**同一个 nginx** 分派。

原来的做法是「一个站一个 `default.d/*.conf`，让 nginx.conf 里那个内置的 `server { listen 80; server_name _; include default.d/*.conf; }` 兜住所有 Host」。这套在 11-26 之前一直好使。

## 二、坏在哪（三层，缺一层都解释不了现象）

### 第一层：`conf.d` 里的文件比内置 server 先被 include

`/etc/nginx/nginx.conf` 里 `include /etc/nginx/conf.d/*.conf;` 在**第 36 行**，而内置的 `server { listen 80; server_name _; include /etc/nginx/default.d/*.conf; }` 在**第 38 行**。

nginx 的规矩：**同一个 `listen` 上，第一个出现的 server 就是默认 server**（Host 谁也匹配不上时用它）。于是 `conf.d/x7k2-80-redirect.conf`（11-27 20:51 由另一个项目落地）成了 80 端口的默认 server。

### 第二层：那个文件自己就是一台 `return 301`

它的原文是：

```nginx
server {
    listen 80; listen [::]:80;
    server_name 8-134-86-249.sslip.io;
    location ^~ /.well-known/acme-challenge/ { root /usr/share/nginx/html; }
    location / { return 301 https://$host$request_uri; }
}
```

注释里写着「other vhosts keep the default 80 server」—— **这个假设是错的**。它自己成了默认 server，于是**任何 Host 打 80 的任何路径，全部 301 到 https**，包括 `/laoyoufen/`、`/laoyou-api/health`、`/course-08.html`、`/ai-course/`、`/x7k2preview/`、目录页 `/`。

实测确认：`Host: random.invalid` 也是 301 —— 它根本没在看 `server_name`。

### 第三层：443 那台 server 只挂它自己

`conf.d/x7k2beta-ssl.conf` 的注释写得很清楚：「只挂 x7k2beta 自己的 location；不 include 整个 default.d，否则同机 aimicro / laoyoufen 的 location 也会被带到 443 上」，且带 `location / { return 404; }`。

于是流量被 301 赶到 https 之后，落在一台**没有我们的 location** 的 server 上 —— 404。

**三层合起来**：`http://8.134.86.249/laoyoufen/` → 301 → `https://.../laoyoufen/` → 404。而 `/laoyoufen/` 的站点文件、`/etc/nginx/default.d/laoyoufen.conf`、后端 `laoyoufen-api`（`active`、97 局数据在）**全都是好的**。

## 三、三个修法，为什么选 C

| 方案 | 做什么 | 好处 | 代价 |
| --- | --- | --- | --- |
| A | 删掉 `x7k2-80-redirect.conf` | 443 零影响，一行不留 | beta 项目自己的「https-only」意图丢了 |
| B | 在 `x7k2beta-ssl.conf` 里加 `include default.d/{laoyoufen,aimicro,x7k2preview}.conf` | 两个端口都能进 | http 仍全站 301 → 用 IP 打 https 会撞证书告警（证书 SAN 只有 `DNS:8-134-86-249.sslip.io`，**没有 IP**）；等于把四个站都绑到一张 beta 的证书上 |
| **C（已执行）** | **只改 `x7k2-80-redirect.conf` 一个文件** | beta 路径仍强制 https，其余三站 + 目录页回 80 走明文无告警；只碰一个文件，回滚就是换回来 | 80 与 443 两套配置各管一段，日后加站要记得两处 |

C 的终版内容（已在线上）：

```nginx
server {
    listen 80; listen [::]:80;
    server_name 8-134-86-249.sslip.io;

    location ^~ /.well-known/acme-challenge/ { root /usr/share/nginx/html; }
    location ^~ /x7k2beta { return 301 https://$host$request_uri; }

    include /etc/nginx/default.d/laoyoufen.conf;
    include /etc/nginx/default.d/aimicro.conf;
    include /etc/nginx/default.d/x7k2preview.conf;

    location / { root /usr/share/nginx/html; index index.html; }
}
```

**刻意不 include 整个 `default.d`** —— 那会把 `x7k2beta.conf` 里的 location 也带进来，和上面那条 `^~ /x7k2beta` 重复。头部写了 11 行注释讲清「同 listen 取第一个 server 当默认 server」这件事，防下一个项目再踩。

> 过程中我自己引入并修掉一处错误：第一版写了 `location = / { return 301 https://$host/x7k2beta/; }`，把目录页也跳走了。实测 `/ -> 301` 后改成让 `/` 落到 `location /`，回到 200 目录页。

## 七、这一批踩到的三个 PowerShell 5.1 真坑（写在这里省下一次）

### 7.1 改 `.ps1` 必须保住 UTF-8 BOM

`deploy/deploy-cli.ps1` 改完之后 `powershell.exe -File` 报一堆 `标记"&&"不是此版本中的有效语句分隔符` / `语句块或类型定义中缺少右"}"` / 中文全变乱码。

- **真因**：文件原来是 **UTF-8 BOM**（前三个字节 `239,187,191`），我改完写回时丢了 BOM。**PS 5.1 对无 BOM 的 `.ps1` 按系统 ANSI（GBK）解码** ⇒ 中文注释变乱码 ⇒ 语法崩。
- **连带坑**：`[Parser]::ParseFile()` 也按 ANSI 读，它报的 parse errors 全是假的。必须 `[IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)` + `Parser::ParseInput()` 才是真结果（改前改后都是 0 errors）。
- **修法**：`[IO.File]::WriteAllText($p, $txt, (New-Object Text.UTF8Encoding($true)))`。
- 编码现状：`deploy-cli.ps1` / `deploy.ps1` 带 BOM（必须）；`remote-install.sh` / `README.md` 不带 BOM（sh 由 bash 解析，对的）。

> 顺手排除一个误判：here-string 结束符 `"@ 600` 后面跟超时参数，在**赋值形式**下确实非法（`$a = @"..."@ 600` → `Unexpected token '600'`），但在**命令参数形式**下合法（`$inst = RC @"..."@ 600` → 实测超时参数正确收到 600）。原文件本来就对，别去改它。

### 7.2 `Invoke-WebRequest` 判不了 301 和 https

- `-MaximumRedirection 0` 遇到 301 **不返回 Response**，而是抛 `InvalidOperationException`「对象的当前状态使该操作无效」，`Exception.Response` 是 `null` ⇒ catch 只能拿到 `-1`，**301 与「连不上」分不开**。
- `-SkipCertificateCheck` 是 PS 6+ 参数；PS 5.1 默认只开 TLS 1.0，打 https 报 `WebException: 基础连接已经关闭`。
- **正解**：`[System.Net.HttpWebRequest]::Create($url)` + `AllowAutoRedirect = $false` + `ServicePointManager.SecurityProtocol = Tls12` + 需要时 `ServerCertificateValidationCallback = { $true }`（用完置 `$null`）。

### 7.3 变量名不能叫 `$args`

函数内自动变量（参数数组），赋值**静默失效**。这个坑没有报错，只有「值怎么都不对」。
