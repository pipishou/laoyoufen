# 三句提示（批 Q′）· 2026-11-25

> 目的：把界面上「其实已经算出来了、却没告诉玩家」的三件事说出来 —— 明天的行情、门路哪天到期、手艺先点哪一格。
> 起因：P339（行情没有预告）、P303（门路跨零点失效无提示）、P306（手艺页十六格不知先点哪个）。

## 二、改了什么

### 1. 明天的行情（解 P339）

`game/src/sim/market.ts`

- 抽出 `hasMarketAt(month, day, seed)` / `pickMarketAt(month, day, seed)`，哈希串仍是 `${seed}:market:${month}:${day}:has|pick` —— **不碰 `state.rng`**，所以「明天有什么」不会因为多问一次就变。
- 新增 `marketOnDay(state, month, day)`、`tomorrowMarketOf(state)`（`day + 1`，`> 30` 自动翻月）、`tomorrowPairOf(state)`（配那条当月不在季就退回 `PAIR_FALLBACK`）、`tomorrowMarketWords(state)`。

`game/src/ui/hud.ts`

- 行情行：`名字 · 四个数（配…）` + ` · 明天：X（配Y）`。
- `title` 里也带上，鼠标停着能看到细节。

用词纪律：**预告只说名字，不带钱、不带百分比、不带数字。** 理由是开罗 `economy.txt` 也只给窗口不给量 —— 说量等于替玩家算账。

### 2. 门路哪天到期（解 P303）

`game/src/sim/invest.ts`

```ts
export function investDoneToday(state: GameState): InvestDef[] {
  const last = dayIndexOf(state) + 1;
  return INVESTS.filter((def) => state.investments?.[def.id] === last);
}
```

**关键事实（踩过一次）**：`dayIndexOf(state)` 是 `state.days.length`（记账天数），**不是日历日**。`investUntil` 存的是「到期那天」，`investToday` 判的是 `> dayIndexOf`，所以它的**最后一天**是 `dayIndexOf + 1 === until`。第一版按日历日写，测试里 `dayIndex` 恒为 0，`expected 1 to be +0` 直接翻出来。

`game/src/sim/state.ts`

- `DayRecord.investDone?: string[]`；`recordDay` 里在 `announceSlotSets` 之前记一笔。

`game/src/ui/hud.ts` / `hud.css`

- 打烊单 `.daywhy` 加第三个 `<span data-invest-line>`，文案「到点：X、Y 走完了」；前缀 `到点 · ` 走 CSS 伪元素，和「为什么 · 」「菜单 · 」同一套。

### 3. 手艺先点哪格（解 P306）

`game/src/sim/perk.ts`

```ts
const next = rows.filter((r) => !r.owned)
  .sort((a, b) => a.def.cost - b.def.cost || a.def.id.localeCompare(b.def.id))[0];
rec: next?.def.id
```

`game/src/ui/panels.ts` / `hud.css`

- 那一格加 `data-rec="1"`、`title` 前缀「先点这个 · 」、`.pane .pc.rec{outline:2px dashed var(--red)}`。

为什么只按价钱挑：**便宜不等于差，只是最早用得上。** 真按「最优解」排，等于把配点这件事替玩家做了，那四族就没意义了。

## 六、新缺口

- **P345** 预告只给名字不给量。玩家知道「明天停水」，但不知道「停水到底少几成客人」。要不要给量，取决于是否愿意让玩家算账（开罗选择了不给）。
- **P346** `rec` 只按价钱挑。同一族里「便宜但离瓶颈远」和「贵一点但正打在瓶颈上」两种点法，界面都只标前者。
- **P347** `investDone` 只记名字，不记「这一天它到底帮我多做了几碗」。打烊单只能说「走完了」，说不出「值不值」。
- **P348** 预告只覆盖行情，不覆盖段位评定、赛事开赛——那两件的「明天」其实也能算。
- **P349** `.pc.rec` 的红虚线与「现在最缺」的红标同色，同一个面板里两种红。将来要收成「推荐用虚线、紧急用实心」的层级规矩。
