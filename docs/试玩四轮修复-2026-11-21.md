# 试玩第四轮修复：钩子终于看得见「人为什么走」

> 依据：`老友粉试玩总结-2026-11-21.md`（20:02 包，`index-Dr0y6jjr.js` / saveVersion 31）。
> 本轮只改三件事：**走人原因分档**、**钩子按原因点名**、**红标只说一件事**，另加两处观感修（日注、事件卡）。

## 一、这一轮最硬的一条数字

三家（阿兰 / 老韦 / 小陆）第 2、3、4 天早晨各买一档猛火灶 —— 第 1 档 ¥1,500、第 2 档 ¥3,800、第 3 档 ¥9,000，合计 **¥14,300**；
HUD 出碗从 2.0 → 1.7 → 1.4 → 1.2 分/碗，**但卖出的碗数一直停在 31–38，座位一直是 2，日上限一直是 120**。

| 局 | D1 走失 | D2（第 1 档后） | D3（第 2 档后） | D4（第 3 档后） |
|---|---|---|---|---|
| 阿兰 | 46.4% | 58.0% | 61.6% | 60.8% |
| 老韦 | 47.8% | 59.3% | 47.2% | 41.3%（D2 误点陈米，评价 0.5–0.6，不能算干净样本） |
| 小陆 | 45.3% | 60.6% | 60.0% | 54.3% |

结论：**「会买灶」和「买完流失就下去」是两件事**。钩子点名点得够清楚（三家都买了），但它点的那件事当时不是瓶颈。

## 二、根因：钩子只有「产能」一只眼睛

旧钩子判断流失时只看一个数字（走人比例），然后**无条件去 `capacityPick` 里挑设备或扩建**。
可那家店当天实际卖 37 碗、日上限 120 碗 —— 产能根本没被卡住。
真正走人的理由写在三个不同的出口里，而这三处从来只汇总到 `lostToday` 一个计数：

| 出口 | 代码位置 | 玩家的感受 |
|---|---|---|
| 队满（门口已经站着 12 位） | `sim/customer.ts` 的 `arriveOne` | 「挤不进去」 |
| 看价牌（钱包不够买最便宜那款） | 同上 `pickDish` 返回 null 的分支 | 「太贵了」 |
| 等不及（耐心耗尽） | 同上 每分钟结算的过滤 | 「等太久」 |

## 三、改了什么

### 1. 走人的三档分开记（`sim/state.ts` + `sim/customer.ts`）

`CustomerFlow` 加 `lostQueue / lostPrice / lostWait`，三处出口各加一行；`DayRecord` 加三个可选字段，
打烊时写进当日记录 —— **老档没有这三个字段，读出来是 `undefined`，按「没有分档数据」处理，不升存档版本**。

### 2. `lossSplitOf`：谁最多（`sim/bottleneck.ts`）

```ts
export interface LossSplit {
  queue: number; price: number; wait: number; total: number;
  dominant: "queue" | "price" | "wait" | "none";
  priceShare: number;
  live: boolean;
}
```

取数顺序与 `lostSampleOf` 一致：打烊快照 → 今天的实时计数（≥5 人）→ `days` 末条。
和产能模型放在同一个文件里，是因为这两件事回答的是同一个问题：「今天到底卡在哪儿」。

### 3. 钩子先问「为什么走」（`sim/hook.ts`）

- 新增 `HookKind = "price"`。流失 ≥45% 时先看 `lossSplitOf`：
  - **价牌主因** → `把「老友粉」降到 ¥8`，why 写「今天有 44 位是看价牌走的（现在 ¥10）」；
    目标价 = 最便宜那款再降 ¥2，但**不低于成本 +¥1**（压到成本线就压不动了，退回产能那条）。
  - **队满主因** → `capacityPick(state, /* preferSeat */ true)`：先看能不能多坐几个人，
    排队的本质是坐下的人太少。
  - **等不及主因** → 走原来的产能挑选（按每元增益排序）。
- 新增口吻档 `HOOK_VOICE.price` 四句，副行不会再说「灶台」，说价牌：
  「街坊掏钱的时候，手是要停一下的。」「价钱压在人家心口上，味道再好也白搭。」

### 4. 日注按原因分流（`ui/hud.ts` 的 `dayNoteOf`）

上一轮四天三家读到的都是同一句「多半是嫌贵或者等太久」。现在三种：

- 价牌：「走了 50 位：44 位是看价牌掉头的 —— 最便宜那款再低一块试试。」
- 队满：「走了 50 位：45 位是门口站满了没进来 —— 座位和出碗两头看一眼。」
- 等不及：「走了 50 位：24 位是等不及 —— 出碗慢的时候，人站着就烦。」

### 5. 红标只说一件事（`ui/panels.ts`）

上一轮店面和设备两处同时亮「← 现在最缺」，一个指着打通隔墙、一个指着猛火灶。
现在红标跟着当天的钩子走：钩子说座位才标店面，说灶/备料才标设备，说家当才标家当段 —— **一天只有一处红**。

顺手修了「配方页的滚动位置被店铺页接下来用」：换页签时把该页滚动归零。
上一轮阿兰第 2 天、小陆第 3 天早晨第一次打开店铺都落在杂项区，红字根本不在视野里。

### 6. 事件卡不再把生成方式写给玩家看（`ui/hud.ts`）

三局第 2 天的「今日突发」选项上方漏出浅灰小字「AI 导演 · 离线模板」。
现在本地句写「街上听来的」，在线句写「刚在巷口听人说」——说的是同一件事，但不解释后台。

## 六、缺口（本轮发现、没做）

- **P144**：门口站满时若「扩座」被段位锁住，`preferSeat` 只能退回推灶 —— 钩子应该说「先评段位解锁扩座」，而不是继续催灶。
- **P145**：看价牌走的人里，有多少是「钱包不够」（真买不起）与「觉得不值」（预算够但嫌贵）没分开；现在一律算价牌，压价可能压错。
- **P146**：走人原因只在打烊单与店铺红标上可见，HUD 的客流胶囊仍是单一数字 —— 白天看不出「现在走的人是嫌贵还是等不及」。
- 上一轮遗留 P142（AI 空句率无度量）、P143（锦旗/祖师像缺出处）未动。
