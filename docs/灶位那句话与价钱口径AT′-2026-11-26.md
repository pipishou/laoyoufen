# 灶位那句话只有一个出处，价钱句报技能与一次性介绍费（批 AT′）

> 2026-11-26 · 解 **P461 / P462 / P463**（批 AS′ 顺手记下的三条）。
> 一句话总结：**同一个事实不再写两遍；价钱句从此报「技能几级」和「介绍费只收一次」。**
> 本批只动说法与挑选口径，`serveMinutes` / `cookSlots` / 座位与来客公式**一格没动**，替身四种子逐位相同。

## 一、这三条为什么是一件事

批 AS′ 把「灶位缺口」这段话从一句扩成三层（主句 / 副句 / 价钱句）之后，露出三个问题：

| 缺口 | 现象 | 玩家会怎么误读 |
| --- | --- | --- |
| **P461** | 价钱句只报**最便宜**那个煮粉 | 「谁便宜雇谁」→ 雇到技能最弱的，灶还是开不快 |
| **P462** | 打烊单一句、店面页一句、店员页又一句，字不同 | 三处说法明天就会走样（P451「卖不动」复发过一次） |
| **P463** | 「介绍费 ¥300」没说收几次 | 当成月费算账，以为雇人成本是日薪 + 月费 |

三条都落在「补一个人」这件事上，所以一批做完。

## 二、P461：日薪与技能是绑死的，「最便宜」等于「最弱」

### 实证（临时脚本，跑完已删）

`probe(tag, seats, stoves, skills)` 打印 `cookSlots / serveParallel / inNoodlesNum / serveMultiplier / 每批分钟 / 日灶碗`：

| 配置 | `serveParallel` | `serveMultiplier` | 每批分钟 | 日灶碗量 |
| --- | --- | --- | --- | --- |
| 2 灶 · 无人 | 3 | 1.000 | 0.333 | 360 |
| 2 灶 · 1 人 skill 1 | 6 | 0.955 | 0.159 | 754 |
| 2 灶 · 1 人 skill 5 | 6 | 0.775 | 0.129 | 929 |
| 2 灶 · 2 人 skill 1+1 | 6 | 0.910 | — | 791 |
| 2 灶 · 2 人 skill 5+5 | 6 | 0.550 | — | 1200 |
| 4 灶 · 3 人 skill 5×3 | 12 | 0.450 | — | 1200 |

**技能确实改产能**：`serveMultiplier` 的煮技那一项是 `1 - min(0.55, 技能 × 0.045)`（`game/src/sim/staff.ts`）。
但日薪由技能定（`WAGE_BY_SKILL = [110, 130, 150, 180, 220]`，`game/src/data/staff.ts`），
所以「挑最便宜」就是「挑最弱」—— 玩家看不出这件事，是因为界面上从来只有价钱、没有技能。

### 改法

`game/src/sim/crew.ts` 的挑人口径从「日薪最低」改成 **「每一块钱技能最高」**：

```ts
const cooks = state.staff.candidates.filter((m) => m.role === "cook");
const cand = cooks
  .slice()
  .sort((a, b) => b.skill / Math.max(1, b.wage) - a.skill / Math.max(1, a.wage) || a.wage - b.wage)[0];
```

`CrewHire` 加 `skill: number`，价钱句改成：

```
今天有人来问工：阿强（技能 3）日薪 ¥150 · 介绍费 ¥300（一次）· 月薪约 ¥3,262
```

判据（`game/src/sim/crew.test.ts`）：摆一个「阿弱 skill 1 ¥110」和一个「阿强 skill 5 ¥220」，
必须挑阿强、`hire.skill === 5`、`cost` 含「技能 5」。

## 三、P462：那句话只许有一个出处

### 新建 `game/src/data/crew.ts`

跟批 AQ′ 的 `data/demand.ts` 同一个套路 —— **核心那一截只写一次**：

```ts
/** 核心那一截：第 N 口起没人看（长句短句共用） */
function gapCore(slots: number): string {
  return `第 ${slots + 1} 口起没人看`;
}

export function crewGapWords(stoves: number, slots: number, short = false): string {
  const head = short
    ? `灶 ${stoves} 口，只有 ${slots} 个人掌勺`
    : `灶位 ${stoves} 口，眼下只有 ${slots} 个人掌勺`;
  return short ? `${head} —— ${gapCore(slots)}` : `${head} —— ${gapCore(slots)}，火开不起来`;
}

export function crewFitWords(stoves: number, slots: number): string {
  return `灶位 ${stoves} 口，能开火 ${slots} 口 —— 人手够，每一口灶都烧得上`;
}
```

- 长句给店面页 / 店员页（`words`），短句给打烊单（`brief`）—— 打烊单那一行只占一行（P406 折行）；
- 两句的头不同（`灶位 N 口` / `灶 N 口`）、尾巴不同（长句多「，火开不起来」），
  但**「第 N 口起没人看」这一截只有一处**：改口径只改 `gapCore`；
- 数字由调用方传，模板不管数值 —— 数字永远来自确定性模拟（AGENTS.md 三、数值纪律）。

### 新建 `game/tools/crew-literal.test.ts`（5 例，扫源码）

放在 `tools/` 而不是 `src/`：要 `node:fs`，本仓没装 `@types/node`，`tsc` 盯 `src` 会报 TS2591
（`demand-literal.test.ts` 踩过同一个坑）。

五条判据：

1. 「口起没人看」与「每一口灶都烧得上」**不许**出现在 `src/data/crew.ts` 之外（剥掉注释再判，注释里写字不算抄）；
2. 短句与长句**共用同一个核心**：两句都含 `—— 第 2 口起没人看`，只有长句带「，火开不起来」；
3. 数字由调用方给：`crewGapWords(4, 2, true) === "灶 4 口，只有 2 个人掌勺 —— 第 3 口起没人看"`；
4. 三句都不匹配 `/¥|元|买|推荐|建议|划算/`（价钱只在 `cost`）；
5. `hud.css` 里有 `[data-crew-line]::before{content:"灶位 · "}`（打烊单那一行确实存在）。

> **踩到的坑**：第一版第 2 条写的是 `expect(long.startsWith(short)).toBe(true)` ——
> 短句头是 `灶 3 口，只有 1 个人掌勺`、长句头是 `灶位 3 口，眼下只有 1 个人掌勺`，
> 短句不是长句的前缀，首跑红。改成「两句都含同一截核心」才是这条判据真正想说的话。

## 四、P463：介绍费只收一次，写在字里

原来的文案是「日薪 ¥150 · 介绍费 ¥300 · 月薪约 ¥3,262」——
「月薪约」紧跟「介绍费」，玩家很自然把 ¥300 按月算一遍。

改成：

```
日薪 ¥150 · 介绍费 ¥300（一次）· 月薪约 ¥3,262
```

`fee` 的语义在 `CrewHire` 的注释里也写死了：**`fee = wage × HIRE_FEE_RATE`，一次性**。

## 八、新缺口

- **P465**：`crewGapWords` 的头两句（`灶位 N 口` / `灶 N 口`）仍是两段手写，只共用了核心那一截；若要连头也同源，得再拆一层参数。
- **P466**：「每一块钱技能最高」是拍的排序，没算「雇他到底多卖几碗」—— 因为实测（批 AS′ 十二格）雇人最多多卖 0.6 碗，算 ROI 只会得出「一个都别雇」。这句口径哪天厨房真成闸，就要重算。
- **P467**：`crew-literal.test.ts` 只盯「口起没人看 / 每一口灶都烧得上」两句；`why` 与 `cost` 那两句仍是 `sim/crew.ts` 里手写的，与 P451 同型，只是还没抄第二遍。
- **P468**：探针 `rich_*` 四条都留了「今天没有煮粉的来问工」这个例外分支（P464 的延续），候选池为空时四条一起放行，仍是弱判据。
