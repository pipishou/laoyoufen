## 二、四处改动

1. **「为什么」那行给形态，不给模板**（`game/src/sim/advice.ts`）
   - 队满：`今天 12 位站在门口没进来：2 张桌，一碗占 6 分钟，一天最多接得住 30 碗。`
   - 看价牌：`今天 9 位看了价牌就走：最便宜那款 ¥10，街坊掏钱时手会停一下。`
   - 等不及：`今天 6 位等不及：一碗要 2.2 分钟，站着的人没那么多耐性。`
   - 数字全部本地算**（AI 只补口气，不许改数字——服务端正则仍在）。`ask.key` 跟着带参：`queue:2:30` / `price:10` / `wait:2.2`，同一天同一个形态才复用同一句。
2. **日注不再和它重复**（`game/src/ui/hud.ts` 的 `dayNoteOf`）
   - 原：`走了 37 位：29 位是门口站满了没进来 —— 座位和出碗两头看一眼。`
   - 新：`走了 37 位：29 位是门口站满了没进来。`（「为什么」那行说为什么，日注只说走了多少）
3. **左下角读模拟，不写死 6.0**（`game/src/sim/customer.ts` + `game/src/ui/hud.ts`）
   - `CustomerFlow` 加可选 `serveInterval?: number`（**不升版本，仍 36**），每轮出碗时把这一轮的间隔写进去；
   - HUD：`const bowlSpan = Math.max(0.4, s.flow.serveInterval ?? SERVE_MINUTES * serveMultiplier(s));`
   - 于是买灶、买汤锅之后，左下角那个数字和右侧座位行说的是同一件事。
4. **副行不再一字不差**（`game/src/sim/hook.ts` + `game/src/main.ts` + `game/src/ui/hud.ts`）
   ```ts
   export function hookVoiceKeyFor(plan: HookPlan, day: number): string {
     if (plan.kind === "none") return "none";
     return `${plan.key}#d${((Math.max(1, day) - 1) % 3) + 1}`;
   }
   ```
   取模三份：相邻两天必不同，第四天回到第一份；键空间只放大三倍（预算仍有余量）。
   顺带把卡座位时的红标挪到「店里 · 家当」段（矮凳摆在那里）：
   ```ts
   const gearHot =
     (hotPlan?.kind === "gear" && gearEfficiencyLeft(s).length > 0) ||
     (hotPlan?.kind === "capacity" && hotPlan.key === "capacity:seat");
   ```

## 六、新缺口

- **P267** 副行只取模三份，七天里仍会重复两次；真正的不重样要靠内容层多写几句（方案二的「内容层」还没做）。
- **P268** 「为什么」给的是形态（几张桌、一天接得住几碗），没给「加一张桌几天回本」——玩家算不出该不该买。
- **P269** 左下角虽然跟设备变了，但只在「等客落座」时显示；炒料与盛装那两句仍不含时间，忙着的时候看不到自己的速度。
- **P270** 卡座时红标挪到「家当」段，可没进过那一段的玩家不知道矮凳在哪（没有指路文案）。
- **P271** 报告第 5 条的视觉层级（红标、最慢、评定三行都在抢眼）整块没动，要单独一批重排店铺页。
