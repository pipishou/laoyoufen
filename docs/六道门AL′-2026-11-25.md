## 二、这一批做出来的东西

### 1. 帧差回归门（补 P417 缺的那一半）

`eye_gate` 只看「色数」和「stamp 条数」——它挡不住「色数一个没变但整块挪了」。新门补的是逐点比对：

- 状态钉死（`PIN` 脚本）：`phase="prep"`、month 3 / day 12、cash 30000、reputation 62、price 10、totalCustomers 420、minuteOfDay 480、servedToday 7、lostToday 3、revenueToday 70、`customers=[]`、`dayReport=null`、seats 6、stoves 2、gradeLevel 1、shopName「老友粉店」，然后 `window.__laoyou.refresh()`。
- 只截 `.pane[data-pane='shop']` 这一个元素（不截会动的 canvas），三个视口 375×667 / 768×1024 / 1440×900。
- `--save-baseline` 存基准到 `game/data/evidence/framediff/baseline/`；不带参数就是比对；`--allow "x,y,w,h"` 可以把「本来就该动的那一块」圈出来。
- **首跑就逮到一件真事**：同一份代码两次截图差 1269–5293 px，差异区域是**开局那条 toast 上的店名**——它是开局随机取的（`game/src/data/shop-names.ts` 里有「秀灵」「中山路」这些），任何截图门都会被它搞成飘的。修法写进 PIN：清空并隐藏 `#toasts`。此后三个视口**逐点相同（0 px）**。

**怎么算做完**：`python -X utf8 tools/gate/framediff_probe.py --url http://localhost:4246/` 输出三个 `ok ... 总变化 0 px`。

### 2. 长跑试玩门（并把 P429 修掉）

从 `autoplay_probe.py` 硬化而来，复用它的 `__gameState` / `__autoplay` 注入，判据九条：

```
hud_alive / days_reached(≥20) / phase_playing / fps_min(≥30) / fps_avg(≥45)
errors_clean / http_only_api / api_budget / heap_bounded(≤0.6)
```

两个设计上的坑，都写进代码注释了：

- **`phase` 不是 `playing` 不算掉出去**：`__gameState` 在报账单挂着时按契约返回 `"won"`，那是每天打烊那一拍。改成「连续 40 拍（约 4 秒）都不是 playing」才算卡住。
- **4xx 不是零容忍**：预览环境压根没有 `/laoyou-api/`，判据是「4xx 只许出现在 `/laoyou-api/` 下」，`ERROR_ALLOW` 白名单是给 console error 用的。

首跑（修 P429 之前）5 分钟到第 37 天，fps 55/60，堆增长 0.0，**4xx 389 条**——全是 `/laoyou-api/line`，平均 **10.5 次/游戏日**。根因不是探针，是游戏：`game/src/ai/lines.ts` 的 `fetchLine` 失败后**不缓存、不退避**，服务端一挂就每句都发、每句吃满 800ms 超时。

**P429 的修法**（同一批做掉，不给下批留）：指数退避。`FAIL_BASE_MS = 60s`、`FAIL_MAX_MS = 10min`，连败翻倍，封顶六次；成功一次清零；`resetLines()` 一并清退避。四处失败（`!res.ok`、`body` 不是字符串、`isCleanLine` 不过、`catch`）都记账。

修完复跑：**同一个 5 分钟、同样第 37 天**，一句话接口 **7 次（0.19 次/天）**，console error **389 → 18**，九条判据全绿。

**怎么算做完**：`playthrough_gate.py --minutes 5` 九条全 `ok`，且 `一句话接口` 那行 ≤ 3 次/天。

### 3. 存档篡改五路（补 P436 / P437 两条真缺口）

`game/src/sim/save-tamper.test.ts` 五例，测的是「玩家直接改 localStorage 会怎样」：

| 路 | 结果 |
| --- | --- |
| 类型翻转（cash 变字符串、price 变 null、`"[]"`、`"not json"`、空串） | 全部 `null`（拒收），不会半读进来 |
| 负数极端值（seats −5、cash −1e12、price 0） | **收下了**，但 `assertPlayable()` 证明推 12 分钟不出 NaN/负库存 → 记为 **P436** |
| 未知 id（`perks: {hack_all_might: 1}`） | 收下但不生效（`perkTasteCap` 仍是 2） |
| 跨档复制（换 `playerId`/`shopName` 能读；`saveVersion: 38` 与 `"37"` 拒收） | 版本号是硬的 |
| 超长串（shopName 4000 字、2000 个假浇头） | **收下了**，没有长度上限 → 记为 **P437** |

**顺手修的真问题**：v36→v37 的迁移原来只按值过滤（`v === 1 || v === true`），手改出来的 `{bad: true}` 会一路跟着存档走。改成「值合法 **且** `perkById(id)` 认得这个 id」才收。这条不是新增约束，是补上原来漏的那一半。

### 4. 飘测试记账（`docs/FLAKY.md`）

不是门，是账：一张表五条（并行假红、cooldown 用 reset 当时间、折叠状态跨 refresh 残留、帧差被随机店名搞飘、`eye_gate` 清证据），外加三条「会被误当成飘的」——`phase` 契约、`/laoyou-api/` 的 4xx、四种子逐位相同。

规矩写死在里面：**不许靠重跑过关**；要「等」用 `vi.useFakeTimers()`。

### 5. 发布包调试出口门

扫 `game/dist/assets/*.js`：只允许白名单里的 `window.__` 出口（`__laoyou` / `__gameState` / `__autoplay` / `__probeReady`），不许有 `debugger`，不许出现 `localhost` / `127.0.0.1`。

现状：**只挂了 `__laoyou` 一个**，其余三条干净。报告落在 `game/data/evidence/debug-exit/report.json`。

### 6. 内容条数双向对账（替掉早已失真的 `count_entries.py` 正则）

`tools/gate/count_entries.py` 用正则数，实测早就失真：事件 0、手艺 0、地名 0、手册 12（真值 16）、长对白 66（真值 60）。改成读**权威出口**：

- `game/tools/entry-counts.rows.ts`：能读 `*_TOTAL` 就读它，读不到才数数组长度；43 项，键名给人看。
- `game/tools/entry-counts.gen.ts`：写 `game/data/entry-counts.json`（跟 `server-events.gen.ts` 同一个范式，`gen:server` 一起跑）。
- `game/tools/entry-counts.test.ts`：**只读对账**，`npm test` 里跑，一处不同就红并点名（连同「清单里不写 0、不写小数」）。

清单首版 43 项，其中最该被人记住的几个数：事件 **83**、浇头 **21**、加菜 **13**、手册 **16**、长对白 **60 句**（6 类）、手艺 **16 项 / 64 点**、店员手艺 **21 + 毕业技 6**、成套 **6**、铺面 **5 档 / 扩建 4 档**。

## 四、这一批没动的

- **P70（先点产能还是先点座位）** 仍开：`capacityGain().seat(1)` 在开局 4 座时是 0，钩子永远先点设备；试玩报告第 4 天纯灶对照（流失 50.0% vs 加凳 33.7%）说明先点凳才对。动它四种子必然变，要单开一批。

## 五、新缺口

- **P438** 帧差门只截店铺页一屏 —— 配方页、员工页、打烊单这些没钉状态，画面挪了也看不见。

- **P442** 帧差基准是「上一次存的」，改文案后要人记得重存 —— 没有「基准该更新了」的提示（与 P412 同型：状态不出机器）。
