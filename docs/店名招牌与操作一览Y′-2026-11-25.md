## 一、开罗怎么放这两件事

| 开罗的表 | 里面是什么 | 我们的做法 |
| --- | --- | --- |
| `custom.txt`（4 类 × 5 级） | 可以定制的四类东西，每类五级外观 | 只取「店名」这一类：名字是认领感最强、又不烧美术产线的那一个 |
| `softkey.txt`（63 行） | 手柄每个键干什么，逐条列出 | 手册「怎么操作」一章四页 + 设置弹窗里的「操作一览」 |
| `help.txt`（57 节） | 说明分散在各处，随手能翻 | 设置弹窗直接摊开四行，不用先进图鉴再翻手册 |
| `storeparts.txt` / `custom` 的贴图层 | 门脸贴图随定制换 | **不照搬**：没有招牌贴图产线，硬做只会得到四张糊的图 |

结论：开罗的「定制」是**外观层级**，我们的「定制」是**名字 + 一句说明**。层级砍掉，认领感留住。

## 二、换招牌

### 1. 一条命令

`game/src/sim/setup.ts` 新增：

```ts
export function renameShop(state: GameState, raw: string): RenameResult {
  if (state.phase === "setup") return { ok: false, line: "", reason: "还没开张" };
  const name = raw.trim();
  if (name === state.shopName) return { ok: false, line: "", reason: "还叫这个" };
  if (!validShopName(name)) return { ok: false, line: "", reason: "店名要 2–12 个字" };
  state.shopName = name;
  return { ok: true, line: `招牌换了：${name}`, reason: "" };
}
```

- 复用建店仪式那条**同一个校验**（`validShopName`：两个字到十二个字、只收汉字字母数字与 `· - （ ）`），
  所以开张能起的名字，之后改名也能用；开张起不了的，改名也起不了。
- 不碰 `SAVE_VERSION`：`state.shopName` 本来就在存档里（`game/src/sim/state.ts:606`），
  改名只是把它从「建店那一刻写一次」变成「随时能写」。

### 2. 界面：店铺页顶上那一行

`game/src/ui/panels.ts` 的 `shopHtml` 顶部加一块 `nameBox`：

```html
<div class="shopname" data-shopname-box>
  <label title="开张之后也能改，两个字到十二个字"><span>招牌</span><input maxlength="12" data-rename-shop value="…"></label>
  <span class="tag2">换名字不改任何数，只是街坊改口</span>
</div>
```

- 事件走已有的 `change` 监听（`panels.ts:560`）：`else if (el.hasAttribute("data-rename-shop")) actions.renameShop(el.value);`
  —— 用 `change` 不用 `input`，理由和菜单改名一样：每敲一个字重渲染会吞光标。
- 顶栏那个名字是 `hud.ts` 的 `[data-shopname]`，改名后 `refresh()` 一次就跟着换；
  面板里那个容器特意叫 `data-shopname-box`，**不跟顶栏抢同一个选择器**（第一版抢了，探针取到的是顶栏那个 div）。
- 只填一个字会被退回，toast 原文「店名要 2–12 个字」——只说字数区间，不说「非法」。

## 三、手册从十二页到十六页

`game/src/data/manual.ts` 加一章「怎么操作」，四页：

| id | 标题 | 讲什么 | 指到哪 |
| --- | --- | --- | --- |
| `m.how-order` | 怎么点一碗 | 配方页挑三样；改配方下一碗生效；份量二两三两 | `sim/menu.ts · sim/dish.ts 的 dishName` |
| `m.how-serve` | 怎么把碗端出去 | 炉子亮着自己走；托盘数字是这批几碗；灶眼与座位两头 | `sim/customer.ts 的 serveBank · sim/bottleneck.ts 的 capacityOf` |
| `m.how-tabs` | 面板上那七个页签 | 七个页签各管什么；页签多时可横划 | `data/perk.ts 的 PERKS · sim/perk.ts 的 perkViews` |
| `m.how-prefs` | 设置与存档 | 六项设置不进存档；存档自动，一天写一次 | `sim/save.ts 的 serialize · data/manual.ts` |

- `MANUAL_TOTAL` 由 12 变 **16**，分章由四变五。
- 纪律照旧：正文与 gist **不写阿拉伯数字**（手册讲道理，不报数）；`where` 必须以 `data/` 或 `sim/` 开头，能被 grep 到。
  —— 第一版 `m.how-tabs` 写的是 `ui/panels.ts 的 TABS · data/perk.ts`、`m.how-prefs` 写的是 `ui/prefs.ts · sim/save.ts`，
  两条都被 `manual.test.ts` 的 `where` 断言拦下，改成以 `data/` / `sim/` 开头才过。
- `m.how-tabs` 正文里原来写「这十二页手册」，随页数改了「这十六页手册」——**页数一变，正文里提到页数的句子要一起改**。

- 数据**不另写一份**：`manualSections().find((g) => g.section === "怎么操作")?.pages` 直接取手册那一章。

## 六、这一批留下的缺口

- **P384** 招牌只有字，没有门脸可换。开罗的定制是外观层级（`custom.txt` 四类五级），我们只有名字与一句说明；
  想换招牌灯箱、旧木牌那一层，得有招牌贴图产线。
- **P385** 改名之后旧报道跟着变。`game/src/sim/news.ts:58` 与 `:98` 是拿 `state.shopName` **现算**的，
  所以上个月的街坊报里也印着新名字 —— 现实里老报纸不会改口。
- **P386** 设置里的「操作一览」是手册那一章的副本。手册改一句这里跟着变，但两处的**排版与截断**是两份
  （设置弹窗窄，长 gist 会换行到三行）—— 与 P344「游戏内容与服务端副本会走散」同型。
- **P387** 十六页手册仍是平面清单，没有「读没读过」的标记。开罗的 `help.txt` 至少按场景分组（开店前 / 经营中 / 比赛）；
  我们只有 `▸` 折叠，谁也不知道哪一页还没看。
- **P388** 改名不进存档摘要与试玩回执。`downloadPlaytest` 里记的是天数、营收、碗数，名字改了之后对不上「谁家的档」。
