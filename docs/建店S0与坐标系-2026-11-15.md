# 建店（S0）与「钱 / 老友粉」坐标系 · 2026-11-15

## 0. 三句结论

1. **六阶的第一阶已经能玩了**：全新存档不再直接开门，而是停在「开张」——挑铺位、起店名、付转让费，之后才进「准备」，再点「开门营业」时钟才走（四态 `setup → prep → open → closing`）。
2. **钱有了统一的尺子**：新增 `game/src/data/anchors.ts`，任何新数值先过「几碗 → 几个月营收 → 几小时工资」三关才许落成元；段位费按这把尺子重定为 ¥500→¥120,000（合计 **¥33.3 万**，约三年营收 1/3），旧表 ¥50→¥20,000 等于三个月买通全部段位。
3. **仍然是「可玩但不耐玩」**：S1（第一碗）之后，S2 招人 / S3 布置 / S4 设备 / S5 扩建 / S6 分店还没做，中期依旧没有新动词——账本 P24 不变。

## 1. 这一轮落地的状态机

| 状态 | 谁能进 | 时间 | 玩家能做什么 |
|---|---|---|---|
| `setup` | 全新存档 | **冻结** | 选铺位（3 档）、起店名（5 候选 / 可换一批）、看现金与月租 |
| `prep` | 开张后 / 日结确认后 | 冻结 | 调配方、定价、雇人、看账本；点「开门营业」 |
| `open` | 点开门 | 120 分钟/天 | 卖粉、看顾客钱包、被事件打断 |
| `closing` | 走完一天 | 冻结 | 看日结单，点「明天继续」 |

代码落点：`sim/state.ts`（`Phase` / `GameState.site` / `GameState.shopName` / `openShop` / `ackDayReport` / `tickMinute`）、`sim/setup.ts`（`openForBusiness` / `canTakeSite` / `rentFactorOf`）、`ui/setup.ts` + `ui/setup.css`、`main.ts`（`setupScreen.render(state)` 接进 `refresh()`）。

存档 `SAVE_VERSION 7 → 8`：v5–v7 老档照读，`site` 补 `"alley"`、`shopName` 补「老友粉店」，**不把老玩家踢回建店**；只有全新存档才从 `setup` 开始。

## 2. 三档铺位（数字怎么来的）

| 铺位 | 转让费 | 折成碗 | 座位 | 灶 | 日上限 | 月租 | 月租折成碗 |
|---|---|---|---|---|---|---|---|
| 街边摊 | ¥0 | 0 碗 | 2 | 1 | 120 | ¥2,772 | 277 碗 |
| 巷内小店 | ¥15,000 | 1,500 碗 | 4 | 1 | 200 | ¥4,620 | 462 碗 |
| 临街铺面 | ¥28,000 | 2,800 碗 | 6 | 2 | 260 | ¥6,468 | 647 碗 |

- 起始现金 `GUANGXI.startCashYuan = ¥30,000`（现实下限：押金＋简装＋首批原料）。
- 转让费按「拿走起始现金的 0% / 50% / 93%」定 —— 三种开局都是**现金取舍**，不是难度选项：选临街铺你会剩 ¥2,000，但六张桌的产能上限更高。
- 月租 = `rentFor(月目标) × 铺位系数`（0.6 / 1.0 / 1.4），系数 1.0 对齐现实临街小铺 ¥4,500/月。
- 座位与灶台在**选址时**就给到，不是后续买升级 —— 现实里看铺面时你就知道能摆几张桌。

## 3. 坐标系（`data/anchors.ts`）

三把尺子：

| 尺子 | 定义 | 例子 |
|---|---|---|
| 碗 | 1 碗 = 售价 ¥10（成本 ¥4.2、毛利 ¥5.8） | 灶最贵一档 ¥30,000 = **3,000 碗** |
| 月营收 | 70 碗/日 × 30 天 = **¥21,000** | 临街铺转让费 = **5.7 个月营收** |
| 工时 | 南宁最低工资 ¥1,990/月 ÷ 21.75 天 ÷ 8 小时 ≈ **¥11.4/小时** | 一个帮工月薪 ¥3,800 ≈ 333 小时 |

规则（写进代码注释，也写进账本）：**新数值先过三关，再写成元**。开罗的 KCU 只允许通过 `kcuToYuan()` 解释「开罗原值」，**禁止**把开罗价直接搬进本作账本——开罗一碗约 1,000 KCU，我们一碗 ¥10，直折会把门槛折成零头。

资本阶梯（后续 S3–S6 的价格表，先写死在这里）：

| 项 | 四档 | 折成碗 |
|---|---|---|
| 布置（整套风格 5 部件） | ¥3,000 / ¥4,500 / ¥6,000 / ¥8,000 | 300–800 碗 |
| 设备（灶 / 粉篓 / 案台，各四档） | ¥1,500 / ¥3,800 / ¥9,000 / ¥30,000 | 150–3,000 碗 |
| 扩建 | ¥12,000 / ¥35,000 | 1,200 / 3,500 碗 |
| 区县转让费 | ¥0 – ¥120,000 | 0–12,000 碗 |
| 段位审查 | ¥500 → ¥120,000（11 级） | 合计 ¥33.3 万 |

自检断言（`sim/setup.test.ts`）：段位费合计 333,000、占三年营收 30%–55%；资本品总量与段位费同阶（不是零头）。

## 5. 与开罗的对照

| 开罗 | 本作 | 差异说明 |
|---|---|---|
| `store_data.txt` 四档店（购店 3/5/10/15 万 KCU，月租 5,000–50,000） | 三档铺位（转让费 ¥0 / ¥15,000 / ¥28,000） | 开罗第四档是三年后的事；本作压成三档，取舍更早出现 |
| Game Flow 1：先做出能卖的一碗，才开始营业 | S0 建店 → S1 配方/定价 → 开门 | 一致；本作把「先建店」显式化 |
| 自动循环、没有手动开关店 | 手动「开门营业」 | **故意不同**：玩家反馈「一进来就在营业」不好，我们需要一个「准备好了吗」的停顿 |
| grade_review 11 级，费 5,000→2,000,000 KCU | 11 级，¥500→¥120,000（合计 ¥33.3 万） | 形状照搬，量级按本作月营收重定（开罗直折会变零头） |

## 6. 已知缺口

1. **S2–S6 未做**：招人、布置、设备、扩建、分店仍走旧的 `shop.ts` 六件升级（合计 <¥7,500），`anchors.ts` 里的价格表还没有消费方。
2. **段位有层没门**：`applyGrade()` 仍零 UI 调用（账本 P21 / 验收 B6 △）——本轮只改了费表，没加评定入口。
3. **区县未接线**：`data/nanning.ts` 的 12 区县数据齐，`tally.districts` 仍只有兴宁（B9 △）。
4. **店名还没被 AI 改写**：`nameCandidates()` 纯本地确定性生成；接 `POST /event` 让 AI 出一批南宁口吻候选是下一步（失败回落本地，不影响玩）。
