# 换个人到底多卖几碗：那句话改由模型算（批 AV′，P469 / P470 / P471）

> 2026-11-26 · 本批只动「怎么说」，不动任何经济数值。四种子逐位不变是判据。

## 一、这一批要解决什么

批 AU′ 给价钱句加了一句前提：「（不过今天厨房不是最紧那道，换个人也换不来更多的碗）」。
这句话**是一句量化断言**，可它的判据只是一个布尔：`capacityOf().tight === "stove"`。

三处由此长出来：

| 缺口 | 现象 |
|---|---|
| **P469** | 「灶不是最紧那道」推不出「换人不多卖」。哪天有人调 `FLOW.serveMinutes`、并行槽、区客流，这句话会变成假话，而没有任何东西会红。 |
| **P470** | 同一个 bool 把「差一点」和「差很远」压成一句。多卖 5 碗和多卖 30 碗说的是同一句「补齐人手这口灶才烧得上」。 |
| **P471** | `crewCostWords(hire, kitchenBinds = true)` 的第二参数有默认值 —— 调用方忘传，前提被静默吞掉，玩家看到一句不带前提的报价。 |

## 二、改法：让模型自己算「多一个人掌勺」

`game/src/sim/bottleneck.ts` 新增：

```ts
export function capacityWithCooks(state: GameState, extra: number): Capacity {
  const now = capacityOf(state);
  const stoves = Math.max(1, state.venue.stoves);
  const slots = Math.max(1, cookSlots(state));
  const want = Math.max(1, slots + Math.max(0, Math.floor(extra)));
  // 一锅几份（inNoodlesNum）两边同时出现，约掉了 —— 只留「能同时开几口灶」之比
  const ratio = Math.max(1, Math.min(stoves, want)) / Math.max(1, Math.min(stoves, slots));
  const raw = bowlMinutes(state, FLOW.serveMinutes, stationServeFactor(state));
  const stove = DAY_MINUTES / Math.max(0.2, raw / ratio);
  return pack(stove, now.seats, now.cap, now.demand, now.serveNow);
}
```

口径与 `capacityOf` 完全一致：`bowlMinutes ∝ 1 / 并行槽`，多一个掌勺的人等于把出碗间隔
除以「并行槽比」；并行槽 = `min(灶位数, 能掌勺的人数) × 一锅几份` —— 一口灶时多雇人
不会多开火（`min` 卡住），这正是实测「1 灶雇人一碗不多」的由来。

`game/src/sim/crew.ts` 于是：

```ts
const now = capacityOf(state);
const kitchenBinds = now.tight === "stove";
const cookGain = capacityWithCooks(state, 1).total - now.total;
const cookAddsBowls = cookGain > COOK_GAIN_NOISE;   // 半碗以内算噪声
```

`CrewFacts` 多一个 `cookGain`（面板不显示，留给测试与探针读）。

## 三、三句话跟着改

| 句子 | 判据 | 现在的样子 |
|---|---|---|
| 副句 `crewWhyWords(kitchenBinds, cookGain)` | 灶是不是闸 + 这口火值几碗 | 卡的就是灶：`今天卡的就是灶 —— 补齐人手这口灶才烧得上（多一个人约多卖 5 碗）。`；不卡：`不过今天卡的不是灶：座位和街上的人先顶着天花板，多开一口火也不会多卖。` |
| 价钱句 `crewCostWords(hire, cookAddsBowls)` | `cookGain > 0.5` | 第二参数**没有默认值**（P471），由类型系统挡住忘传；`cookAddsBowls === false` 时才接前提 |
| 噪声线 `COOK_GAIN_NOISE` | —— | `0.5`：只用来挡 `min(...)` 除法链的浮点抖动，不承担任何「划不划算」的判断；导出给测试用同一把尺 |

那 5 碗不是拍的：`FLOW.serveMinutes = 6`、4 座 2 灶、一个掌勺的人 —— 灶项 60 碗，
多一个人 `min(2,2)` 让并行槽翻倍，灶升到 120，但座位 65.5 压着，实际 `total` 60 → 65.45。

## 四、第十七次「键漏字段」

`why` 现在依赖 `kitchenBinds` 与 `cookGain`，而 `cookGain` 又随座位、来客、总闸、出碗节拍变。
两处缓存键补上它：

- `game/src/ui/panels.ts` 店员页：`|${s.venue.stoves}|${s.totalCustomers}|${crewFacts(s).idle}|${crewFacts(s).cookGain}`
- `game/src/ui/panels.ts` 店面页：`…|${crewFacts(s).idle}|${crewFacts(s).cost}|${crewFacts(s).cookGain}|…`

不补的话：换了座位/来客、`idle` 没变，副句该从「卡的就是灶」变成「卡的不是灶」，而 DOM 不重画。

## 六、这一批没动什么

- 日薪表 `WAGE_BY_SKILL`、`HIRE_FEE_RATE`、`serveMultiplier` 的煮技系数、`capacityOf` 的四道闸、
  `STAGE_MINUTES`、`FLOW.serveMinutes` 默认值 —— 一格没动。
- `crewFacts` 只被界面与测试读，不参与任何模拟分支 ⇒ 替身四种子必然逐位不变，
  这也正是「本批只改说法」的验收判据。

## 七、新缺口

- **P472** `cookGain` 只算「多一个人」，没算「多这个人技能几级」—— 技能改的是
  `serveMultiplier`，`capacityWithCooks` 里那一项被继承了，差值其实跟着技能变，但界面只说「多一个人」。
- **P473** 副句里那个「约多卖 N 碗」是 `Math.round`，5.45 与 5.4 都说 5 碗；差一点不可见。
- **P474** `COOK_GAIN_NOISE = 0.5` 与 P450 的「+0.5 半碗容差」是同一把拍子，两处各写一次，没有统一出处。
- **P475** `capacityWithCooks` 没有进 `docs/ACCEPTANCE.md` 第三节的口径表，只在本文与代码注释里。
