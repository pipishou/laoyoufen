# 批 AU′：从「每一块钱技能最高」到「厨房不是最紧那道就别急着换人」

> 日期：2026-11-26 · 批次：AU′ · 解 P465 / P466 / P467
> 上一批：AT′（`docs/灶位那句话与价钱口径AT′-2026-11-26.md`）

## 一、这一批要解决什么

上一批把「灶位 3 口，只有 1 个人掌勺」这句话收成了一份出处，还顺手把价钱报全了：
技能几级、日薪多少、介绍费（一次）、月薪约多少。三句话读起来都对，可合在一起有一处**没人算过**：

> 那个「每一块钱技能最高」的师傅，雇下来到底能多卖几碗？

批 AS′ 的十二格实测里其实已经有答案了，只是当时没往这一步想：座 6 · 灶 1，无人卖
**111.2**、有一个煮粉卖 **111.8** —— 换个人，多卖 0.6 碗。座 4 更糟，雇人之后
**76.6 < 77.0**，还少了半碗。

于是 U′ 要干三件事：

1. **P466**：把「雇了也未必多卖」这个前提说出来 —— 只在厨房真卡的时候才不拦；
2. **P465**：那句「灶位 N 口，只有 M 个人掌勺」的头还是两段手写的，收成一处；
3. **P467**：`why` 与 `cost` 两句话还在 `sim/crew.ts` 里手写，一併搬进 `data/crew.ts`。

## 二、取证：技能到底改不改卖碗数

临时脚本 `game/src/sim/tmp_p466.test.ts`（已删）：`FLOW.serveMinutes` 覆写（`try/finally` 还原）+
`createInitialState("p", seed)` + `venue.seats/stoves` + `capacity = 9999` + `reputation = 500` +
`totalCustomers = 5000` + 手摆 `staff.roster`，6 天取后 3 天均值，种子 1/2/3。

### 默认配平（`serveMinutes = 1`，游戏里就是这个）

| 座位 | 无人 | 技能 1 | 技能 5 | 技能 5 ×2 |
|---|---|---|---|---|
| 4 座 | **76.4** / 走 248.7 | 75.4 / 240.8 | 75.4 / 240.8 | 75.4 / 240.8 |
| 6 座 | **112.1** / 走 295.4 | 112.7 / 289.2 | 112.7 / 289.2 | 112.7 / 289.2 |
| 8 座 | **111.4** / 走 184.4 | 112.1 / 193.8 | 112.1 / 193.8 | 112.1 / 193.8 |

**卖碗数几乎不动**（最多 +1.3 碗，4 座还倒挂），只有走掉的人少 6–10 位。

### 灶项（`capacityOf().stove`）却被技能拉得很开

| `serveMinutes` | 无人 | 技能 1 | 技能 3 | 技能 5 | 技能 5 ×2 |
|---|---|---|---|---|---|

### 厨房真卡（`serveMinutes = 6`）时卖碗数才真的跟着技能走

| 座位 | 无人 | 技能 1 | 技能 5 | 技能 5 ×2 |
|---|---|---|---|---|
| 6 座 | 58.6 | 82.7 | 87.0 | 94.1 |
| 8 座 | 58.6 | 106.0 | 112.4 | 114.9 |
| 12 座 | 58.6 | 112.9 | 111.6 | 111.8 |

**结论**：「每一块钱技能最高」这个排序没错（技能确实决定灶开多快），但**默认配平下它换不来碗**
—— 因为闸在座位和来客，不在灶。价钱句只报价钱不说这个前提，就是在催人白花钱
（和批 AN′ 的 P446「抬了也卖不动」同一个病理）。

所以本批**不动任何数值**，只做一件事：**让价钱句自己带上前提**。

## 三、改了什么

### 3.1 `game/src/data/crew.ts`：所有句子收成一处（P465 / P467）

```ts
function gapCore(slots: number): string { return `第 ${slots + 1} 口起没人看`; }

function headWords(stoves: number, slots: number, short: boolean): string {
  const noun = short ? "灶" : "灶位";
  const lead = short ? `只有 ${slots} 个人掌勺` : `眼下只有 ${slots} 个人掌勺`;
  return `${noun} ${stoves} 口，${lead}`;
}

export function crewGapWords(stoves, slots, short = false)   // 缺口句（长/短）
export function crewFitWords(stoves, slots)                  // 富余句
export function crewWhyWords(kitchenBinds: boolean)          // 副句（P467）
export function crewCostWords(hire, kitchenBinds = true)     // 价钱句（P466）
export function crewGateWords(gate)                          // 招不进来那句（P467）
export function crewNoneWords()                              // 今天没人来问工（P467）
```

**P465 的实质**：以前长句头 `灶位 ${stoves} 口，眼下只有 ${slots} 个人掌勺` 与短句头
`灶 ${stoves} 口，只有 ${slots} 个人掌勺` 是两段各自拼数字的字符串，改口径要改两处。
现在两者都走 `headWords`，**数字只在这里拼一次**，长短只差两个词（`灶位`/`灶`、
`眼下只有`/`只有`）。

**P467 的实质**：`why`（「不过今天卡的不是灶…」）与 `cost`（「今天有人来问工…」）原本写在
`sim/crew.ts` 里，`crew-literal.test.ts` 只盯主句那两句 —— 和 P451 同型，只是还没抄第二遍。
现在四句都搬进 `data/crew.ts`，因为**同一个意思一旦有两处可能写，就一定会写成两套字**。

### 3.2 价钱句带上前提（P466）

```ts
export function crewCostPremiseWords(): string {
  return "（不过今天厨房不是最紧那道，换个人也换不来更多的碗）";
}

export function crewCostWords(hire, kitchenBinds = true): string {
  const line = `今天有人来问工：${hire.name}（技能 ${hire.skill}）日薪 ¥${hire.wage}` +
               ` · 介绍费 ¥${hire.fee}（一次）· 月薪约 ¥${hire.monthly}`;
  return kitchenBinds ? line : `${line}${crewCostPremiseWords()}`;
}
```

`sim/crew.ts` 那侧只需 `cost = crewCostWords(hire, kitchenBinds)` —— `kitchenBinds` 本来就算好了
（`capacityOf(state).tight === "stove"`，批 AR′ 为 `why` 加的那个字段）。

于是同一句在两个世界里读起来是：

- **厨房真卡**（`serveMinutes` 被压慢，或在测试里）：`今天有人来问工：阿强（技能 3）日薪 ¥150 · 介绍费 ¥300（一次）· 月薪约 ¥3262`
- **厨房不是最紧那道**（游戏默认）：同上，后面多一句 `（不过今天厨房不是最紧那道，换个人也换不来更多的碗）`

**没做的事**（都是故意的）：不改日薪、不改招聘门槛、不改 `serveMultiplier`、
不改 `capacityOf` 的灶项公式 —— 本批只让话说全，不动一个经济数值。

### 3.3 测试

`game/tools/crew-literal.test.ts` 从 5 例扩到 **8 例**：

| 用例 | 判据 |
|---|---|
| 缺口句与富余句各只有一份模板 | 「口起没人看」「每一口灶都烧得上」只许在 `data/crew.ts` |
| **头也同源**（P465） | 「个人掌勺」只许出现一次；长短两句的数字必须一致 |
| 打烊单短句与面板长句共用核心 | 都含 `—— 第 2 口起没人看`；只有长句带 `，火开不起来` |
| **副句与价钱句也只有一处**（P467） | 「今天卡的不是灶」「今天有人来问工」「人手槽还差」「今天没有煮粉的来问工」四处为零 |
| **价格带前提**（P466） | `binds` 不带前提、`loose` 以 `binds` 开头且含「厨房不是最紧那道」 |
| 数字由调用方给 | `crewGapWords(4, 2, true) === "灶 4 口，只有 2 个人掌勺 —— 第 3 口起没人看"` |
| 不劝购 | 主句、富余句、副句都不匹配 `/¥|元|买|推荐|建议|划算/` |
| `hud.css` 前缀对得上 | 含 `[data-crew-line]::before{content:"灶位 · "}` |

`game/src/sim/crew.test.ts` 11 例保持不变（新文案多了一句前提，但 `toContain("日薪 ¥150")`
与 `toContain("介绍费 ¥300")` 仍成立 —— 这正是「只加尾巴」的好处）。

## 五、这一批没动什么

- **没动任何经济数值**：日薪表 `WAGE_BY_SKILL`、`HIRE_FEE_RATE`、`serveMultiplier`
  的煮技系数、`capacityOf` 的灶项公式、`STAGE_MINUTES` —— 一格没动。
- **没让「雇人真的多卖」**：技能对卖碗数的影响仍接近零。这是配平事实，不是文案能修的；
  真要修得动经济（把灶项拉到真卡的位置，或者让技能影响别的环节），那是另一批的事。
- **没动 P464 / P468**（探针弱判据）与 P459（`kitchen-never-binds.test.ts` 只钉现状不是论证）。

## 六、新缺口

- **P469** `crewCostPremiseWords` 说的「换不来更多的碗」是**今天是这个配平**时的事实，
  一旦有人把 `FLOW.serveMinutes` 调大或把灶项拉紧，这句话就会变成假话 —— 而它没有
  像 `kitchen-never-binds.test.ts` 那样的守卫，只是跟 `kitchenBinds` 一起动。
- **P470** `crewFacts.kitchenBinds` 只用 `capacityOf().tight === "stove"` 一个判据；
  「厨房差一点点就卡」这种情况（tight 是 seats 但 stove 只高 60 碗）与「差很远」
  说的是同一句话。
- **P471** `crewCostWords` 的默认参数是 `kitchenBinds = true`，调用方忘传就等于
  「厨房真卡」—— 一句默认值就能把前提吞掉，且测试只覆盖了显式传 `false` 的分支。
