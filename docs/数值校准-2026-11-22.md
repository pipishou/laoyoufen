# 数值校准 · 2026-11-22

> 一句话：把「开罗的骨架」重新对到「我们自己的钱」上。三处校准 —— 配料价目、钱包地板、段位费 —— 每一处都先指出开罗原文的数，再说我们为什么不照抄那个数、只借它的形状。

---

## 一、为什么要校准

开罗的数值骨架在同一套表里咬合得很好（`topping` 加价 80/120 对一碗 800–1200、`customer` 钱包 840–1400、`grade_review` 段位费合计 8,330,000）。我们的表是分十几批长出来的，每批只看自己那一块，于是出现了三种「单看没错、放在一起不对」：

1. **配料加价能到 ¥10** —— 一碗粉卖 ¥10，加一份牛腩再收 ¥10，等于「再造一碗」。开罗加料是「撒一把」，我们是「一份肉」，比例该更高，但高不过半碗。
2. **学生仔（预算 ¥8）站在 ¥10 的价牌前只能掉头** —— 开罗最穷的钱包 840 也买得起最便宜那碗 800，**谁都吃得起一碗**。我们不是，于是 62.5% 的流失里有一大块是「价牌」，把真正该修的队伍与口味问题盖住了。
3. **段位费还是 ¥82,600** —— 批次四按当时的三年营收（¥541k）把评定费降到开罗量级（8,260 碗）。后来钱包地板让营收涨到月均 ¥184k，段位费就变成了零头，期末现金堆到 ¥1.29M–¥2.14M（P173 早就警告过这一条）。

## 二、三处改动

### ① 配料价目：加价不过半碗，料钱不过半价

`game/src/data/ingredients.ts` 三十七条重标，共改 15 条：

- 加价 `clamp(price, 0.5, 5.0)` —— 一碗 ¥10，加一份不超过半碗；
- 料钱 `min(cost, price × 0.5)` —— 卖一份至少留一半毛利。

| 配料 | 旧加价 | 新加价 | 旧料钱 | 新料钱 |
|---|---|---|---|---|
| 牛腩 | ¥10.0 | ¥5.0 | ¥5.00 | ¥2.50 |
| 牛百叶 | ¥10.0 | ¥5.0 | ¥4.60 | ¥2.50 |
| 猪手 / 牛肉片 / 牛杂 | ¥9.0 | ¥5.0 | ¥4.20–4.50 | ¥2.50 |
| 猪粉肠 / 猪花肠 / 五花肉 | ¥8.0 | ¥5.0 | ¥3.60–3.80 | ¥2.50 |
| 猪杂 / 猪肚 / 猪肝 / 猪肉片 | ¥7.0 | ¥5.0 | ¥3.00–3.50 | ¥2.50 |
| 瘦肉片 / 牛肉丸 | ¥6.0 | ¥5.0 | ¥2.80–3.00 | ¥2.50 |
| 葱花 | ¥0.0 | ¥0.5 | ¥0.20 | ¥0.20 |

素料与蛋（¥1–2）一条没动 —— 那一段本来就在带宽里。

### ② 钱包地板：谁都吃得起一碗

`game/src/sim/customer.ts` 新增 `export function walletFloor(state, raw)`：

```ts
export function walletFloor(state: GameState, raw: number): number {
  return Math.max(raw, cheapestPrice(state));
}
```

`arriveOne` 里 `const wallet = walletFloor(state, walletRaw);`。钱包只抬到「刚好买得起菜单上最便宜那一款」，贵的款仍买不起 —— 这是开罗的形状（840 能买 800 那碗，买不起 1200 那碗）。

### ③ 段位费：改按碗定，成为主现金出口

`game/src/data/anchors.ts` 的 `CAPITAL.gradeFeeYuan`：

```
旧 [500, 1000, 1800, 2800, 4500, 7000, 10000, 14000, 18000, 23000, 0]   合计 ¥82,600
新 [4000, 8000, 14400, 22400, 36000, 56000, 80000, 112000, 144000, 184000, 0]  合计 ¥660,800
```

门槛 `minCustomers`（110 → 6,000）**一位不动**。同时 `game/src/data/money.ts` 把 `gradeFee` 区间上限从 ¥130,000 抬到 ¥200,000，`note` 改成「顶档约二十来天营收，含非遗认定材料」。

## 三、开罗原文 → 本作：借形状，不借数

| 表 | 开罗原文 | 本作校准后 | 借什么、不借什么 |
|---|---|---|---|
| `topping` | 加价 80/120 KCU（一碗 800–1200 的 8–15%）、料钱 20/30（2–3.75%） | 加价 ¥0.5–5（一碗 ¥10 的 5–50%）、料钱 ≤ 加价一半 | 借「加料是碗之上加一点、料钱占加价小头」；不借它的小比例 —— 它的浇头是一撮玉米，我们的是一份肉 |
| `customer` | 钱包 840–1400，最穷 840 ≥ 最便宜一碗 800 | 预算 ¥8–15，地板抬到最便宜那款 | 借「谁都吃得起一碗」；不借 1.67 倍的钱包跨度（我们 8–15 已是 1.875 倍） |
| `grade_review` | 合计 8,330,000 KCU ≈ 8,330 碗 ≈ 全程营收绝大部分；storeequip 最贵 8,000（0.1%） | 合计 ¥660,800 ≈ 66,080 碗 ≈ 全程碗数（约 24 万）的三成；设备合计 ¥44,300（6.7%） | 借「段位费是主出口、设备是零头」；不借「吃掉全部营收」——那会把设备线彻底压死 |
| `store_data` 容量 | 50/150/270/420 | 日上限 200（新局） | 不动 |

三条读法：

1. **①② 一上，流失从 62.5% 掉到 38.8%、碗数涨 47%** —— 价牌流失确实是最大一块假流失，与 `loss_probe` 的观察一致（校准后主打解释变成「45 位是门口站满了没进来」）。
2. **段位费一上，期末现金从 ¥1.65M 掉到 ¥339k（−79%）** —— 段位费确实是主出口，但它同时与设备抢同一笔现金，月均营收回落到 ¥95,897（比只改①② 低 48%）。
3. **流失率没有再降**（41.8%）—— 剩下的都是队伍、耐心与口味，这才是开罗的样子的。

## 六、新缺口

- **P230**：段位费与设备抢同一笔现金 —— 只改①② 时月均 ¥184k，加上段位费掉到 ¥96k，升级被挤、产能不足；错峰机制（分段收 / 按累计营收比例收）还没做。
- **P231**：期末现金均值 ¥339k，仍高于方案的 ¥80k–¥200k 判据；但四种子跨度 ¥78k–¥508k，说明出口位置比总量更成问题。
- **P232**：加料只加成本、不加售价，面板写的是「建议加价 +¥5」，没有明确提示「不抬价就是亏」—— 加一份牛腩在 ¥9 的价签下把毛利从 ¥4.2 压到 ¥1.7。
- **P233**：钱包地板把价牌流失打到 0，价格杠杆只剩「贵的款卖不动」，而菜单常年只有一款 —— 价格分层要靠玩家自己开第二款。
- **P234**：配料价目按 tier 一刀切（15 条全落到 ¥5 / ¥2.50），档内差异（牛腩 vs 猪肝）被抹平，只有 charm 还在区分。
