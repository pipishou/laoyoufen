# 手艺树（P39）——照开罗 `rank.txt` 排的解锁表

日期：2026-11-15 · 批次：六阶之后的「中期节奏」第三批 · 状态：已上线 `http://8.134.86.249/laoyoufen/`

## 一、三句话

1. **开罗的中期节奏不是 KPI，是 `rank.txt` 那 17 行奖励**：扩建、修路、排队位、买更大的店 —— 升一级 rank 多一件能做的事，不是多一个数字。
2. 我们把这条照搬到自己的 11 级段位上：**升一段 = 多一件能做的事**，10 项里 6 项已接进模拟，4 项先在面板里预告（不许假装生效）。
3. **T3（中期营收持平）没有消失，但归因清楚了**：产能被「座位 × 灶位 × 并行槽」物理封顶（15 座 3 灶 ≈ 120 碗/日），价格被南宁现实封顶（¥12），两个天花板一起把营收压在 ¥47k/月 —— 出口是第 10 段的「分店」，还没接。

### 真正接到模拟里的三个点

```ts
// game/src/sim/unlocks.ts
export function queueMaxOf(state) {           // 排队位
  let q = FLOW.queueMax;                       // 12
  if (isUnlocked(state, "queue2")) q += 2;     // 第 2 段 → 14
  if (isUnlocked(state, "queue4")) q += 4;     // 第 7 段 → 18
  return q;
}
export function roadworkBoostOf(state) {       // 巷口灯箱
  return isUnlocked(state, "roadwork") ? 1.15 : 1;
}
```

- `game/src/sim/customer.ts` 的 `arriveOne()` 用 `queueMaxOf(state)`（原 `FLOW.queueMax` 常量）。
- `game/src/sim/district.ts` 的 `demandCapOf()` 乘 `roadworkBoostOf(state)` —— 灯箱让本区池子变大，与「区能量每季度 −9%」对撞。
- `game/src/data/expansion.ts` 从两档扩到四档，后两档带 `minGrade`；`game/src/sim/expansion.ts` 的 `buyExpansion()` 先判段位再判钱（`expansionLockReason()` 说人话：「要评到第 3 段才准动这个（现在第 2 段）」）。

## 四、替身会做菜了（P40）

上一轮测试员给出的 T3 有一条 21 个月持平，我一直归因于「缺新动词」。这一轮发现**量尺自己不会做菜**：

> 替身从不碰配方 → 味道永远停在初始分 → `priceTolerance()` 只有 1.0 → 价格卡 ¥9 → **营收 = 碗数 × 9 = 产能曲线**。

两处修正（`game/src/sim/standin.probe.ts`）：

1. **配方爬山** `climbRecipe()`：每月随机挑一个汤/粉参数 ±4，满意分更高就留、否则回滚，试 6 次 —— 真人就是这么试的。
2. **定价看营收不看流失**：旧规则要求「流失 <5% 才敢涨」，可高产能店流失永远 60%+，于是永不涨价。改成：味道 ≥65 且有人被挡在门外（流失 >25%）就涨 1 元试一个月，**下月营收跌 5% 以上就退回**。

效果（同种子、同策略）：

| 指标 | 改前 | 改后 |
|---|---|---|
| 味道 | 55（初始） | **70–72**（爬了 36 个月） |
| 均价 | ¥9 | **¥12** |
| 月均营收 | ¥31,470 | **¥38,708** |
| 三年成长 | ×1.37 | **×1.71** |
| 最长持平段 | 11 月 | **10 月**（种子 1）/ 22 月（种子 2） |
| 段位 | 10 | 9 |
| 扩建 | 2 次 | **4 次（15 座 / 3 灶）** |
| 期末现金 | ¥41,476 | **¥100,587** |

T3 仍在，但**换了一种病**：不是「没东西可买」，而是「买完了也就到这儿」。

## 五、T3 的真因（本轮最重要的发现）

替身跑到最后：**15 座 / 3 灶 / 设备全满 / 段 9 / 价 ¥12 / 味道 72 / 流失 71%**。

- 出碗上限 ≈ 15 座 × 3 灶 × 3 碗（并行槽）≈ **120 碗/日**；
- 价 ¥12 已是南宁现实上限（牛肉粉 12 元，人均客单 12–15）；
- 于是营收封顶 ≈ 120 × 12 × 30 ≈ **¥43k/月**，之后只能靠搬去更大的区把池子放大 —— 但产能不变，池子再大也吃不下。

**两个天花板同时到顶**，这就是「有 10–22 个月营收不动」的物理原因。开罗的出口有两层，我们都还没接：

1. `More Active Items`（同时操作更多）→ 我们的**并行槽**已经做了（P35），但只到「4 档设备 + 3 灶」；
2. `Buy Amazing Shop`（买顶级店）→ 我们的**分店/更大铺位**还是 `pending`（第 10 段）。

→ 记 **P41**：要做中期的第三个天花板突破，只有两条路 —— **分店（第 10 段）** 或 **客单价结构（加料/加蛋/饮料，开罗的 `avgTicket`）**。

## 六、顺手修掉的一个真 bug

准备阶段（`phase === "prep"`）时间不推进 → 没有 tick → `panels.render()` 从不被调用 → **点开任何页签都是空白面板**。

修：`main.ts` 的 `onOpenTab` 里 `panels.open(tab)` 之后补一次 `refresh()`；同时给 `panels.ts` 的 shop 面板缓存 key 补上 `gradeLevel / expansion / district`（否则升段后手艺树不刷新）。

这个 bug 只有真点一遍才会发现 —— 单测与眼睛绿都看不见（面板默认是关着的）。
