# 守卫的成本要看得见、表走散要在测试里就红（批 AJ′）

> 这一批仍然**不动玩家屏幕上的任何东西**：一件是替身的账本（P423），
> 一件是「服务端那张表」的抓漏位置（P424）。四种子数字**逐位不变**，这正是判据。

## 一、P423：换底被挡了几次

批 AI′ 让替身会换底，报尾只印「换底 N 次」。但「成功几次」看不出这台量尺有没有压力 ——
P400 加的那道守卫（先留下下一件家当/下一档扩建的钱 + 三千周转）到底挡掉过几次，以前是看不见的。

`game/src/sim/standin.probe.ts` 的 `pickSoupBase` 现在把三件事分开记：

```ts
if (bestId === cur) return;          // 现状本来最好：不是「想换」
baseWanted += 1;                     // 想过
if (s.cash < keep) { baseBlocked += 1; return; }  // 被「先留钱」挡住
if (setSoupBase(s, bestId).ok) baseSwitches += 1; // 真换了
```

报尾变成：

```
· 换底 1 次（想换 1 次，被钱挡 0 次）· 袋装线 开了
```

四种子实测：**想换 1 / 2 / 3 / 4 次，被钱挡 0 / 0 / 0 / 0 次**。
也就是说 —— 这道守卫在当前替身身上**一分钱成本都没有**（它攒得出的钱总是够），
这本身是个结论：P400 的担心在替身这里没成立，真正的缺口是 P422（开袋装线没有回本判据），
而不是「守卫太紧」。数字没变也印证了这一点。

## 二、P424：表走散要在 `npm test` 里就红

批 AH′ 的生成器（`tools/server-events.gen.ts`）只在 `npm run -s gen:server` 和部署脚本里跑 ——
命令行的测试全绿，表照样能走散，只有发布那一刻才炸。这条现在拆成三件：

| 文件 | 作用 | 会不会写盘 |
| --- | --- | --- |
| `game/tools/server-events.rows.ts` | 「把 `EVENTS` 摊成服务端的行」这一份逻辑，两个调用方共用 | 不碰 `fs` |
| `game/tools/server-events.gen.ts` | 写盘（`npm run -s gen:server`，部署打包前也跑） | 只在内容变了时写 |
| `game/tools/server-events.test.ts` | **只读**对账，`npm test` 里就会跑 | 从不写 |

新测试的报错是给人看的，不只给机器看：

```
AssertionError: 这些事件在服务端那份表里与游戏不同：bamboo_press —— 跑一次 `npm run -s gen:server`
```

实测（手动改掉 `bamboo_press` 的标题，不改游戏）：
`npx vitest run tools/server-events.test.ts` → **1 red**，并点名是哪一件；
跑一次 `npm run -s gen:server` → 文件写回原样，测试转绿，`git status` 回到干净。

顺手修掉一处会咬人的地方：生成器原来写的是 `JSON.stringify(rows, null, 1)`（一空格缩进），
而仓库里那份是两空格 —— 第一次真跑会整篇重排、造成 1711 行假 diff。现在写 `null, 2`，
`gen:server` 变成**字节级幂等**（跑完 `git diff --stat server/events.json` 是空的）。
