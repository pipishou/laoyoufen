# 试玩三轮修复：把「主句与副行打架」拆成三件事（2026-11-21）

## 一、三句话

1. 这轮不动内容，只修三个交互硬伤：**评定交费按钮找不到**、**打烊单主句与副行指的不是一件事**、**产能钩子挑了效能最低的那件（一万二的隔墙）**。
2. 根因都在「同一个判断被写了两处」：瓶颈判定有 `sim/hook.ts` 的 `capacityPick` 与 `sim/gear.ts` 的 `nextGear` 两套；副行口气有 `HOOK_VOICE.capacity` 一个大池；打烊单的「明天」有前缀与大按钮两处。
3. 收口办法是把判断收成一份 `sim/bottleneck.ts`（当天上限按灶/座/备料三面取最小），钩子按**每一块钱能抬多少上限**挑件，副行按卡点细分到「灶 / 座 / 备料」三档。

## 三、改动一：新建 `game/src/sim/bottleneck.ts`

一天能卖多少碗，取决于三个数里最小的那个：

```ts
stove = DAY_MINUTES / serveNow;                            // 灶台出得过来多少
seats = seats × DAY_MINUTES / (serveNow + EAT_MINUTES);    // 坐下的人吃完要腾位
cap   = state.capacity;                                    // 备料总闸
total = min(stove, seats, cap);
```

`EAT_MINUTES = 1`（一游戏分钟 ≈ 六现实分钟，正好嗦完一碗）。`capacityGain(state)` 再算三件事各自能把这上限抬多少：

- `stove`：把 `serveNow` 乘上 `STOVE_SERVE_FACTOR` 后重算 `total` 的差值；
- `bench`：案台抬总闸，但抬不过 `min(stove, seats)`，所以灶还慢时这个值是 0；
- `seat(n)`：座位 +n 后的差值 —— **灶还慢时这个值就是 0**，阿兰那个坑从这里堵住。

## 四、改动二：钩子按「每一块钱能抬多少」挑件

```ts
const perYuan = gain / Math.max(1, cost);
```

`capacityPick` 现在给每个候选（三件设备的下一档 + 未锁的下一档扩建）算 `gain`，先滤掉 `kind === "cost"`（粉篓）与 `gain <= 0.05`，再按 `perYuan` 取最高，买不起才退回最便宜那件。删掉了「座位 ≤4 先扩座」的硬规则 —— 那条规则正是「一万二的隔墙」的来源。

实测（`hook_probe.py` 造 2 座 1 灶、昨天走 60 位）：

- 改前：`明天先把「打通隔墙，多摆两张桌」加上（¥12,000）—— 今天走了 60 位`
- 改后：`先把「猛火灶（第 1 档）」加上（¥1,500）`，副行「锅底那点火，最耽误人。」

## 六、改动四：副行按卡点细分（AI 落点对齐）

- `hook.ts` 的 capacity 分支把 `key` 细分成 `capacity:stove` / `capacity:seat` / `capacity:cap`；
- `hookVoiceContext` 的 `类型` 跟着细分，`VOICE_HINT` 从 `Record<HookKind,string>` 改成 `Record<string,string>`，加「那口灶 / 店里的桌子 / 案台上的备料」；
- `ai/lines.ts` 的 `HOOK_VOICE` 拆出三档（灶 4 句、座 3 句、备料 2 句），旧的 `capacity` 池留 5 句作兜底，**合计 34 句**；
- `server/app.py` 的 `LINE_SCENES["hook_voice"]` 加硬约束：**只能就「细节」里写的那一件事说，不许换话题**（细节说灶就只说灶，不许转到招牌、菜单、评级、比赛、装修、天气），细节里没有的不许编。

## 七、改动五：评定入口（硬 bug）

- `panels.ts` 的店铺页：够格时 `gradeSec` **直接顶到最上面**（`${gc.ready ? gradeSec : ""}`），不够格时才留在原来的中段；
- `hud.ts` 的第五枚胶囊：够格时变成红框 `可评定「X」`，`title` 写明「够格了：去「店铺」页最上面交费评定」。

## 八、改动六：设备说明不再写死分钟

`data/equipment.ts` 猛火灶的 `effects` 从「出碗 5.1 / 4.3 / 3.6 / 3.1 分/碗」改成「出碗快 15% / 28% / 39% / 48%」——绝对分钟数取决于员工技法与并行度，写死必然与 HUD 对不上（报告里「5.1 vs 2.0」就是这个）。

## 十、新缺口

- **P114**：`EAT_MINUTES = 1` 是拍的（按「一游戏分钟 = 六现实分钟」推的），没有实测客人的实际用餐时长。
- **P115**：`tightWords()` 已经能说「灶台出得慢 / 座位坐不下 / 备料不够卖」，但还没上界面 —— 现在玩家只能从「最要紧」那句里反推。
- **P116**：副行池 34 句，一个月按每天一句仍会说完；细分到卡点后每档只剩 2–4 句，重复感更快。
- **P117**：`capacityGain` 与 `gear.nextGear` 的产能判断仍是两处（前者按上限增益，后者按 `seats/servePct/costPct` 归类），P111 只答了一半。
