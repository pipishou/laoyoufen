# 批 H′：回本给区间、指路带因果、设置能恢复默认

> 这一批只做三件事，全是上一批留下的缺口：P273 / P275（回本是一个数）、P277（AI 只知做什么、不知为什么）、P280 / P281（设置不进存档没提示、没有恢复默认）。
> 依据依旧是开罗：`balloon.txt` 一句一处境（口气要落在因果上）；`text.txt` 的设置项里没有「按设备保存」这层说明，玩家自己会以为存进游戏了。

## 一、三处改动

### 1. 回本从「一个数」改成「一个区间 + 口径」（P273 / P275）

原来写「约 5 天回本」。这个数只按**今天这一碗**的卖价与料钱算：明天换了配料、涨了价、来一场台风，它就变。
所以：

```ts
export function paybackRange(cost: number, gain: number, margin: number): [number, number] {
  const best = paybackDays(cost, gain, margin);          // 按今天
  const worst = paybackDays(cost, gain, margin * 0.75);  // 赚头打个七五折
  if (best <= 0 || worst <= 0) return [0, 0];
  return best === worst ? [best, best] : [best, worst];
}
```

界面上一律走 `paybackWords()`：

- 有区间 →「约 4–6 天回本（按今天这碗算）」
- 上下界相同 →「约 1 天回本（按今天这碗算）」
- 不要钱 → 「不花钱，当天就见效」
- 卖不动（`gain` 为 0）→「看不清几天回本」

**把口径摆在数字旁边，比把数字算准更要紧**：玩家看到「按今天这碗算」，就知道明天的数会变，不会觉得自己被骗。

### 2. `pointer_voice` 的上下文补一格「卡在哪」（P277）

`TodayLine` 加 `blocked?: string`，产能那两支填 `tightWords(state)`（座位 / 出碗 / 备料），价签那支填「价签」，家当那支填当时最紧的那一段。
`todayVoiceContext()` 多给一格：

```ts
卡: (line.blocked ?? "").replace(/[¥0-9]/g, "").slice(0, 12),
```

于是模型能说出「位子转不过来，先搬两张凳进来」这种落在因果上的闲话，而不是重复一遍「该买凳子」。

### 3. 设置页加「恢复默认」并写明不进存档（P280 / P281）

- 第六行 `.prefrow.prefreset`（虚线分隔）：名字「恢复默认」，说明「音乐音效全开、音量中、高对比与大字关」，按钮写「恢复」。
- 底注从「存在这台机器上；换台设备要重新调」改成「**这份设置只记在这台机器上，不进存档**；换台设备、清了缓存就回到默认」。
  —— 玩家以为设置跟着存档走是最常见的一类误解，一句话说清比加一个「同步设置」功能便宜得多。

## 五、新缺口

- **P282** 回本区间的下界取「赚头打七五折」，这个 0.75 是拍的；真正该按过去七天的平均赚头算，但那要存历史。
- **P283** `pointer_voice` 的「卡」只给一个名词，模型不知道「已经买了几张凳」这类已做的事，容易重复劝。
- **P284** 设置「恢复默认」不区分「只重置声音」与「连可访问性一起重置」，一键全清。
