# 趁势：门路的第四类（批 BD′）- 2026-11-27

> 一句话：**BB′ 教会了玩家「花钱把坏事挡在门外」，这一批补上另一半 ——「花钱把好事叫到门口」。**
> 门路从三类变四类，`lean`（趁势）与 `hedge`（对冲）成对；顺带解掉 P504（第四位门路位用不满）。

---

## 一、这一批要解决什么

### 1. GAP 四轮第四节 B 条的另一半

原文（`docs/GAP四轮-2026-11-26.md` 第四节 B）：

> 开罗 `economy.txt` 26 条里有一半是花钱买的窗口期（`Prices Up` / `Ingr. Costs Down`，各带月份窗），与被动天气是两套东西。本作 `data/market.ts` 16 条全是被动天气；`data/invest.ts` 8 条门路全是买「量」。体感：行情来了只能挨着，没有任何「提前对冲」或**「趁势加码」**的动作。

批 BB′ 做了「提前对冲」（`hedge` 两条：报备挡检查、包月挡猪肉涨价）。**「趁势加码」那一半没做** —— 玩家还是只能挨着好行情，没法主动把它叫来。

### 2. 顺手解掉 P504

批 BC′ 把门路位从 2 位长到 4 位（第 8 段），但当时只有三类门路、且「同类只能一条」——
三类各挂一条就是三条，**第四位短期用不满**（记为 P504）。这一批第四类一进来，四类各挂一条正好用满。

### 3. 为什么不照抄开罗的 `Prices Up` / `Ingr. Costs Down`

那两条是**乘一个数**。本作的料钱已经叠了五层：

| 层 | 出处 |
| --- | --- |
| 品质档 | ×1.0 / 1.8 / 2.6 |
| 行情 | ±14%（`porkUp` / `gasUp` 等） |
| 物产 | −2% |
| 技法 | −6~12% |
| 店底子 | 见 `balance.ts` |

再挂一条 −6% 就是第六层，上限从来没验过（P154）。所以这一批和 BB′ 一样：
**买的是「哪一条行情出现」，不是「再乘一个系数」。** 纪律一「只买量不买乘数」没有被破 ——
只是把「量」换成了「哪一天」。

## 三、改法（单一出口 + 先抽再调整）

### 1. 数据表：`leanOn` 与 `hedgeOf` 对称

```ts
  /**
   * 行情趁势（批 BD′）：买下的这几天里，**这一条好行情一定来**。
   *
   * 与 `hedgeOf` 正好一对：那边挡坏消息，这边把好消息摁到台面上。
   * 同样不是乘数 —— 它只决定「今天抽到哪一条」，效果仍由 `data/market.ts` 那张表给。
   */
  leanOn?: MarketId;
```

`InvestClass` 从 `"make" | "voice" | "hedge"` 变成 **`"make" | "voice" | "hedge" | "lean"`**。

### 2. 单一出口：`leanedMarketIds`

```ts
export function leanedMarketIds(state: GameState, extraDays = 0): Set<MarketId> {
  const base = dayIndexOf(state) + Math.max(0, Math.floor(extraDays));
  const out = new Set<MarketId>();
  for (const def of INVESTS) {
    if (!def.leanOn) continue;
    if (investUntil(state, def.id) > base) out.add(def.leanOn);
  }
  return out;
}
```

与 `hedgedMarketIds` 同形、同文件（`sim/invest.ts`）—— 因为两边都要读 `state.investments`，
而 `sim/market.ts` 读它们、它们不读 `sim/market.ts`，这样没有环。
`extraDays` 是「问的是今天往后第几天」：明天预告要按**明天**还剩几天算。

### 3. 抽签：先照常抽 → 抽中被对冲的就避让 → 最后把趁势摁上去

```ts
  let picked = pool[Math.floor(r * pool.length) % pool.length] ?? null;
  if (picked && hedged.has(picked.id)) {
    const rest = pool.filter((m) => !hedged.has(m.id));
    if (rest.length === 0) return null;
    const r2 = hashString(`${seed}:market:${month}:${day}:hedge`) / 4294967296;
    picked = rest[Math.floor(r2 * rest.length) % rest.length] ?? null;
  }
  if (picked && leaned.size > 0) {
    const wanted = pool.find((m) => leaned.has(m.id));
    if (wanted) picked = wanted;
  }
  return picked;
```

三条设计理由，写进代码注释：

1. **不剔池子**（与 BB′ 同一条）：剔池子会让每一天的下标整体错位，存档里「昨天预告的是赶圩，今天变成了台风」。
2. **趁势排在避让之后**：它买的是「一定来」，所以只要那天本来就有行情，就把那条好行情摁上去。
3. **`pool.find` 而不是直接 `MARKET_BY_ID.get`**：好行情要是那个月不在季（开学、东博会只在九月），宁可按原样走，也不抽一条季节外的天气出来。

### 4. 一条必须说清的边界：趁势**不会凭空造出一天行情**

`hasMarketAt()` 那道闸（`MARKET_CHANCE = 0.34`）在抽签之前就已经把「今天没行情」的日子挡掉了。
所以买三天趁势，实际效果是「这三天里**本来有行情**的那一两天一定是赶圩日」，
而不是「这三天必定三天都有行情」。否则买趁势就等于买天数，那是另一个东西（也更好卖，但不是这一批要做的）。

探针里专门为这件事留了一条判据：`lean_does_not_invent_days`。

`npm run -s probe:standin`（36 个月 × 4 种子）：

> 反过来说，如果这一批的数字变了，那就说明抽签被改坏了 —— 那是 bug，不是收益。

## 六、这一批的坑

### 坑一：`playthrough_gate` 的 `fps_min` 被并行的替身任务打红

第一次跑长跑门时 `fps min 29.0`（门槛 30），而此前 BC′ 是 54.0。原因不是这一批变慢，而是
**`npm run -s probe:standin`（576 秒、纯 CPU 单核拉满）正好在同时跑**，把浏览器的主线程抢了。
规矩（`AGENTS.md` 二·五）只写了「部署同时只能一个 job」，这一条要补成：
**长跑门与替身不能并行**。重跑时替身已经结束，9 / 9 全过，`fps min 56.0 / avg 59.9`（采样 2375）—— 与 BC′ 的 54.0 / 59.8 同一量级，说明这一批没有拖慢帧率。

### 坑二：`implement` 改 `pickMarketAt` 时不能把「返回 null」的语义丢掉

首版把 `if (!picked || !hedged.has(picked.id)) return picked;` 改成在函数末尾统一 `return picked`，
顺手就把「被对冲的只有一条、池子里没有别的」时该返回 `null` 的那条路写成了 `return null` 在
分支里 —— 两处（`pickMarketAt` 与 `todayMarket`）必须保持一致，否则 `marketOnDay`（明天的预告）
与 `todayMarket`（今天的真实行情）会在极少数日子上打架。

### 坑三：手册正文不许写阿拉伯数字

`manual.test.ts:30` 断言 `/[0-9]/.test(p.body) === false`。这一批往 `m.invest` 那页加的句子
只要写「第四类」「3 天」就当场红 —— 要写「另有两路是买行情的」。

## 八、新缺口

| 编号 | 缺口 | 判据（怎么算解） | 为什么现在不做 |
| --- | --- | --- | --- |
| **P509** | 趁势只有两条，而且都锁在「全月都在季」的行情上；开学、东博会这两条季节性的好行情买不到 | 出现第三条 `lean`，且带月份窗（`SEASON` 只在那几个月有它），面板写清「这两条只有九月买得到」 | 季节窗的门路要在面板上说清「这个月买不到」，是另一件事；这一批先把「全月都在季」的两条做出来 |
| **P510** | 趁势与对冲撞在同一条行情上时，代码里是「挡坏事优先」，但数据上四条 id 互不相干、撞不到 —— 这条规则没被任何测试钉住 | 加一条测试：人为把 `hedgeOf` 与 `leanOn` 都指向 `payday`，断言结果是「不出现」 | 现在造不出这种数据；等 P509 的季节窗门路进来才可能撞，那时一起测 |
| **P511** | 面板 `hint2` 把四类压成一句话，玩家读完还是不知道「趁势比对冲划算在哪」 | 面板上每类给一行小标题（多做 / 多来 / 挡坏 / 叫好），各带一句什么时候该买 | 这是门路面板的信息层级问题，和 P506（位子在别处可见）是同一族的界面债，适合一起做 |
| **P512** | `lean` 的效果完全依赖那条行情本身的效果量（赶圩日 `attractPct 0.28` / `patiencePct −0.14`），但玩家在买之前看不到这个数 | 面板那行 `investWords` 后面补一句「赶圩日 = 进店 +28%、耐心 −14%」 | 要读 `data/market.ts` 的 `effect`，会让 `investWords` 多一个跨表依赖；先记着 |
