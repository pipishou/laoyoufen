# 在线口子收到一处（批 O′，2026-11-24）

> 前七批把内容与机制都加厚了：事件八十三、地名二十四、手册十二页、
> 手艺十六项、店员二十一手艺。这一批只做一件事 ——
> **让「什么时候说话、说多少、说到哪一句为止」变成一处可查的规矩。**

---

## 一、原来是什么样（批 C′ / F′ 留下的口子）

`game/src/ai/lines.ts` 一个文件同时管三件事：

1. **本地句池**（每个落点四到八句，离线可玩）；
2. **在线换句**（`fetchLine`，命中缓存就不再重复换）；
3. **预算**（`LINE_BUDGET`，一局最多换多少个不同的键）。

三件事挤在一起时留了两个口子：

- **口子一：预算是一个总数**。`guest_talk` 的键是「客型 × 场面」，
  长局里它能吃掉几十个键 —— 别的落点就被它挤出去了。玩家会觉得
  「后面整局都不说话」，其实是预算被一类吃光。
- **口子二：算预算的理由没写进代码**。批 C′ 的二次评估把预算算错过一次
  （拿调用点当上限），后来改成「键空间」，但读者要从注释里推。

## 二、这一批做了四件事

### ① 预算 260 → 320，并把理由写清楚

```ts
export const LINE_BUDGET = 320;
```

二十二个落点在三十六月里能出现的不同键，实测约两百个；新增三个落点
（店员长进二十一键 / 手艺十六键 / 门路杂货十二键）再加四十九个，
三百二是留了余量之后的数。

超了不报错、不提示、不降级界面 —— **静默改走本地句**，玩家看不出预算这件事。

### ② 分项配额（解 P243）

```ts
export const LINE_QUOTA: Partial<Record<LineKind, number>> = { guest_talk: 40 };
```

`guest_talk` 单独封四十个键。用超了只影响它自己：同一个局里
钩子、为什么、菜单、店员长进照旧能换。

实现是两张表：`KIND_USED` 记每类用掉几个，`quotaLeft()` 在 `fetchLine` 里
先于网络请求判断，`resetLines()` 一并清空（否则测试之间会串）。

### ③ 三个新落点（22 → 25）

| 落点 | 何时说 | 键 | 上下文 |
| --- | --- | --- | --- |
| `staff_grow_voice` | 日结时哪位店员学会了一手 | 店员 uid | `{谁, 会}` |
| `perk_voice` | 点下一门手艺 | 手艺 id | `{族, 事}` |
| `item_voice` | 买了门路或杂货 | `invest:…` / `good:…` | `{事, 在哪}` |

三处都接在已经有的动作上，没有新增面板：

- `game/src/main.ts` 的 `buyPerk` → `speakPerk(id)`；
- `buyInvest` / `buyGood` → `speakItem(where, id, line)`；
- `refresh()` 里 `speakStaffGrow()` 读 `state.staff.lastEvent`（只在这一行变化时说，
  没长进的日子是空串，所以不会天天响）。

服务端 `server/app.py` 的 `LINE_SCENES` 补了三个场景，措辞纪律一致：
**不报数字、不提「技能 / 属性 / 升级」、不劝老板接着买什么**。

### ④ 口径统一：说一句就够

三个新场景都写「只说这一件」。这条纪律来自开罗 `balloon.txt` ——
一百零二条短口气，一句一处境，从不把两件事塞进一句。

## 五、新缺口

- **P326 配额是一刀切**：`guest_talk` 封四十个键，但「四十」是拍的；
  长局里常客重复出现时，四十可能不够；短局里根本用不到。
- **P327 三个新落点没有「同一件事只说一次」的判据**：
  `speakItem` 每次买都问一次，买九件杂货就问九次，键不同所以缓存不会合并。
- **P328 `staff_grow_voice` 的键是 uid**：uid 是运行期生成的字符串，
  换局就变 → 同一份存档重开也会再问一次（预算多花一点，玩家看不出）。
- **P329 预算与配额都写在代码里**：服务端其实能算一局用了多少键，
  但前端不报，所以「这一局预算快用完了」只有测试知道。
- **P330 本地句仍是四句**：三个新落点各四句，同一件事重复出现三次就会开始重复。
