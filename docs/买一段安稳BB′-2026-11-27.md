# 买一段安稳 BB′（2026-11-27）

> 这一批只做一件事：门路原来只有「多做几碗」「多来几个人」两类，都是**往好处加**；
> 这一批补上第三类 —— **「这半个月，那条烦人的不来」**。
> `docs/GAP四轮-2026-11-26.md` 第五节的 BB′。

---

## 一、这一批要解决什么

`game/src/data/invest.ts` 原来只有两类：

| 类别 | 含义 | 现有条目 |
| --- | --- | --- |
| `make` | 买产能 / 买速度 | 拿货、师傅指点、中央厨房 |
| `voice` | 买人气 | 报社、夜市、旅游团、展销、直播 |

开罗 `economy` 那张表（26 行）分两半：一半是「坏事」，一半是「把坏事挡掉」。本作只抄了前半截 ——
行情有十六条（检查、猪肉涨、气价涨、停水、修路…），玩家**只能被动挨**，没有任何一手棋可以下。
GAP 四轮把它记成 B 条：「没有对冲行情的手段」。

这一批补的第三类叫 `hedge`，语义只有一句：

> 买下的这十五天里，**那一条行情抽不到**。

不是「让那条的坏处小一点」（那是乘数），是「那条根本不出现」。

### 为什么不照抄开罗的倍率

文件头纪律一（批 J′ 立的，P154 还没解）：只买量不买乘数。理由写在实测里 ——
料钱已经叠了五层（品质档 ×1.0/1.8/2.6 × 行情 ±14% × 物产 −2% × 技法 −6~12% × 店底子），
再往上叠一层，上限没人验过。

所以 GAP 四轮原稿写的「菜贩子包月 → 半个月料钱 −6%」落成代码时改掉了：
−6% 就是第六层乘数。改成「猪肉涨价那条这半个月抽不到」—— 效果量小，但每一步算得清。

## 二、两条门路

### `inspect_report` · 跟监管所报个备（¥300 / 15 天）

- `hedgeOf: "inspection"`（创城检查）
- what：手续摊在柜台上，这半个月不会有人上门抽查
- line（买了的那句）：「手续都交上去了，这半个月门口清静。」
- why：检查是随机抽查、逐项看，手续齐的店照章办事，就不用每次提心吊胆
- 两条南宁出处：
  1. 南宁市政府《食品生产经营日常监督检查管理办法》随机抽查事项清单
     `https://www.nanning.gov.cn/zwgk/fdzdgknr/zdxxgk/ssjygk/t2564311.html`
     →「原料控制（含食品添加剂）情况的检查 / 餐饮服务经营者 / 一般检查事项 / 现场检查、书面检查」
  2. 广西食品安全网 · 西乡塘区春节前专项检查 `https://gxfsn.org.cn/page52?article_id=13457`
     →「执法人员……随机检查了食品加工流程、场所环境卫生、人员健康管理、餐具清洗消毒、原材料采购、食品留样等情况」

检查那条本来就只压 −8% 进店（`game/src/data/market.ts` 的 `inspection` 是
`{attractPct:-0.08, costPct:-0.05, patiencePct:0.04}`），所以买它买的是「这半个月门口不用提心吊胆」，
当保险，不是发财路。这句写进了代码注释。

### `meat_price_deal` · 跟菜贩子包个月（¥220 / 15 天）

- `hedgeOf: "porkUp"`（猪肉涨价）
- what：价钱讲定在这半个月，猪肉涨价那条摊不到你头上
- line：「价钱跟菜贩子讲定了，这半个月涨跌都不算你的。」
- why：「以销定产」，价钱提前定死
- 两条南宁出处：
  1. 广西日报《一碗粉的产业链》`http://epaper.gxrb.com.cn/gxrb2/html/2021-12/24/content_1814966.htm`

  2. 广西政府采购网《广西宁昌鲜蔬达供应链》
     `https://zfcg.gxzf.gov.cn/site/supplierDetail?supplierId=jXYUEfaibxEX0oeqgrpIBw==`
     →「当日订、次日达……为客户降低采购成本」

## 三、改法：先抽、抽中了才避让

`game/src/sim/market.ts` 的 `pickMarketAt` 加第四个参数 `hedged`：

```ts
const picked = pool[Math.floor(r * pool.length) % pool.length] ?? null;
if (!picked || !hedged.has(picked.id)) return picked;
// 抽中了被买断的那条：从剩下的里再抽一次（换一个盐，免得与原来同一条）
const rest = pool.filter((m) => !hedged.has(m.id));
if (rest.length === 0) return null;
const r2 = hashString(`${seed}:market:${month}:${day}:hedge`) / 4294967296;
return rest[Math.floor(r2 * rest.length) % rest.length] ?? null;
```

**为什么不直接把被买断的那条从池子里剔掉**（这是这一批唯一一个真正的设计决定）：

剔池子会让**每一天**的下标整体错位 —— 哪怕那天的行情本来与对冲无关。
存档里会出现「昨天预告的是赶圩，今天变成了台风」。所以走「先抽、抽中了才避让」：

- 没买对冲的日子与原来自洽（**替身不买门路 ⇒ 四种子逐位不变**，这是本批的判据之一）；
- 买了对冲的日子只会少那一条，别的一天都不动。

`todayMarket` 同样处理，但用 `roll(state, "hedge")` 这个新盐重抽 —— 它是按 `playerId + 月 + 日` 哈希的，
与 `pickMarketAt` 的 `seed` 哈希是两条不同的流。

明天预告用 `marketOnDay`，它按「**那一天**还剩几天对冲」算，不是按今天：

```ts
const ahead = Math.max(0, (month - state.month) * 30 + (day - state.day));
return pickMarketAt(month, day, state.playerId, hedgedMarketIds(state, ahead));
```

否则一条今天到期的报备会把明天的检查也预告掉。

### 单一出口 `hedgedMarketIds`

```ts
export function hedgedMarketIds(state: GameState, extraDays = 0): Set<MarketId> {
  const base = dayIndexOf(state) + Math.max(0, Math.floor(extraDays));
  const out = new Set<MarketId>();
  for (const def of INVESTS) {
    if (!def.hedgeOf) continue;
    if (investUntil(state, def.id) > base) out.add(def.hedgeOf);
  }
  return out;
}
```

放在 `sim/invest.ts` 而不新建模块，是因为它要读 `state.investments`，而 `sim/market.ts` 读它、
`sim/invest.ts` 不读 `sim/market.ts` —— 这样没有环。

## 四、界面

- 门路段：`investWords(def)` 加第四支 → 面板每行多一句「「创城检查」抽不到」；
  打烊单的 `investGainOf(def)` 加第四支 → 「「创城检查」不上门」。
- hint2 原来写「钱能买到的是「今天多做出几碗」和「今天多进来几个人」」，与第三类矛盾，改成：

  > 钱能买到的是「今天多做出几碗」「今天多进来几个人」，还有「这半个月烦人的那条不来」。
  > 买不到乘数。同类只能走一条。

- 每行加了 `data-invest-id`：原先探针（和任何脚本）只能靠「行里有没有买按钮」来认这一行是谁，
  买下之后按钮换成「在走 · 还剩 N 天」，整行就认不出来了。
  这不是为探针加的 —— 一行 DOM 认不出自己是谁，本身就是缺陷。

### 探针 `tools/gate/bb_probe.py`（22 条）

`invest_found / hedge_rows_present / report_names_inspection / report_says_not_drawn / meat_names_pork /
meat_says_not_drawn / hedge_days_fifteen / hedge_no_multiplier / hint_mentions_hedge / hint_not_two_only /

三个坑（都写进探针注释了）：

1. **认行不能靠按钮**：买下后按钮变成「在走 · 还剩 N 天」，靠它取 `id` 会得到空串 →
   两条判据假红。现在读 `data-invest-id`。
2. **「找一天本来是检查」必须排在买之前**，而且要扫满 360 天：`MARKET_CHANCE = 0.34` × 十六条里一条 ≈ 2%/天。
3. **撤销后重买不能点按钮**：撤销那次 `refresh()` 不保证重绘（面板没打开时 `render` 直接 return），
   DOM 里那行还停在「在走」，点空 → 对冲没挂上，后两条又假红。重买改成直接摆状态，
   「按钮能买」这条路由第三段负责。

## 六、没动什么

- **一个经济数值都没动**：两条门路的价钱（¥300 / ¥220）、天数（15）、`hedgeOf` 对冲的那条，都是新加的；
  原有八条门路、十六条行情的任何一个系数、任何一个百分数都没改。
- **没动抽签分布**：只有抽中被对冲那条的日子才会重抽，别的日子逐位自洽。
- **没动存档版本**：`state.investments` 本来就有，`SAVE_VERSION` 仍是 37。
- 替身策略一行没改（它本来就不买门路）。

## 七、新缺口

- **P499** `hedgeOf` 一条只能挡一条行情；「停水」与「气价」这种一条行情里含两个坏处（`waterCut` 同时压进店与料钱）的，挡掉等于全挡 —— 玩家看不出「报个备」到底省了多少钱。
- **P500** 买对冲那十五天，`marketTotals` 少了一条却没人告诉玩家「这些天一共躲掉几次」；打烊单只报到点那一句。
- **P501** `pickMarketAt` 重抽的盐 `:hedge` 与 `todayMarket` 的 `roll(state,"hedge")` 是两条不同的流 —— 同一天「明天预告」与「今天实抽」在对冲下可能给出不同的第二条，没有测试钉住。
- **P502** 两条对冲都写死「15 天」，而 GAP 四轮原稿是「半个月」；按月长度算应该是 15 还是 14/16 天，没定。
- **P503** `inspection` 撞上「本来那条已经抽出来」时会被换成别的，玩家看到的「今天没有行情」概率因此上升 —— 这个副作用没在界面上解释。
