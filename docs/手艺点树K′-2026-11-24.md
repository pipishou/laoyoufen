# 批 K′：手艺点数树（2026-11-24）

> 解 P0-3「没有点数树」：`rank.txt` 17 项在开罗是打烊给点、自己往上点的一条树；
> 本作此前只有段位费，钱与段位都不换「手上能多做什么」。
> 三维度纪律照旧：无出处不做 / 不叠第六层乘数 / 四色不新增。

## 一、点从哪来、花在哪

- **来**：段位晋升发一次，`PERK_AWARD_BY_LEVEL = [2,4,6,8,8,8,8,8,7,5]`，共 **64 点**；
  `perkEarned(state)` 按当前 `gradeLevel` 累加（不存冗余数），所以读老档不会算错。
- **花**：`PERKS` **16 项**，四条线各四项 —— **镬气**（味道）/ **刀工**（浇头位）/ **记性**（出碗）/ **人情**（人情日上限）。
  合计花费正好 64，点满不多不少（P297 的「余 5–9 点」在实装时收掉了）。
- **封顶**（`PERK_CAP`）：味道末段 ≤ 6、浇头位 ≤ 2、出碗 ≤ 0.3 分、人情日上限 ≤ 8。
  与 `SKILL_CAP`、`XP_TASTE_CAP` 同一套纪律：能感觉出来，不能越叠越强。

## 二、十六项

| 线 | 四项 | 落点 |
|---|---|---|
| 镬气 | 稳火 / 收汁 / 猛镬 / 老汤底 | 味道末段 `total + N`，合计 +6 |
| 刀工 | 一刀断 / 薄切 / 顺纹 / 花刀 | 浇头位 `maxToppingAdds + N`，合计 +2 |
| 记性 | 写单 / 记脸 / 报单 / 一锅到底 | 出碗三段 `−N 分`，合计 −0.3 |
| 人情 | 送客 / 记熟客 / 留座 / 街坊账 | 人情日上限 `dailyCapByBowls + N`，合计 +8 |

> 二次确认 **R-11 撤掉了「汤料位 +1」**：`Recipe.soup` 是定长元组，全仓 `soupSlot` 命中 0，
> 没有这个上限就写不出这个奖励 —— 改成人情日上限，是现成杠杆（`game/src/data/favor.ts`）。

## 四、界面（第七个页签「手艺」）

- `PanelTab` 加 `"perk"`、`TABS` 加 `{ id: "perk", label: "手艺" }`、面板 shell 补 `<section data-pane="perk">`（**这一步漏了会白屏但不报错** —— 探针首跑 `four_blocks` 全红就是这个）。
- 页内 `.ptree` 4 行 × 4 格，每格 **28px**（`PX = 4` 的七倍），三态：未点虚线沙色、可点亮实线红边、已点亮金底 + `steps(2)` 的 0.18s 弹一下（`prefers-reduced-motion` 下不动）。

## 六、替身四种子（36 月）

与批 J′ **逐位一致**：¥113,348 / ¥122,978 / ¥136,773 / ¥105,548 → 均值 **¥119,662 · 215.8 碗 · 36% · 期末 ¥629,963**。
原因很简单：替身不点树。点数树是「给玩家自己决定」的那一层，朴素策略不吃它 —— 这正是想要的形状。

## 七、新缺口

- **P306**：16 项全是「+N」的同类效果，四条线的区别只在中段数字；玩家第一次打开会不知道该点哪条。
- **P307**：点数只看段位，看不出「这一项现在点下去能省多少碗」，缺一句可算的因果（与 `today.ts` 的回本句同源，可复用）。
- **P308**：没有重置或洗点（开罗也没有），但界面写了「点了就退不回来」，需要一句更具体的确认。
- **P309**：`.mtabs` 横滚在触屏上与面板纵向滚动抢手势（P299 的实测版）。
- **P310**：`PERK_AWARD_BY_LEVEL` 合计与 16 项 cost 合计都是 64，改任何一项都要两边同时改，没有测试锁「两表相等」以外的关系。
