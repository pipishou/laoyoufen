
## 五、-2 窗做了什么（BH′，解 P545/P547/P548）

### 客流按座位分档

```ts
export function spawnScaleByDay(state: GameState): number {
  const seatFactor = spawnSeatFactor(state.venue.seats);
  if (state.month !== 0) return seatFactor;
  if (state.day <= 1) return 0.55 * seatFactor;
  if (state.day <= 7) return 0.85 * seatFactor;
  return seatFactor;
}

const SEAT_BASE = 4;

export function spawnSeatFactor(seats: number): number {
  if (seats >= SEAT_BASE) return 1;
  return Math.sqrt(Math.max(0, seats) / SEAT_BASE);
}
```

**为什么是 `sqrt(seats / 4)` 而不是线性**：线性（2 座 ×0.5）会把首日到店压到 29 人，2 座卖 29 碗 —— 玩家看不到「忙」，也就没有「接不住要加凳」的动机。sqrt 给 0.707，到店 41 人，仍会排一点队。**这条系数不碰产能**（座位闸照旧 32.7 碗），修的是「来的人比能接的多」这个配平错位。

**`seats >= 4` 恒等于 1.0** —— 替身全程 4 座，所以四种子逐位不变。这不是巧合，是硬约束，有单测钉住（`setup.test.ts:217`，`for (const seats of [4,5,6,8,12]) expect(spawnSeatFactor(seats)).toBe(1)`）。

### 建店卡写日产能

```ts
// data/sites.ts —— 与模型同一个算式，不另抄一份
export function dailyBowlCeiling(site: SiteDef): number {
  return Math.round(seatBowlCeiling(site.seats));   // seats × 120 × 0.9 / 6.6
}
```

卡片第四枚统计：`一天最多约 33 碗`（街边摊）/ `65 碗`（巷内）/ `98 碗`（临街）；2 座那档底部 badge 从空变成 `起步档`。

> `SEAT_IDLE` 因此从模块常量改成 `export`，`capacityOf` / `capacityGain` 的内联算式都改成调 `seatBowlCeiling()` —— **浮点运算顺序没变**，所以 4 座以上的 `capacity.total` 逐位不变。
