## 二、F4：副行为什么会自己变

```ts
// game/src/main.ts —— prefetchHookLine()
.then((line) => {
  if (line) refresh();          // ← 改前：整块重绘
});
```

`refresh()` 会把打烊单、左栏、顶栏、面板一起重画。玩家看到的现象是「我刚读完的那句话，忽然换了一句」——
报告里的「会自己改字」就是这个。

改成只碰那一格：

```ts
.then((line) => {
  if (!line) return;
  const node = document.querySelector<HTMLElement>("[data-hook-line]");
  if (node) node.textContent = line;
});
```

配合 `lastHookKey`（`key:month:day` 节流），同一份打烊单只替换一次，不会来回跳。

## 三、F5：副行按用途分池（6 → 26 句）

改前 `LOCAL.hook_voice` 是一个六句池，`capacity / grade / gear / street / arena / none` 六个档位共用一个。
于是出现报告里那句「主句说加灶，副行在说街上的事」—— 副行是在给主句解释理由，说的不是同一件事就是噪音。

现在 `sim/hook.ts` 的 `hookVoiceContext()` 在 context 里多带一个 `类型`：

```ts
return hint ? { 类型: plan.kind, 事: hint } : {};
```

`ai/lines.ts` 按它选池：

```ts
const HOOK_VOICE: Record<string, readonly string[]> = { capacity: [...6], grade: [...4], gear: [...5], street: [...6], arena: [...3], none: [...2] };
function hookPool(ask: LineAsk): readonly string[] {
  const kind = ask.context["类型"];
  return (kind ? HOOK_VOICE[kind] : undefined) ?? HOOK_VOICE.capacity!;
}
```

`类型` 只给本地选池用，**发请求前剔掉**（`stripKind()`），不进模型上下文。

| 档 | 句数 | 示例 |
|---|---|---|
| capacity 加灶扩座 | 6 | 「桌椅不够，生意越好越亏心。」 |
| grade 评段位 | 4 | 「招牌是给别人看的，手艺是给自己留的。」 |
| gear 家当 | 5 | 「别人看不出你换了什么，你自己知道顺手了。」 |
| street 街面 | 6 | 「修的是街，收的是人心。」 |
| arena 落场 | 3 | 「赢一场，街坊记你一整年。」 |
| none 什么都不缺 | 2 | 「日子还长，慢慢做。」 |

**数字红线没松**：26 句全部过 `isCleanLine()`。写的时候踩了三次 ——
「一天下来少弯十几次腰」（`十几` + 量词）、「一件顶一件用」、「做一件是一件」都被中文数量词规则拦下，
全部改成了不带数量词的说法。这条规则宁可误杀。

## 四、F6：两套成就合并

改前同一局里有两套「成就」：

| | `sim/achievements.ts`（老） | `sim/trophies.ts`（B 批） |
|---|---|---|
| 条数 | 11 条（带 4 档阈值） | 30 枚（单阈值） |
| 用在哪 | HUD 左栏两行 | 图鉴页第 6 段 |
| 字段 | `customers/regulars/queue/...` | 与本作真实状态一一对应 |

玩家在左栏看到的名字和图鉴里对不上，而且老那套的 `hint` 里写着「开罗 trophy：顾客 100/1000/3000/6000」，
被 `hud.ts` 直接贴进 `title` 属性 —— hover 就露出来（`copy_gate` 只扫 ui 层渲染串，看不见）。

处理：
1. 删除 `game/src/sim/achievements.ts` 与 `achievements.test.ts`（−12 用例）；
2. `sim/trophies.ts` 新增 `nextTrophies(state, n = 2)` —— 未获得里按 `pct` 降序取两枚，
   全收齐（30/30）时退回最近拿到的两枚，别让左栏空掉；
3. `hud.ts` 左栏改读它，`title` 用 `def.note`，右侧写 `cur / target`。

## 五、`copy_gate.py` 扩到 data / sim 层

改前规则只有一条：「扫 `game/src/ui/*.ts`，剥注释与 `devNote`」。
这条规则挡不住 F6 那类问题：**字是在 data/sim 层写的，ui 只是把字段贴上去**。

改后：

| 规则 | 说明 |
|---|---|
| 扫 `ui/*.ts` | 渲染串 + `title="…"`（原有） |
| **扫 `data/*.ts`、`sim/*.ts`** | 玩家看到的 `name / line / note / hint / pitch / request / effect` 都在这里 |
| 跳过 `*.test.ts` / `*.probe.ts` | 不进包，玩家看不到 |
| 只认**字符串字面量** | `RAMEN_CALC`、`KAIRO_REF` 这类标识符不算文案 |
| `kairo:` 整行豁免 | 取证引用（原文照抄的那句描述），从不渲染 |
| `import` / `export` 行豁免 | 模块路径不是文案 |

第一次跑（没加豁免）报 37 处，全是误杀：测试文件、标识符、import 路径。
收敛后报 **2 处真命中**：`data/menu.ts` 的 `MENU_CAP_HINT`
（「……开罗的售卖机上也是一排券，客人自己挑。」——真的会被渲染到面板上）和一处 import 路径。
改完 `MENU_CAP_HINT` 为「……墙上贴一排价目，客人自己挑。」，门变绿：

```
[copy-gate] ok —— 玩家可见文案 0 处别的作品名
[copy-gate] 注释/取证引用里的命中（允许）：41 处
```
