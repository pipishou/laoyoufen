# 批 I′：打烊单要压住 toast、红标与钩子同源、为什么改口语

> 依据是 11-24 的试玩报告五条观察。这一批没有新玩法，只修「该读的那一句被挡住」「两处指的不是同一件」「读起来像系统说明」。
> 锁定：`saveVersion 36`、AI 落点 22（本批没有新落点）。

## 一、五条观察 → 五处改动

### 1. 打烊单被 toast 压住约 8 秒（第 1 条）

`#toasts` 的 `z-index` 是 80，`.modal` 是 50 —— 打烊单弹出来时，toast 正好盖在「明天继续」旁边那几行上。
改法不是把 toast 关掉（打烊那一刻它也承载结算提示），而是**分两层**：

```css
.modal.dayreport{z-index:90}                 /* 打烊单是这一刻唯一该读的东西 */
.dayreport:not([hidden]) ~ #toasts{          /* 开着时把 toast 挪到上方 */
  bottom:auto; top:16px;
}
```

写这段时踩了一个坑：第一版用了 `body:has(> .modal.dayreport …) #toasts`，而打烊单与 `#toasts` 都挂在 **hud root** 上、不是 `body` 的子节点 → 选择器永不匹配。改成同一父节点下的兄弟选择器才生效。

### 2. 红标与打烊钩子各说一件（第 2 / 5 条）

试玩里：三局第 2 天钩子都点名「先把「塑料矮凳」加上（¥150）」，阿兰老韦买了；买完 **红标移到竹躺椅，钩子却改去评「摆摊仔」**。
根因不在文案，在**两个口径**：

```ts
// 旧
const hotPlan = lostRateOf(s) >= CAPACITY_LOST_RATE ? nextHook(s) : null;  // 面板自己的闸
// 钩子那边用的是打烊样本的阈值
```

两个阈值一个看「今天实时」、一个看「昨天打烊」，一错开就分叉。现在两边只问 `nextHook(state)`：

```ts
const hotPlan = nextHook(s);
```

红标只指钩子点的那一件；钩子说去评定，就没有红标。

### 3. 「为什么」读起来像系统话（第 4 条）

旧句：`今天 24 位站在门口没进来：2 张桌，一碗占 6 分钟，一天最多接得住 30 碗。`
新句：`今天 24 位站在门口没进来。就 2 张桌，一碗要吃上 6 分钟——今天出了 34 碗，已经顶到边了。`

两处不一样：
- 破折号换成口语的**停顿**（「就 2 张桌」而不是「2 张桌，」）。
- **模型给的「一天最多」低于当天真卖出的碗数**时，不再说「撑死也就 30 碗」（而玩家刚卖了 34 碗）—— 改说「今天出了 34 碗，已经顶到边了」。让数字和事实对得上，比让模型算准更要紧。

### 4. 只加灶不掉走失、加座才掉（第 3 条）

这条是**观察记录**，不是本批的改动：小陆只买灶，D4 走失 56.8%；阿兰老韦跟着凳子钩子加座，D4 掉到 33.7% / 25.6%。它验证 D′ 的方向对，也说明「座位是第一瓶颈」。三局样本仍太小，记在缺口里。

### 5. 替身不买矮凳（P285）

D′ 之后「出碗变快」在自动化里换不来碗数，因为替身只按设备单子买。本批让它学会先看加座：

```ts
if (lostRate > 0.4) {
  const seatGear = GEARS.filter((g) => (g.seats ?? 0) > 0 && !hasGear(s, g.id))
    .sort((x, y) => x.costYuan - y.costYuan)[0];
  if (seatGear && s.cash >= seatGear.costYuan + 4_000 && buyGear(s, seatGear.id).ok) gears += 1;
}
```

## 五、新缺口

- **P286** 打烊单与 toast 的层叠用 `z-index` 硬抬；若以后有第二个需要压在 toast 之上的弹窗，这个数字要统一成一个层级表。
- **P287** 「为什么」的形态句只覆盖队满 / 价牌 / 等不及三档；`servedNow >= perDay` 这条分支没有单独测试（探针覆盖了，单元测试没有）。
- **P288** 替身买座只买「最便宜的加座家当」，没算「再加一张凳不如换大桌」这类比较。
- **P289** 试玩样本仍只有三局、四天，走失曲线在第 2 天最高这件事没有跨包对照。
