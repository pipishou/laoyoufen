# P42 粉型本土化 + 套餐 + 冬夏限定（2026-11-15）

## 0. 三句话

1. 开罗的「面」不是一个滑块，是**材料选择 + 煮制档位 + 汤面协同矩阵**三层；我们照这个把 `粉宽 / 粉型` 两个数字滑块换成**六种能点的粉**：切粉、圆粉、伊面、湿面（碱水）、干捞（夏）、砂锅（冬）。
2. 粉型不是皮肤：它带**成本系数 / 出碗时间系数 / 与当前汤底的契合度 / 当季加成**，而且契合度可以超过 100 —— 切粉永远是 100（谁都能吃），**这锅汤正好是它的菜时才 104–125**，否则切粉永远最优、玩家没有理由换。
3. 同一轮把 P42 的另外两件一起做完：**粉 + 饮料套餐**（饮料 −¥1、满意 +1）与**冬夏限定组合**（干捞配豆浆、砂锅配热浆），并把 P39 预告的 `topping4` 接到「每碗可多加一件加料」上。

## 2. 六种粉（`game/src/data/noodles.ts`）

| 粉 | 成本 | 出碗 | 门槛（累计客人） | 季节 | 配什么汤才好吃（契合） | 南宁话 |
| --- | --- | --- | --- | --- | --- | --- |
| 切粉（宽扁）`flat` | ×1.00 | ×1.00 | 0 | 全年 | **恒 100** —— 基准，谁都能吃 | 宽扁的切粉，汤挂得住，这是老友粉的正统 |
| 圆粉（细圆）`round` | ×0.95 | ×0.90 | 60 | 全年 | `90 + (咸−45)×0.8 + (鲜−50)×0.6` | 细圆的粉，滑是滑，但吸汤少 —— 汤要够味才压得住 |
| 伊面 `yifu` | ×1.15 | ×1.15 | 300 | 全年 | `50 + 汤厚×0.9` | 先炸后泡，一口汤全吸进去；汤薄了就寡得慌 |
| 湿面（碱水）`wetchow` | ×1.05 | ×1.20 | 700 | 全年 | `92 − max(0, 酸−60)×1.2 + max(0, 辣−40)×0.4` | 碱水味爽口，但压酸 —— 酸笋别下太狠 |
| 干捞老友粉 `dry` | ×0.90 | ×0.85 | 1200 | **夏 6–9** | `80 + (豆豉−50)×0.7 + (辣−45)×0.5 + (咸−45)×0.4` | 南宁的夏天，粉过冷水捞起来，全靠豆豉辣椒提味 |
| 砂锅老友粉 `claypot` | ×1.25 | ×1.50 | 1800 | **冬 11–2** | `55 + 汤厚×0.6 + 蒜香×0.4` | 冬天滚着上桌，汤浓蒜香，吃到最后一口还是烫的 |

- 契合度钳在 **0–125**：`100` = 切粉基准，`>100` = 这锅汤正好是它的菜。
- 当季粉 `×1.15` 契合、满意 **+3**；反季 `×0.85`、满意 **−3**。
- `state.month` 是 **0 基**（`createInitialState` 里 `month: 0`），`seasonOf()` 也是 0 基 —— 6 月是 `month: 5`。

## 3. 三个接线点

```ts
// game/src/sim/score.ts —— 只动「粉」这半分，不碰 total 的权重公式
const fit = noodleFit(kind, recipe.soup);
const noodle = groupScore(subs, "noodle") * (0.6 + 0.4 * (fit / 100));
const total = soup * 0.55 + noodle * 0.45;   // 切粉 fit=100 → 与改前完全一致
```

```ts
// game/src/sim/customer.ts —— 成本、出碗、满意度
const cost = score.cost * costMultiplier(state) * equipCostMultiplier(state) * noodleCostFactor(state) + sidePick.cost;
flow.serveCooldown = FLOW.serveMinutes * serveMultiplier(state) * equipServeMultiplier(state) * noodleServeFactor(state);
// satisfactionOf(..., regularBonus + frenzyAura(state) + noodleSeasonBonus(state))
```

```ts
// game/src/sim/state.ts —— 时间推进时把粉型带进评分
const score = scoreRecipe(state.recipe, state.price, noodleKindOf(state));
```

`scoreRecipe` 的 memo key 加了 `kind` 前缀（不加就会被上一碗的粉型污染），第三参默认 `"flat"` —— 所以**所有既有回归锁在默认粉型下分数一个都没变**，229 个用例零改动通过。

## 4. 套餐与冬夏限定组合（`game/src/data/sides.ts`）

- **套餐** `state.sides.mealDeal`：粉 + 饮料一起卖，饮料 **−¥1**、满意 **+1**。开罗 `avgTicket` 的思路：客单价不是把粉卖贵，是多卖一件。
- **冬夏限定组合**（`SIDE_COMBOS` 新增 `noodle?` / `season?` 两个条件字段）：
  - `summer_dry`「干捞配豆浆」：`dry` + 豆浆，夏 → **+3**
  - `winter_claypot`「砂锅配热浆」：`claypot` + 豆浆，冬 → **+3**
- `comboOf(items, noodle, season)` 现在要传粉型与季节；条件不满足的组合直接跳过，所以切粉全年都凑不出季节组合。

## 5. `topping4` 接上（P39 预告项转正）

`maxToppingAdds(state) = MAX_TOPPING_ADDS(2) + (已解锁 topping4 ? 1 : 0)`，
`pickSides` 的 `toppingCap = maxToppingAdds(state) + (rich ? 1 : 0)`。
第 4 段（浇头台加一格）现在真的让客人多凑一件 —— 也是「老友味」组合（酸笋+豆豉+辣）更容易凑出来的前提。
