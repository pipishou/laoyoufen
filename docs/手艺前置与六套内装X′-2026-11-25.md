# 手艺前置与六套内装（批 X′，2026-11-25）

> 这一批补两件事：第一，手艺点树从「十六个并排的按钮」变成**四根链**；
> 第二，内装成套从两条补到**六条**。都不动数值上限，动的是「先后」与「配齐」这两层。

## 一、开罗是树，不是篮子

`rank.txt` 是 17 项点数树 —— 先点得出「最大含水量」，才谈得上下一档。我们这批之前
十六项是平的：玩家有 64 点，任意点任意一条，第一次打开根本不知道从哪起手（P306 只补了
「先点这个」的推荐，没有真的先后）。

这一批把每族四项按便宜到贵串成一根链：

| 族 | 链（→ 表示前置） |
| --- | --- |
| 镬气 | 爆得透（3）→ 锅气不散（4）→ 两锅轮着来（4）→ 火不熄（5） |
| 刀工 | 切得薄（3）→ 丝切得匀（3）→ 粉抖得开（4）→ 码得齐（5） |
| 记性 | 记得住脸（3）→ 记得住火候（3）→ 记得住口味（4）→ 记得住搭法（5） |
| 人情 | 门口有张熟脸（4）→ 肯听劝（4）→ 肯赊一碗（5）→ 帮手肯搭手（5） |

规矩三条：

1. **没点前置就点不动** —— 按钮写成虚边、透明度 0.62，`title` 与 toast 都说「先点「X」」，不扣点。
2. **「先点这个」跳过被挡的** —— 推荐只在「未被挡住」的项里挑最便宜的，不会推一条点不了的。
3. **总数不变** —— 十六项、64 点、四条出口封顶全部照旧；变的只是路径。

## 二、成套从两条到六条

开罗 `storeparts` 是六套内装（Chic / Cafe / Retro / Natural …），每套五件，配齐才有整套效果。
我们批 J′ 只做了两条（桌 6 / 门面 4），这批补到六条，**仍然只走「耐心」与「进店」两个出口**：

| id | 名字 | 条件 | 出口 |
| --- | --- | --- | --- |
| `room_done` | 店里坐得下了 | 桌 6 | 耐心 +12% |
| `wok_done` | 灶排开了 | 灶 3 | 耐心 +3% |
| `prep_done` | 案子摆开了 | 备料 4 | 进店 +3% |
| `full_house` | 灶桌对上号 | 灶 3 + 桌 8 | 耐心 +5% |
| `lane_show` | 门口一条街 | 门面 4 + 桌 6 | 进店 +4% |
| `front_done` | 门面齐了 | 门面 4 | 进店 +4% |

六条加起来耐心 +20%、进店 +11%，全常驻、不改料钱、不改出碗时间。**没有一条给座位**
（P301 的教训：座位是本作唯一真瓶颈，白送一个座位等于白送一天十碗）。

## 五、新缺口

- **P379** 链条顺序是「便宜到贵」，不是「有什么用」—— 玩家可能想先要味道，却被挡在 4 点那一档外面。
- **P380** 六条成套的百分比是拍的（+3 / +4 / +5），没有和「一件家当多贵」换算过。
- **P381** 成套只在店铺页显示，打烊单不报「今天凑齐了一套」（`recordDay` 已有 `slotSet` 字段，但只在有 `announceSlotSets` 结果时写，界面没展示）。
- **P382** `pc blk` 的虚线在 375 宽只剩 1px 可见（同 P352）。
- **P383** 前置链写死在数据里，改一项的 `prev` 不会自动检查成环（目前靠测试首条兜着）。
